## 【前提（今の実装）】
* 書き出し（出力（エンジン用））は、`SpriteSerializer.serialize(model.getItems())`がスプライトデータ`{ format, formatVersion: 4, bounds, elements, source }`を作り、`CodeExporter.toModuleText`がJSのテキストにする。`elements`・`bounds`は見えている図形だけ、`source`は作業データ（`DocumentSerializer.serialize`の戻り値そのもの）で全部。
* 描画要素は各図形の`toDrawElement()`が作り（呼び出し元は`SpriteSerializer`だけ）、`kind`の次に`id`を持つ。`id`は、書き出したJSの`draw`・外枠の計算・確認用ページ・エンジン・ゲームのどれも読まない。
* 開く・インポートは`FileContentReader.deserializeFromText`を通る。JSは`source`だけを`DocumentSerializer.deserialize`へ渡し、`source`が無ければ読み込み不可（`elements`・`bounds`は読まない）。結果（`{ ok, items, shapes, skipped, error }`）は`CanvasFileOperations`が判定の表で「読み込み不可・空・一部・全部」に分ける。
* ツールのアイコン（`asset/sprite/`の2本）は版2の書き出しで、`source`を持つ。`wiring/ToolIconWiring`は`bounds`と`draw`だけを使う。

## 【用語】
* **復元用のデータ**：スプライトデータの`source`。
* **今までのJS**：`source`を持つ、これまでに書き出したJS（版1〜4）。
* **新しいJS**：本作業の後に書き出した、`source`を持たないJS。
* **組み立て**：`source`の無いJSの`elements`から図形を作ること。

## 【実装要件】
書き出したJSを、ゲームに必要なデータだけにする。JSを開いたときは、描画データから図形を組み立てる。

*   **要件1: 書き出しから外すもの**
    *  書き出したJSに`source`が入らない（キーごと無い）。フォルダ・名前・ロック・隠した図形の情報も入らない。スプライトデータは`{ format, formatVersion, bounds, elements }`の4つのキー（この順）になる。
    *  描画要素から`id`を外す（発注者の決定、2026-11-25）。各図形の`toDrawElement()`が`id`を作らない形にする。ほかのキー・値・並びは変えない。
    *  **書き出し形式の版は4のまま上げない**（発注者の決定、2026-11-25。`source`も`id`も読む側は使っておらず、描く処理が変わらないため）。版の値・`checkFormat`の受理の範囲（1〜4）も変えない。
    *  `bounds`の値、JSの`draw`の処理、既定のexportの形（スプライトデータの全キーと`draw`）、`const spriteData = `から始まる形は変えない。先頭の説明コメントは、実際のキーに合わせて直す。
    *  すべて隠れているときは、今までどおり図形0個の書き出しと同じ結果になる。
*   **要件2: 新しいJSを開く・インポートする**
    *  `source`のキーが無いJSは、`elements`から図形を組み立てて開ける・インポートできる。**組み立てた図形は、書き出したときと同じ見た目になる**（形・線・太さ・塗り・重なり順。座標の差は計算の丸めの範囲）。
    *  組み立ての対応は次のとおり。

       | 描画要素 | 図形 |
       | --- | --- |
       | `polyline`・`closed`が`true`でない・2点 | 直線（`line`） |
       | `polyline`・上のほか（開いたパスは3点以上、閉じたパスは3点以上） | 区間がすべて直線のパス（`path`）。矩形だったものも四角い閉じたパスになる |
       | `bezierPath` | パス（`path`）。`line`の区間は直線、`cubic`の区間は引っ張る点をそのまま持つ「曲がり方を持つ区間」（`'bezier'`）。角の点は無し |
       | `quadratic` | 今の曲線（`curve`） |
       | `ellipse`・`closed`が`true`・1周分 | 円（`circle`）。縦横の半径・回転も保つ（傾いた楕円を含む） |
       | `ellipse`・`closed`が`true`でない・半周分 | 弧（`arc`）。回した・裏返した弧（開始角がπでないもの）も同じ見た目になる |

    *  スタイルは、書き出したJSの`draw`と同じ読み方をする（2章「読む側の規則」）：`strokeColor`が文字列でなければ線なし、`strokeWidth`が正の有限の数値でなければ2px、`fillColor`が文字列でなければ塗りなし、`closed`は`true`だけが閉じる、`rotation`が有限の数値でなければ0。`draw`が塗らない要素（閉じていない・`quadratic`）の塗りは無しにする。
    *  名前は、種類の自動の名前（「直線 1」「パス 1」など。作業データの読み込みと同じ規則）。フォルダ無し、表示、ロックなし。`id`は今までの読み込み・追加の規則で付く（描画要素に`id`が残っているJSでも、壊れずに読める）。
    *  組み立てられない要素（未知の`kind`・項目の不足や不正・上の表に当てはまらない形）は、**その要素だけを読み飛ばし**、作業データの読めない図形と同じ扱いにする（`skipped`に1件、`console.warn`を1回、残りは読む。「一部の図形（n個）を読み込めませんでした」の通知・すべて読めないときの読み込み不可も今の判定の表のまま）。`elements`が配列でないときは読み込み不可。例外は外へ出さない。
    *  `elements`が空なら、今の「空」の扱い（開く＝空のキャンバス、インポート＝追加できる図形がない通知）。
    *  組み立てて開いたこと自体の通知は**出さない**（発注者の決定、2026-11-25）。開いたキャンバスの名前・入る場所・選択・取り消し・自動保存は、今のJSの読み込みと同じ。
    *  組み立てた図形は、選ぶ・動かす・変形する・頂点を動かす・直線／曲線を切り替える・結合する・色を変える・一覧で扱う・作業ファイルに保存する・書き出すことが、その種類の図形として今までどおりできる。**もう一度書き出したJSも、同じ見た目になる**。
*   **要件3: 今までのJS・作業データは今までどおり**
    *  `source`のキーがある今までのJS（版1〜4）は、`source`だけを使って、フォルダ・名前・隠した図形・表示・ロックまで今までどおり全部戻る（`elements`は使わない）。`source`が読めないときは今までどおり読み込み不可（`elements`からは組み立てない）。
    *  今までのJSを開いて書き出し直すと、新しいJSになる（`source`は入らない）。
    *  作業データファイル（`.ozve.json`）の出力・開く・インポート、自動保存、キャンバスの切り替え、コピー・複製、取り消しは、何も変わらない。作業データの版は4のまま。スプライトのJSON・本アプリの形から外れたJSは、今までどおり読み込み不可。
    *  確認用ページ（`sprite-check.html`）は、新しいJS・今までのJSの両方を今までどおり描く（新しいJSの「作業データの版」は、今の表示のまま「なし」）。
    *  ツールのアイコンのJS（`asset/sprite/`の2本）は書き換えない（版2・`source`入りのまま使える）。
*   **要件4: 自動テスト**
    *  `node --test`がすべて通る。既存のテストのうち、スプライトデータの`source`・描画要素の`id`・「`source`が無いJSは読み込み不可」を確かめているものは、本作業で意味が変わるので直してよい。**直すテストの一覧を、直す理由と直し方とともに計画書に書くこと。** 確かめている観点を捨てない：並び順を`id`で見ていたものは別の見分け方（色・座標など）に替える。隠した図形・名前・フォルダが作業データで戻ることを`source`で見ていたものは、作業データ（`DocumentSerializer`）で見る形か、今までのJSの形（`source`を足した固定のデータ）で見る形に替える。それ以外の既存のテストの値は変えない。
    *  次のテストを足す：書き出したデータ・JSのテキストに`source`・名前・フォルダ・ロック・隠した図形・`id`が無いこと。図形の種類ごと（直線・今の曲線・矩形・円・弧・パス（開いた／閉じた、直線だけ／曲線／曲がり方を持つ区間／混ざり／角の点）と、それぞれを拡大縮小・回転・反転したもの。弧は左右・上下の裏返しと回転の組み合わせ）の往復：書き出し→開く→描く命令の比較、もう一度書き出した`elements`・`bounds`が丸めの範囲で一致。線なし・塗りなし・太さの不正・`fillColor`や`rotation`のキーが無い版1〜3の形（`source`を取り除いたもの）。読み飛ばし（未知の`kind`・項目の不足・表に当てはまらない円弧・点の数の不足・要素がオブジェクトでない）と件数・警告の回数。`elements`が配列でない・空。`source`のあるJS（`elements`を空や別の形にしても`source`から戻ること、`source`が不正なら読み込み不可）。開く・インポートの手順（`CanvasFileOperations`の実物）での通知・1件の取り消し・作業データへの保存。引数を書き換えないこと。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : 既存の責務の分担を崩さないこと。外部フレームワークを導入しない Vanilla JS の原則を維持すること。
*   **組み立ての知識は1か所** : 描画要素から図形データ（`toJSON()`の形）への変換は、`io/`に新しく置く、状態を持たないファイル1つにまとめる。図形の生成と検証は`core/ShapeFactory.fromJSON`に任せ、図形データの規則を書き写さない。読み飛ばしの記録と警告・名前の補いは、作業データの読み込みと同じ仕組みを使う（同じ働きを2つ作らない。`DocumentSerializer`に入口を足すことは可。作業データの読み書きの結果は変えない）。
*   **入口は`FileContentReader`のまま** : `CanvasFileOperations`・`CanvasLibrary`・`ShapeInserter`は、JSDocの記述を直すだけでコードは変えない（変える必要があると判断した場合は、計画の中で理由を示すこと）。
*   **JSは実行しない** : 読み込みで`import`・`eval`・`Function`を使わない。`CodeExporter.extractSpriteDataText`の取り出し方を変えない。
*   **円・弧の組み立て** : 図形データの5つの点（中心・共役な半径の2点・開始角と終了角の点。`Ellipse`の`points`の約束）を、描画要素の中心・半径・回転・開始角から求める。回していない円・約束の位置の弧は、描いたときと同じ約束の位置の点になること。角度の比較は、三角関数の誤差を許すこと。
*   **変更してよい`shapes/`の範囲** : 5つの図形クラスの`toDrawElement()`と、そのJSDocだけ。描画・当たり判定・`toJSON`・`fromJSON`は変えない。
*   **変更しないファイル** : `core/`・`edit/`（JSDocを除く）・`palette/`・`wiring/`・`main.js`・`index.html`・`sprite-check.html`・`js/check/`（JSDocを除く）・`asset/`・`CanvasStorage.js`・`DocumentFileIO.js`。
