## 【実装要件】
Phase 04-02でスプライトを`<名前>.js`と`<名前>.json`の2ファイルで出力するようにしたが、OZ Engineは書き出したJSだけを使うと確認できた（エンジン側で確認済み。根拠`_doc/BRIDGE_FROM_ENGINE.md`）。スプライトのJSON（`<名前>.json`）は読み手がいないため、**スプライトはJSだけとし、JSONの出力と読み込みをやめる**。あわせて、エンジンとの約束を開発資料2章「スプライト（書き出し形式）」の項に書き残す。

### 用語（本REQ内）
* **スプライト**：「出力（エンジン用）」が書き出す`<名前>.js`（ESモジュール）。中身のスプライトデータ（`format: "oz-vector-editor-sprite"`・`formatVersion`・`bounds`・`elements`・`source`）と`draw(ctx)`を既定のexportに持つ。
* **スプライトのJSON**：Phase 04-02〜04-03で「出力（エンジン用）」がJSと一緒に書き出していた`<名前>.json`（スプライトデータを`JSON.stringify`したもの）。本REQで出力・読み込みともにやめる。
* **作業データファイル**：「出力（作業ファイル）」が書き出す`<名前>.ozve.json`（従来の`.json`も含む）。作業データ形式（`format: "oz-vector-editor"`）。本REQでは変えない。
* **確認用ページ**：`sprite-check.html`（Phase 04-03）。

### 決定事項（発注者決定、261109）
* スプライトのJSONは**出力しない**（DIRの決定）。
* 既存のスプライトのJSONは、エディタの「開く」「インポート」で**読めなくする**。理由：作業データファイルも`.json`であり、「`.json`＝作業データファイル、`.js`＝スプライト」と1対1にしてわかりやすくするため。これまでスプライトのJSONは必ず同じ中身のJSとセットで出力されていたので、JSを開けば失われるものはない。
* 確認用ページは**JSだけ**を表示する（JSONは表示しない）。
* 書き出し形式の版（`formatVersion`）は**上げない**（現在1のまま）。理由：エンジンが読む部分（JSの既定のexportの形と`draw(ctx)`の約束）は変わらないため（開発資料2章「2つの版」の条件に当たらない）。JSに埋め込むスプライトデータの中身とJSのテキストの形（`CodeExporter.toModuleText`の出力）も変えない。

### 要件1: 「出力（エンジン用）」をJSだけにする
* 「出力（エンジン用）」を押すと、`<名前>.js`だけがダウンロードされる。`<名前>.json`はダウンロードされない。JSの中身・ファイル名の規則・図形0個のときの挙動（通知なしでダウンロードする）・失敗時の通知`spriteExportFailed`・成功時に通知を出さないこと・図形／選択／履歴／ビュー／操作モードに触れないことは、これまでどおり。
* ダウンロードが1つになるため、「JSとJSONの片方だけがダウンロードされた場合」を前提にした手順・文言をなくす（失敗の通知`spriteExportFailed`の文言を、1ファイルの出力に合った文言へ直す）。
* 「出力（エンジン用）」ボタンの`title`の文言を、JS（`.js`）1つのファイルをダウンロードすることが分かるように直す。
* スプライトのJSONのためだけにある公開メソッド・定数（例：`DocumentFileIO`の`downloadSpriteJson`・`toSpriteJsonFileName`・`SPRITE_JSON_EXTENSION`）は削除する（呼び出し元・JSDoc・テストも合わせて整理する）。どれが「JSONのためだけ」かは計画時に実コードで確かめて列挙すること。`SpriteSerializer.stringify`は`CodeExporter`がJSへデータを埋め込むときにも使っているため、使われ続ける限り残す（削除の判断はタスク内で実際の呼び出し元を確かめてから行う）。

### 要件2: エディタの「開く」「インポート」でスプライトのJSONを読まない
* スプライトのJSON（JSONとして解析でき、`format`が`"oz-vector-editor-sprite"`のもの）を「開く」「インポート」で選ぶと、**読み込み不可**（既存の通知`readFailed`）になる。アプリは停止しない。キャンバスは作られず、開いているキャンバスも変わらない。通知の種類は増やさない。
* スプライトのJS（`.js`）の読み込み（JSは実行せずテキストから`source`を取り出し、`DocumentSerializer.deserialize`へ渡す）、作業データファイル（`.ozve.json`・従来の`.json`）の読み込みは、これまでどおり。判別は引き続き中身で行う（拡張子に頼らない）。
* 「開く」「インポート」のファイル選択（`index.html`の`accept`）は、作業データファイル（`.json`）とスプライトのJS（`.js`）を選べる状態のまま（作業データファイルが`.json`のため`.json`は外さない）。ボタンの`title`の文言と、読み込み不可の通知`readFailed`の文言から、スプライトの`.json`を開けると読める表現をなくす（例：「本アプリで出力した作業ファイル（.ozve.json）、またはエンジン用のファイル（.js）」の趣旨）。
* 「開く」で作るキャンバス名の規則（末尾の`.ozve.json`・`.json`・`.js`を1回だけ除く）は変えない（`.json`は作業データファイルの従来の拡張子として引き続き除く）。
* 全体失敗の警告（`console.warn`）は、これまでどおりどの経路でも1回とし、例外を投げないこと。スプライトのJSONを読み込み不可にする判定を`FileContentReader`・`DocumentSerializer`のどちらで行うか（例：JSONから得た値は作業データとしてのみ扱い、`DocumentSerializer`の`format`の不一致で落とす／`FileContentReader`で明示的に読み込み不可にする）は計画時に決める。ただし`DocumentSerializer`にスプライト形式の知識を持ち込まないこと。

### 要件3: 確認用ページをJSだけにする
* 確認用ページのファイル選択（`accept`）はスプライトのJS（`.js`）だけにする。
* JSONのファイル（中身がJSONとして解析できるもの。拡張子に頼らず中身で見分ける）を選んだ場合は、`import`を試みずに、ページは停止せず前の表示を消して「本アプリのスプライトのJSではない（JSONは表示しない。書き出したJSを選ぶ）」ことが分かる文言を表示する。続けて別のファイルを選び直せること。理由の区分を新設するか既存の区分（`notSprite`等）の文言を直すかは計画時に決める（文言の唯一の定義箇所は`SpriteCheckPage.js`の`FAILURE_MESSAGES`のまま）。
* JSを選んだ場合の挙動（実行して既定のexportの`draw(ctx)`で描く、原点の印・外枠、情報欄、読み込めなかった場合の表示）は、これまでどおり。
* 確認用ページがJSONを描くためだけに使っていたもの（`SpriteCheckPage`から`CodeExporter.toModuleText`への依存、`SpriteCheckInspector`のJSONの値の判定等）は、使われなくなるなら削除する（呼び出し元・JSDoc・テストも合わせて整理する）。`SpriteCheckInspector.parseText`の扱い（JSONの見分けに使い続けるか）は計画時に決める。
* `importFailed`の文言（現在「JSONとして読めず、JSとしても読み込めませんでした…」）など、JSONを表示できる前提の文言・注意書きを、JSだけを扱う前提に直す。

## 【計画立案時の絶対遵守ルール (Constraints)】
*   **アーキテクチャの維持** : 依存方向`main.js → edit → io → core → shapes`を守ること。`palette/`はスプライトデータ・作業データの中身を知らない（文言の変更のみ）。`DocumentSerializer`はスプライト形式を知らない。確認用ページのJSは、エディタの状態を持つモジュール（`core/`の状態・`edit/`・`palette/`）を`import`しない。外部フレームワーク・ライブラリを導入しない Vanilla JS の原則を維持すること。
*   **ビルドなしの維持（憲法3章）** : Node.jsはテストの実行にのみ使う。
*   **書き出したJSを変えない** : 「出力（エンジン用）」で落ちるJSのテキストは、本作業の前後で同じであること（同じキャンバスから同じ内容になる）。`CodeExporter.toModuleText`・`SpriteSerializer.serialize`・埋め込む描画処理を変更しない。
*   **単一の定義箇所** : スプライト形式の識別子・現行版・JSの形・ファイル名の拡張子の規則・通知の文言・確認用ページの文言は、それぞれ既存の1箇所で定義したままにすること。
