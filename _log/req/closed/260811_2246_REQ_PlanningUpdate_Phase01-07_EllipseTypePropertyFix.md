#### 【計画書（RES）の改修要件】

##### 1. 概要
チェック0監査の結果、計画書内に実際のコードベースと食い違う記述が2箇所見つかった。

* **箇所A（「2. アーキテクチャ設計」要件1）**：`this.type`を「共通データ構造上すでに規定されている標準プロパティ」と説明しているが、`Line.js`/`Curve.js`/`Rect.js`のいずれにも`type`プロパティは存在しない（既存ソース確認済み）。`Ellipse`が新規に導入する固有プロパティであるにもかかわらず、既存の共有規約であるかのような誤った説明になっている。機能面の実害はない（`core/`層は関知しない`Ellipse`内部限定の分岐用フラグのため）が、この誤った前提がタスク8で`PROJECT_ARCHITECTURE.md`へ転記されると、後続フェイズの実装AIを混乱させる懸念がある。
* **箇所B（「3. タスクリスト」タスク1、および「5. 懸念事項・要確認ポイント」該当箇所）**：色・線幅の共通プロパティ例として「`color`/`strokeWidth`/`isFilled`」を挙げているが、既存図形の実際の命名は`color`ではなく`strokeColor`である。また`isFilled`（塗りつぶし関連）はどの図形にも存在せず、かつ本Phaseの元REQ（`./_log/req/2609_2250_REQ_Phase01-07_Ellipse_Implementation.md`）のNon-goals「塗りつぶし（Fill）機能は本Phaseでは実装しない」と直接矛盾する例示になっている。このまま実装させると誤命名（`this.color`）や不要なプロパティの混入を誘発するリスクがある。

いずれも計画の大枠（5頂点構造・正準正規化ロジック・0除算ガード等）には影響しない、記述の事実誤認の訂正のみを目的とする。

##### 2. 修正箇所

**箇所A：「2. アーキテクチャ設計」要件1の該当行を以下に置き換える：**

修正前：
```
* `shapeType`（`'circle'` | `'arc'`）は、共通データ構造上すでに規定されている `this.type` プロパティにそのまま格納する（`ShapeData` 標準プロパティ `type` の値をそのまま種別フラグとして流用するため、専用の重複フラグは持たない＝Single Source of Truth）。円・弧の判定が必要な箇所（`draw`/`hitTest`等）は都度 `this.type === 'circle'` を参照する。
```

修正後：
```
* `shapeType`（`'circle'` | `'arc'`）は `this.type` プロパティに格納する。ただし `this.type` は `Line`/`Curve`/`Rect` を含む既存図形いずれにも存在しない、`Ellipse` が新規に導入する固有の内部プロパティである（既存の共通データ構造上の標準プロパティではない）。この `this.type` は `Ellipse.js` 内部の分岐（`draw`/`hitTest`等での `this.type === 'circle'` 判定）にのみ用い、`core/`層（`VectorModel`/`CanvasManager`/`InputTracker`）からは一切参照されない、`Ellipse`自身に閉じたプロパティであることを明確にする。
```

**箇所B-1：「3. タスクリスト」タスク1の該当行を以下に置き換える：**

修正前：
```
* 色・線幅・塗りつぶし等の共通プロパティ（`color`/`strokeWidth`/`isFilled`等）は、既存図形（`Line.js`/`Curve.js`/`Rect.js`）のコンストラクタ初期化パターンに完全準拠させる（実装時に当該ファイルを直接参照し、命名・デフォルト値の一貫性を確認すること）。
```

修正後：
```
* 線の色・太さは、既存図形（`Line.js`/`Curve.js`/`Rect.js`）と同一の命名・デフォルト値（`strokeColor = '#000000'`, `strokeWidth = 2`）に完全準拠させる（実装時に当該ファイルを直接参照し、一貫性を確認すること）。塗りつぶし（`isFilled`等）関連のプロパティは、元REQ Non-goals「塗りつぶし（Fill）機能は本Phaseでは実装しない」に従い、一切追加しないこと。
```
