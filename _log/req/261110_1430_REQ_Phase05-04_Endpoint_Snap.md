## 【実装要件】
直線を描くとき、および選択モードで線の端点のハンドルをドラッグするときに、結合できる線（直線・開いたパス）の端点へ吸い付くようにし、吸い付いた端点で描き足し・結合・閉じる操作を行えるようにする。吸い付いている端点には、塗りつぶしたハンドルを表示する。

前提（Phase 05-02・05-03で追加済み）：
* パスは`js/shapes/Path.js`（図形種別`'path'`）。図形データは`{ type: 'path', id, points, closed, segments: [{ kind: 'line' }, ...], strokeColor, strokeWidth }`で、頂点数の下限は開いたパス2点・閉じたパス3点、区間の要素数は開いたパス`n - 1`・閉じたパス`n`（`n`＝頂点数）の不変条件がある。`Path`のコンストラクタは引数を検証しない。パスは`ShapeFactory.create`では作れない（結果のパスは`Path`のコンストラクタ等で作る）。直線（`Line`、図形種別`'line'`）は頂点2つ（始点・終点）を持つ。
* 結合の規則は`js/shapes/PathJoinRules.js`（`JOIN_TOLERANCE_SCREEN_PX`・`isJoinableLine`・`classifyJoin`・`buildClosedPath`・`buildJoinedPath`・`planJoin`）、選択中の線の結合の手順は`js/edit/PathJoiner.js`、モデルの差し替えは`VectorModel.replaceShape`（結果の図形だけを選択する。前提は選択モード）。結合の規則（端点の重なりの判定＝画面上5px、基準の線＝重なり順で奥の線、結果の向き・色・太さ・重なり順の位置＝基準の線のもの、2本の結合は新しいid、閉じる操作は元のid）は開発資料3章11.と`_doc/arch/12_shapes.md`に記載がある。
* 直線は図形作成モードで「クリックで描き始め → マウスを動かす → クリックで描き終える」で作る（`InputTracker.handleClick`の`startDraft`・`commitDraft`）。

### 要件1: 吸い付く対象・距離・候補の選び方
* **吸い付く対象**：モデルにある図形のうち、結合できる線（`isJoinableLine`が真＝直線・開いたパス）の端点（始点・終点）だけ。曲線・矩形・円・弧・閉じたパスの点、パスの途中の頂点には吸い付かない（DIRのメモ「吸い付く＝描き足し・結合になる、の1対1」）。
* **吸い付く距離**：マウスカーソルと端点の距離が**画面上8px以内**（ちょうどを含む）なら吸い付く（発注者の決定）。その時点の表示倍率でワールド座標の長さへ換算して判定する（表示倍率によらず画面上で一定）。8pxの定数は1箇所に定義し、結合の重なりの判定（`JOIN_TOLERANCE_SCREEN_PX`＝5px）とは別の値として扱う。
* **候補が複数あるとき**：カーソルにいちばん近い端点を選ぶ。距離が等しいときは重なり順で前面の図形の端点を選ぶ。同じ図形の始点と終点が同距離なら始点を選ぶ。
* **吸い付いたときの座標**：描き始め・描き終え・ドラッグ中の頂点の座標は、吸い付いた端点の座標そのもの（ワールド座標）になる。
* 修飾キーによる吸い付きの一時無効は作らない（DIRの「やらないこと」。精度のPhase）。

### 要件2: 吸い付いている表示（発注者の決定：中を青で塗った正方形）
* 吸い付く対象の端点にカーソルが吸い付いている間、その端点の位置に、選択ハンドルと同じ大きさ（画面上8px）の正方形を、中を青（選択ハンドルの枠と同じ`#4a90e2`）で塗りつぶして描く。枠の色・太さは計画時に決めてよい（選択ハンドルと見分けがつくこと）。
* 表示は1つだけ（いま吸い付いている端点のみ）。吸い付いていないときは描かない。表示は図形・選択ハンドル・作成途中の図形より前面に描く。
* 表示する場面：(a) 図形作成モードで描く図形種別が直線のとき、描き始める前（カーソルを動かしているだけのとき）、(b) 直線を描いている途中（描き終える点の候補）、(c) 選択モードで端点のハンドルをドラッグしている途中（要件5）。それ以外の場面（選択モードでカーソルを動かしているだけのとき、直線以外の図形種別のとき、キャンバス移動モード、パン中）では表示しない。
* 表示の状態（いまどの点に吸い付いているか）をどこに持つか、どう描画へ渡すかは計画時に決めること。再描画は既存の経路（`model.onChange`→`CanvasManager.render`等。開発資料3章冒頭）で行い、機能専用の再描画経路を足さない。描画層（`CanvasManager`）に状態の判定を持ち込まない（渡された引数を描くだけ）。
* 表示を消し忘れない：モードの切り替え・図形種別の切り替え・描き終え・描き途中の取り消し・ドラッグの終了と中断・キャンバスの切り替えや読み込み・取り消し/やり直し（`abortOngoingOperation`を通る処理）の後に、古い表示が残らないこと。キャンバス外へカーソルが出た場合の扱いは計画時に決めてよい（次のカーソル移動で正しくなればよい）。

### 要件3: 直線を描くときの振る舞い（描き足し・結合・閉じる）
図形作成モードで描く図形種別が直線のときだけ、要件1の吸い付きを行う（曲線・矩形・円・弧を描くときは吸い付かない。従来どおり）。描き始めのクリックで吸い付いていた端点を「始点の端点」、描き終えのクリックで吸い付いていた端点を「終点の端点」と呼ぶ。描き終えのクリックで、次の表のとおり確定する。

| 始点の端点 | 終点の端点 | 結果 |
| --- | --- | --- |
| なし | なし | 従来どおり独立した直線の図形を追加する（既存の振る舞いを変えない） |
| 線Lの端点 | なし | **描き足し**：Lの、描き始めた端点の側に頂点を1つ足す（3-1） |
| なし | 線Mの端点 | **描き足し**：Mの、吸い付いた端点の側に、描き始めた点を頂点として1つ足す（3-1） |
| 線Lの端点E | 同じ線Lの、Eではない方の端点 | **閉じる**：Lを閉じたパスにする（3-2） |
| 線Lの端点E | 同じ線Lの同じ端点E | 何も起きない（3-3） |
| 線Lの端点 | 別の線Mの端点 | **結合**：LとMを、吸い付いた2つの端点の間に描いた区間でつないで1本の開いたパスにする（3-4） |

* **3-1 描き足し**：吸い付いた線（以下「元の線」）の向き（始点→終点）を保ったまま、足す頂点を元の線の先頭または末尾に加えた開いたパスにする。元の線が直線なら、その直線は開いたパスになる（DIRの実装要件）。結果は元の線と同じ図形として扱う：**元の線のid・色・線の太さ・重なり順の位置を保つ**（DIR「描き足しになる（別の図形にならない）」。閉じる操作が元のidを保つ05-03の規則に揃える）。描いている直線の色・太さは使わない。元の線の頂点の配列・頂点オブジェクトを結果と共有しない。足す頂点が吸い付いた端点と結合の重なりの判定（画面上5px以内）で重なる場合の扱い（何も起きない／足さない）は、05-03の規則（重なっていれば1つにまとめる）に揃えて計画時に決めること（吸い付かなかった描き始め・描き終えの点は、8px以内のすべての端点の外にあるため、通常は重ならない）。
* **3-2 閉じる**：Lの頂点の並び・向きを変えずに、終点から始点への区間を足して閉じたパスにする（描いた区間がその閉じる区間になる）。05-03の閉じる規則（`buildClosedPath`）に揃え、**元のid・色・線の太さ・重なり順の位置を保つ**。Lの頂点が2つ（直線・頂点2つのパス）の場合は閉じられないため、何も起きない（描いた線も追加しない。元の線も変えない。履歴に残さない。発注者の決定）。Lが頂点3つ以上の開いたパスなら閉じたパスになる（両端は別の端点なので、05-03の「始点と終点が重なっていればまとめる」は通常起きないが、重なっていた場合は05-03の規則どおりまとめ、まとめて3つ未満なら何も起きない）。
* **3-3 同じ端点**：長さ0の区間になるため、何も起きない（描いた線も追加しない。元の線も変えない。履歴に残さない）。
* **3-4 結合**：05-03の「2本の結合」の規則に揃える（基準の線＝LとMのうち重なり順で奥の方、結果の向き・色・線の太さ・重なり順の位置＝基準の線のもの、**新しいid**、もう一方の線は除かれる）。ただし、つなぐ端点の組は「いちばん近い組」ではなく**吸い付いた2つの端点（Lの端点とMの端点）**とする。2つの端点が離れていれば間に直線の区間が足され（描いた区間がその区間になる）、重なっていれば（画面上5px以内）1つの頂点にまとめる（まとめた頂点の座標は基準の線の端点）。結果は常に開いたパスで、両端が重なっても自動では閉じない。
* **規則の使い回し**：上の結果の組み立てはすべて`PathJoinRules`の規則（`isJoinableLine`・`buildClosedPath`・`buildJoinedPath`と`JOIN_TOLERANCE_SCREEN_PX`）を使い、同じ規則を別の場所に書き直さない。`buildJoinedPath`はいちばん近い端点の組を自分で選ぶため、3-4（と要件5の結合）では「つなぐ端点を指定する入口」を`PathJoinRules`に足すこと（既存の`buildJoinedPath`・`planJoin`の振る舞いと05-03のテストは変えない）。3-1を「元の線」と「描いた直線」の2本の結合として既存の規則で組み立てるか、別の入口を足すかは計画時に決め、理由を記載すること。
* **確定後の状態**：図形作成モードのまま、作成途中の図形が無い状態（IDLE）に戻る。図形作成モードでは選択集合は空のまま（「選択モード以外では選択集合は空」の不変条件。`replaceShape`は結果を選択し、前提が選択モードであるため、そのまま使えない。選択しない差し替えの方法を計画時に設計すること）。描き足し・結合・閉じた直後に、できた線の端点から続けて描き始められる（端点への吸い付きにより）。
* **描き途中の取り消し**：描き始めた後、描き終える前に取り消した場合（`Esc`・モードの切り替え・図形種別の切り替え・取り消し/やり直しの前処理等、既存の作成途中の破棄の経路）は、作成途中の直線を捨てるだけで、吸い付いていた元の線は変わらない。履歴にも残らない（既存の振る舞いと同じ）。
* 描いている途中の見た目（作成途中の直線）は、描き終えの点が吸い付いていれば吸い付いた端点まで、吸い付いていなければカーソルまで伸びる。

### 要件4: 直線を描くときの履歴（Undo/Redo）
* 描き足し・閉じる・結合は、既存の図形の書き換え・除去を含めて履歴へ1件だけ記録する。Undo1回で操作前の状態（元の線が同じid・同じ形・同じ重なり順）に戻り、Redo1回でやり直せる。何も起きない場合（3-2の閉じられない場合・3-3）は記録しない。
* 記録は既存の`beginEdit`/`commitEdit`の対で行う（`InputTracker`が直線の作成を記録するのと同じ記録先）。選択集合の復元の扱いは既存の仕組み（`SnapshotAdapter`・`shouldRestoreSelection`）に従い、新しい規則を足さない。

### 要件5: 端点のハンドルのドラッグ（発注者の決定：吸い付いて結合する）
* 選択モードで、結合できる線（直線・開いたパス）の**端点のハンドル**（直線の始点・終点、開いたパスの最初・最後の頂点）をドラッグしている間、要件1の吸い付きを行う。パスの途中の頂点のハンドル、直線の移動（`move`）ハンドル、曲線・矩形・円・弧・閉じたパスのハンドル、本体のドラッグ（移動）では吸い付かない（従来どおり）。
* **吸い付く対象**：ドラッグしている線以外の、結合できる線の端点。加えて、ドラッグしている線自身の**もう一方の端点**は、そこへ重ねて閉じたときに頂点が3つ以上残る場合（＝頂点4つ以上の開いたパス）だけ対象にする（閉じられない場合は吸い付かない。「吸い付く＝結合・閉じる」の1対1を保つため）。ドラッグしている端点そのものは対象にしない。
* ドラッグ中、吸い付いている間は、ドラッグしている頂点が吸い付いた端点の座標に置かれ、要件2の表示が出る。吸い付く範囲を出れば頂点はカーソルに追従する（従来どおり）。
* **離したとき**（ドラッグの終了）に吸い付いていれば：
  * 別の線Mの端点に吸い付いていた → ドラッグしている線とMを、05-03の「2本の結合」の規則（3-4と同じ。基準の線＝重なり順で奥の方、新しいid、つなぐ端点＝ドラッグしていた端点とMの吸い付いた端点。2つは同じ座標なので1つの頂点にまとまる）で1本の開いたパスにする。結果のパスだけが選択された状態になる（05-03の結合と同じ）。
  * 自身のもう一方の端点に吸い付いていた → 05-03の閉じる規則で閉じたパスにする（重なった2つの端点は1つにまとまる。元のid・色・太さ・重なり順の位置を保つ）。そのパスが選択された状態のまま。
* 離したときに吸い付いていなければ、従来どおり頂点を動かしただけで終わる。
* **履歴**：頂点の移動と結合・閉じる操作をあわせて1件として記録する（Undo1回でドラッグを始める前の状態に戻り、Redo1回で結合・閉じた後に戻る）。既存のハンドルのドラッグの記録（閾値超過時の`beginEdit`・終了時の`commitEdit`）の中で行い、記録を2件に分けない。
* **中断**（ウィンドウのフォーカスが外れる・モードの切り替え等の既存のドラッグ中断）では結合・閉じる操作を行わない（頂点の位置は中断した時点のまま。既存の振る舞いと同じ）。
* ハンドルの当たり判定・優先順位（`hitTestHandle`・`InputTracker`の当たり分類）は変えない。

### 要件6: 処理を置く場所
* `InputTracker`（約1150行）へ足すのは、入力の場面（カーソル移動・描き始め・描き終え・ハンドルのドラッグの更新と終了）で吸い付きの照会・結果の反映を**呼び出す**最小限の配線に留める。吸い付く候補の探索・距離の判定・結果の組み立て・モデルへの反映の手順は`InputTracker`の外に置く（`_doc/COWORK_STATUS.md` 2章A。再分離は精度のPhase）。`InputTracker`の行数の増分を計画書に見積もって記載すること。
* `InputTracker`は図形種別の分岐を行わず、`vertexIndex`規約を`core/`層にハードコードしない（開発資料4章`InputTracker`の「知らないこと」）。「描く図形種別が直線のときだけ吸い付く」「端点のハンドルかどうか」の判定は、この制約を破らない形（図形種別・頂点構造を知ってよい場所の関数、または`main.js`が注入する中立な関数等）で設計し、理由とともに記載すること。
* 吸い付きの規則（対象の判定・端点の列挙・候補の選び方）と結果の組み立て（要件3・5）は、図形種別・頂点構造を知る必要がある。開発資料の各フォルダの「知らないこと」（特に`edit/`の「図形種別の分岐、図形固有のプロパティ名」・`VectorModel`の図形種別を関知しないこと）と依存方向（`core → shapes`の一方向、`shapes/`は`core/`をimportしない）を破らない置き場所を計画時に設計し、理由とともに記載すること（05-03の`PathJoinRules`（規則）・`PathJoiner`（手順）の分け方に倣うことを推奨する）。規則の関数は表示倍率を知らず、ワールド座標の距離を引数で受け取る形にすること（自動テストで確かめられるようにするため）。新しいファイルを足す場合は、開発資料1章のフォルダ構成と4章の責務に追記する。
