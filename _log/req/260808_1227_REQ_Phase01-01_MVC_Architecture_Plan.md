#### 【実装要件】
UI要素やパレット、詳細なイベントを一切排除し、**「Canvasをどこでも1クリックすると、仮の『直線（LINE）』データが内部で1つ生成・追加され、Canvasに静的描画される」** という、MVCおよびES Modulesの最小接続サイクルを構築する。

##### 1. 作成・連携するファイル群の設計案（物理パス・論理クラス完全明示）
*   **`./index.html`** : キャンバス要素（`<canvas id="editor-canvas">`）だけが中央に配置された、スタイリングのない最小限のHTML。
*   **`./js/main.js`** : アプリの起動トリガー。DOM読み込み完了後に、後述の Model / CanvasManager / InputTracker をインスタンス化し、お互いを連携・バインドする。
*   **`./js/core/VectorModel.js`** (Model) : 
    *   単一の真実（SSOT）となる「Shapeオブジェクトの配列（shapes）」をプライベート保持する。
    *   外部からShapeを安全に追加するメソッドを用意する。
    *   Shape配列が更新された際、変更イベントを外部（CanvasManager）に通知する仕組みを定義する。
*   **`./js/core/CanvasManager.js`** (View) :
    *   Canvas要素を保持し、再描画ループまたはイベント駆動による「全クリア ➡️ 全Shapeの再描画」を司る。
    *   **状態（選択中の図形など）や入力イベントは一切持たせず、Modelからデータを読み込んでただ愚直に描画する責務を維持すること。**
*   **`./js/core/InputTracker.js`** (Controller) :
    *   Canvasに対する「マウスのクリック」イベントを監視し、クリックを検知したら仮の直線データを生成して `VectorModel` に追加を依頼する。

##### 2. スコープ外（本計画に絶対に含めないこと）
*   図形選択パレットの作成、サイドバーや設定UI
*   直線の座標をマウスから取得するロジック（P1-2で対応）
*   直線以外の図形（曲線、矩形、円、楕円）の実装

#### 【将来の拡張性に関する設計要件（最重要・要計画記述）】
AIは、本最小実装（Phase 01-01）のコードが、将来の機能追加（P1-2 〜 P1-5）の際に壊されず、綺麗に「拡張（O-C原則）」できるように、以下の点に関する具体的な設計方針を作業計画書（RES）の『2. アーキテクチャ設計』内に明文化して提案すること。

1.  **図形クラス（Shape）の物理ファイル分割設計**:
    *   将来、各種図形（直線、曲線、矩形、円、楕円）がそれぞれ `./js/shapes/` ディレクトリ配下に独立した具象クラスファイル（`Line.js`等）として分割されることを見据え、P1-1における「仮の直線」のオブジェクト設計（JSDocによる型定義、共通インターフェース）をどう定義するか。
2.  **描画（Renderer）の結合度低下設計**:
    *   `./js/core/CanvasManager.js` 内に、各種図形の Canvas API 実装（`ctx.lineTo` 等）をベタ書き（if/switch分岐）すると、図形追加のたびにこのファイルが肥大化し破壊されます。
    *   これを防ぐため、描画処理を各Shapeクラス側へ持たせる（`shape.draw(ctx)`）か、あるいは描画ロジックを別モジュールに綺麗に委譲する設計（レンダラーのストラテジー化など）にするか、P1-1の時点でどう骨組みを担保するか。
3.  **入力（InputTracker）の状態遷移マシンの余地**:
    *   将来的に「1クリック配置」や「複数クリック（2クリック）配置」など、パレットで選ばれた図形ごとに変化する複雑な入力ロジックに `./js/core/InputTracker.js` が耐えられるよう、どのような入力状態管理（Stateパターンの導入余地など）を想定して骨組みを設計するか。

#### 【計画立案時の絶対遵守ルール (Constraints)】
*  **MVCの厳守（防衛線の維持）**: 描画（CanvasManager）にデータを保持させず、入力（InputTracker）から直接描画を呼ばせず、「Model ➡️ 変更通知 ➡️ CanvasManager再描画」というクリーンなPull型の関係を100%維持する設計を計画すること。
*  **ファイル先頭への『責務定義』**: 新規作成するすべてのJSファイルの最先頭行に、JSDocでそのファイルが担う「単一の責務（Responsibility）」を3行以内で記述するタスクを各ファイル生成手順に含めること。
