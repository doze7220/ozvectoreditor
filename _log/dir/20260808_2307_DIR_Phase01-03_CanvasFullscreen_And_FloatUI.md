### 設計指針書 DIR: Phase 01-03 : キャンバス全体化、右側固定フロートUI、およびツールモード切り替えの基盤確立
*  ルール: `./PROJECT_CONSTITUTION.md`
*  開発資料: `./PROJECT_ARCHITECTURE.md`

--------------------------------------------------------------------------------

#### 1. 設計目的
本フェーズでは、今後のベクターエディタ拡張（パン・ズーム、新規図形追加）において絶対的な土台となる「全画面ワークスペース」と「明示的なツール選択状態」を確立する。
当初予定していた「複数図形パレット」の実装に先立ち、レイアウト変更に伴う座標バグを永久に根絶するための「Canvasの全体化」と、アドホックな入力分岐を解消するための「フロートUIおよび選択モード（Select/Line）」を導入する。

--------------------------------------------------------------------------------

#### 2. アーキテクチャ設計

##### 【要件1: キャンバスの全体化 (100vw/100vh化)】
*   Canvas要素をブラウザの表示領域全体（`100vw`, `100vh`）に広げ、CSS上で `position: absolute; top: 0; left: 0; z-index: 1;` とする。
*   これにより、Canvasの左上原点 `(0, 0)` は常にブラウザの表示領域の左上 `(0, 0)` に物理的に一致する。
*   ウィンドウサイズが変更された場合でも、高DPI（dpr）対応のピクセルバッファをリサイズ追従させる。

##### 【要件2: 右側固定フロートUI（コントロールパネル）の導入】
*   UI要素（パレット、ツール切り替えボタン）は、Canvasの上に重ねる形で配置する（`position: absolute; z-index: 10;`）。
*   まずは画面の右側に固定配置される、スタイリッシュでシンプルな「コントロールパネル（フロートウィンドウ）」をHTML/CSSで構築する。
*   将来的なウィンドウドラッグ移動を考慮し、DOM構造は本体コンテナとヘッダー（ドラッグバー想定の領域）を明確に分離した構造にしておく。

##### 【要件3: ツールモード切り替えの導入 (SELECT vs LINE)】
*   これまでの「空白クリック＝新規作成」「図形クリック＝選択」という暗黙の入力分岐を卒業し、ユーザーが意図的に「何を行うか」を切り替える明示的なツール状態（`currentTool`）を導入する。
    *   **SELECT_TOOL（選択・編集ツール）**: 図形のホバー、クリック選択、ハンドルのドラッグ操作、削除を行うモード。空白クリックをしても新規図形は作成されない。
    *   **LINE_TOOL（直線ツール）**: 2クリックで直線を引くことのみに特化したモード。このモード中は既存図形のホバーや選択判定は一切行わない。
*   UI上に「選択ツール（矢印アイコン等）」と「直線ツール（ペン/ラインアイコン等）」の切り替えボタンを配置し、現在アクティブなツールが視覚的に強調されるようにする。

##### 【要件4: 抽象ファクトリ `ShapeFactory.js` の新設（Modelのデカップリング）】
*   `VectorModel.js` 内にハードコードされている `new Line()` を排除するため、生成責務を完全に隔離した `./js/core/ShapeFactory.js` を作成する。
*   Modelは `ShapeFactory.create(type, x, y)` を経由して抽象的に図形を生成し、個別図形（Line等）へのインポート依存関係を完全に排除する。
*   ドラフト更新（`updateDraft`）におけるLine固有プロパティ（`x2`, `y2`）へのアクセスを、すでにLineに実装済みの共通頂点更新インターフェースである `shape.setVertex(1, x, y)` のポリモーフィックな呼び出しへとリファクタリングする。

#### 3. 関連フォルダと物理ファイル構成
```
/workspace/
├── index.html                   ← 全画面Canvas化、右側フロートUI（ボタン群）の追加
├── js/
│   ├── main.js                  ← ツール切り替えイベントの仲介、初期化の連携
│   ├── core/
│   │   ├── VectorModel.js       ← ShapeFactoryの利用、Line依存の除去、ドラフト更新のポリモーフィック化
│   │   ├── CanvasManager.js     ← ウィンドウリサイズ時のdprバッファ再計算の対応
│   │   ├── InputTracker.js      ← currentTool（Select/Line）状態の保持、モード別イベントハンドリングの整理
│   │   └── ShapeFactory.js      ← 【新規】指定されたtypeに基づくShapeインスタンスの生成・返却
│   └── shapes/
│       └── Line.js              ← 変更なし（すでに頂点操作APIは5.5でカプセル化済み）
```

#### 4. 実装AI（Pure Executor）を導く3ステップ・ロードマップ

実装AI（Claude Desktop）のハルシネーションを防止し、トークン消費を最小化するため、本フェーズは以下のクリーンな3つの独立タスクに分割して指示を出すこと。

##### 🟩 ステップ1: Canvas全体化 ＆ 右側フロートUIの土台構築
*   **対象**: `index.html`, `js/core/CanvasManager.js`
*   **目的**: 物理レイアウトをエディタとしてのデファクトスタンダード（全画面）に変更し、リサイズと高DPIに完璧に対応させる。
*   **作業要件**:
    1.  `index.html` のCSS（styleタグ内）を改修し、Canvasを `100vw`, `100vh` の全画面表示にする。
    2.  画面右側に固定されるシンプルなフロートコンテナ（`<div id="control-panel">`）を `position: absolute; right: 20px; top: 20px;` 等で重ねて配置。
    3.  フロートパネル内に、将来ボタンを配置するための領域（ヘッダーとコンテンツ部）をマークアップ。
    4.  `CanvasManager.js` に `window.addEventListener('resize')` に伴うバッファ再計算・再描画トリガーをクリーンに実装（リサイズしても描画がボケず、等倍が維持されること）。

##### 🟩 ステップ2: `ShapeFactory.js` の新設とModelの完全デカップリング
*   **対象**: `js/core/ShapeFactory.js` (新規), `js/core/VectorModel.js`
*   **目的**: Modelから直線への直接依存を剥がし、未来の図形追加（曲線、矩形）時にModelを1行も触らなくてよい開閉原則の防衛線を敷く。
*   **作業要件**:
    1.  `./js/core/ShapeFactory.js` を新規作成。最先頭行に「図形オブジェクトの生成責務（Factoryパターン）を担う。」と3行以内で記述。
    2.  `create(type, x1, y1, x2, y2)` メソッドを実装。`type === 'line'` の場合に `Line` インスタンスを生成して返す。
    3.  `VectorModel.js` から `Line.js` のインポートを削除。
    4.  `VectorModel.startDraft(type, x, y)` のように引数を拡張。内部で `ShapeFactory.create(type, x, y, x, y)` を呼び出すよう変更。
    5.  `VectorModel.updateDraft(x, y)` 内の `this.#draftLine.x2 = x` などの直接アクセスを、`this.#draftLine.setVertex(1, x, y)` のポリモーフィックな委譲に書き換え。

##### 🟩 ステップ3: ツールモードの導入とフロートUIの接続
*   **対象**: `index.html`, `js/core/InputTracker.js`, `js/main.js`
*   **目的**: ユーザーがクリックしたボタン（UI）とコントローラーの入力解釈モードを同期させる。
*   **作業要件**:
    1.  右側のフロートパネル内に「選択ツール（矢印アイコン等）」と「直線ツール（ペンアイコン等）」のHTMLボタンを配置。
    2.  `InputTracker.js` 内に `this.currentTool = 'select';` (デフォルト) を導入。
    3.  `InputTracker` のマウスイベント（mousedown, mousemove, click）において、`currentTool === 'select'` の場合はホバー・選択・ハンドルドラッグのみを実行し、`currentTool === 'line'` の場合は2クリック直線作成処理のみを実行するように、状態別の綺麗なルーティングにリファクタリング。
    4.  `main.js` において、フロートUIのボタンクリックイベントを購読し、`inputTracker.currentTool`（またはセッター）を切り替えるためのイベント仲介配線を繋ぐ。直線が確定（commitDraft）した際は、自動で選択ツール（select）に切り替えるなどの使い勝手の配慮を行う。

#### 5. 懸念事項・要確認ポイント（後続への伏線）
*   **フロートUI上でのマウス操作の透過防止**:
    *   コントロールパネル（右側ウィンドウ）の上でボタンをクリックしたりドラッグしたりした際、その真下にあるCanvasにクリックイベントが透過して、意図しない図形の選択解除やライン描画の開始が起きてはならない。
    *   ステップ3の実装時、フロートUI要素に対する `mousedown` / `click` / `mousemove` イベントに、必ず `event.stopPropagation()` を仕込んで、Canvas層（InputTracker）へイベントが漏れるのを防ぐ防衛線を引かせること。
