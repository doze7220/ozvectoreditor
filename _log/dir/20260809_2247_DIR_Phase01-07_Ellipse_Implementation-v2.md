#### 1. 設計目的
本Phaseの目的は、円・楕円・弧という幾何学的に同根の図形を、将来の相互型変換およびモーフィング（Lerp）時のトポロジー破綻から100%保護するため、**「`Ellipse.js`（楕円弧クラス）」の1枚に完全一元化して設計・実装すること**である [221, 265]。
UI（パレット）側は「円」ボタンおよび「弧」ボタンの双方に実体（Ellipse）を接続するが、初期は「弧」を角度固定の半円としてスタンプ配置し、かつ編集用の表示ハンドルを制限することで、不具合や未実装感を防ぎつつ、将来的にタイムライン上で「楕円」と「弧」をシームレスに行き来可能にするための極めて頑強な幾何学データ基盤（9メソッド契約）を確立する [87, 94]。

#### 2. スコープ境界
##### やること
1.  **shapes/Ellipse.js の新規実装** :
    *  将来の「弧（Arc）」へのシームレスな移行・変形を完全に保証するため、最初から**「頂点数（points配列の長さ）を5で完全固定」**した一元データ構造を構築する [60, 87]。
    *  **「円」ツール選択時** : 開始角 $0$、終了角 $2\pi$ でロックされた、純粋な「閉じた楕円（円・楕円）」として生成する。
    *  **「弧」ツール選択時** : 開始角 $0$、終了角 $\pi$ でロックされた、お椀型の「開いた半円（弧）」として生成し、`closePath`（始点と結ぶ処理）を呼ばずにストローク描画する。
    *  変形編集時は、円・半円ともに**3つの操作ハンドル（中心、右端、上端）のみを表示・操作可能**とし、角度（閉じる角度・開く角度）は固定維持された状態で平行移動と拡縮（X/Y半径の個別伸縮）を行えるようにする。
2.  **ShapeFactory.js の circle/arc 分岐の一元接続** :
    *  現在 Line スタブを返している `circle` および `arc` のケースを、いずれも新設する `Ellipse` クラスのインスタンス生成へ物理結線する [51, 102]。
    *  コンストラクタ引数（または生成時パラメータ）を出し分けることで、同一の `Ellipse` を「閉じた円」か「開いた半円」として初期生成し分ける。

##### やらないこと（Non-goals）
*   **作図・編集時における「開始角・終了角」の可変ハンドルの表示・操作** :
    *  本フェイズのスコープ外とする。データ構造（pointsの長さ5）として角度制御点を裏側で先行保持し、同期更新するのみに留め、操作ハンドル自体の有効化は、後続の「弧・プロパティ拡張フェイズ」へクリーンに送る。
*   **SHIFTキーによる「正円」作図スナップ** :
    *  矩形と同様、UI・操作充実フェイズへ持ち越し、本フェイズでは対角ドラッグ比率通りの自由な楕円/半楕円作図を許容する [87]。

#### 3. 実装要件

##### 要件1: shapes/Ellipse.js の幾何データ構造（トポロジーロックの伏線）
将来「閉じた楕円」から「一部が切り欠かれた弧」への行き来や、補間再生（Lerp）時の頂点数不一致を永久に防ぎ、自己完結させるため、`points` 配列は最初から以下の **長さ5で固定保持** する [60, 221]。

*   `points[0]`: **中心点 (Center)**
*   `points[1]`: **右端制御点 (Right Control)** ➡️ 中心からの距離を X半径 ($r_x$) とする。
*   `points[2]`: **上端制御点 (Top Control)** ➡️ 中心からの距離を Y半径 ($r_y$) とする。
*   `points[3]`: **開始角制御点 (Start Angle Control)** ➡️ $r_x, r_y$ と開始角（常に 0ラジアン）から、円周上の右端座標 `(xc + rx, yc)` に配置。
*   `points[4]`: **終了角制御点 (End Angle Control)** ➡️ $r_x, r_y$ と終了角（円なら $2\pi$＝右端、弧なら $\pi$＝左端 `(xc - rx, yc)`）から、円周上の対応する座標に配置。

##### 要件2: 2クリック作図とドラフト追従（updateDraftEnd）
1.  1回目のクリック（始点 $P_0$）を、ユーザーにとって最も直感的な**「楕円の中心点 $P_c$」**として固定する。
2.  2回目のクリック（またはドラフト中のマウス座標 $P_{current}$）への追従において、中心からマウスまでの絶対距離をそれぞれ $r_x = |x_{current} - xc|, r_y = |y_{current} - yc|$ として算出する。
3.  この $r_x, r_y$ を基に、`points[1]`（右端: $xc + r_x, yc$）および `points[2]`（上端: $xc, yc - r_y$）の座標を動的に再計算して `points` に反映する。
4.  この時、非表示・非編集である `points[3]`（開始角）と `points[4]`（終了角）についても、最新の $r_x, r_y$ に基づく円周上の位置へ自動的に同期再計算・再配置する（化石化の防止）。

##### 要件3: 描画（draw）と 3頂点表示ハンドル（左/下端ドラッグ時の反転連動不具合防止）
*   **楕円/弧の描画** :
    *   Canvas2D の `ctx.ellipse(xc, yc, rx, ry, rotation, startAngle, endAngle)` を用いる（`rotation = 0` 固定）。
    *   **円ツール** : `startAngle = 0`, `endAngle = 2 * Math.PI` で描画し、`closePath()` して stroke する。
    *   **弧ツール** : `startAngle = 0`, `endAngle = Math.PI` で描画し、`closePath()` は **呼び出さずに** stroke する。
*   **ハンドル表示（drawHandles）** :
    *   中心点 `points[0]`（平行移動用ハンドルとして、Line/Curveのmoveと同等に円形ハンドルで描画）
    *   右端 `points[1]`（X半径伸縮ハンドル、正方形）
    *   上端 `points[2]`（Y半径伸縮ハンドル、正方形）
    *   左端（$xc - r_x, yc$）および下端（$xc, yc + r_y$）の対称位置にも、操作性の観点から正方形のダミーハンドルを表示し、ドラッグ可能にする。
    *   開始角（`points[3]`）および終了角（`points[4]`）の角度制御ハンドルは、本フェイズでは**描画・衝突判定ともに対象外（非表示・操作不可）**とする。
*   **【超重要】左端/下端ハンドルドラッグ時の「反転連動」による不具合防止（正準正規化再計算）** :
    *   `InputTracker` はどのハンドルが掴まれたかをインデックスに解決して `setVertex` を呼び出すため、`setVertex` 内部は「どのハンドル名から叩かれたか」の文脈を判断できない。
    *   そのため、単に入力された `(x, y)` をそのまま points に代入（`this.points[1] = {x, y}`）すると、左端を掴んでドラッグした瞬間にハンドルが右側へ瞬間移動して吸着する致命的バグが発生する。
    *   これを防ぐため、`setVertex` 内部では常に**中心点との「絶対距離」を基準にパラメータを正規化・再計算**する設計とする：
        *   `setVertex(1, x, y)`（X半径の更新）：$r_x = |x - xc|$ を再計算し、`points[1]` を常に正準右端位置 `(xc + rx, yc)` に再配置する。
        *   `setVertex(2, x, y)`（Y半径の更新）：$r_y = |y - yc|$ を再計算し、`points[2]` を常に正準上端位置 `(xc, yc - ry)` に再配置する。
        *   同時に、更新後の $r_x, r_y$ を基に、ダミー角度点 `points[3]`, `points[4]` も対応する円周上の同期位置へ再配置・再計算して上書きする。
        *   `setVertex(0, x, y)`（中心点移動）：中心座標を `(x, y)` に更新し、半径 $r_x, r_y$ を維持したまま、すべての points を中心基準で平行移動・再計算して上書きする。

##### 要件4: 楕円方程式に基づく当たり判定（hitTest）および0除算ガード、角度フィルタ
*   **【不具合防止】0除算（NaN/Infinity化）の鉄壁ガード** :
    *   作図の開始瞬間や極端な伸縮により、$r_x$ または $r_y$ が極小（例：1px未満）の縮退状態になった際、楕円方程式の分母が0になり計算結果が `NaN` や `Infinity` に暴走し、キャンバス全体がフリーズ（どこをクリックしても常に当たり判定がtrueで誤爆する）する不具合を防ぐ。
    *   `hitTest` の冒頭において、**「$r_x < 1$ または $r_y < 1$ の場合は、即座に `false` を返す」**ガードロジックを必ず実装する。
*   **当たり判定ロジックと角度範囲フィルター** :
    *   入力点 $(x, y)$ に対し、中心 $(xc, yc)$ からの正規化された距離が、一定の許容誤差（tolerance）および `strokeWidth` を加味した範囲内にあるかを以下の楕円方程式で判定する：
        $$\frac{(x - xc)^2}{r_x^2} + \frac{(y - yc)^2}{r_y^2} \approx 1$$
    *   **半円お椀型（弧）の場合の角度ガード** :
        *   弧（開いている状態）の場合、描画されていない空隙部分（上半分、180度〜360度の領域）をクリックした際にも当たり判定が `true` に誤爆するのを防ぐ。
        *   入力点 $(x, y)$ と中心 $P_c(xc, yc)$ から角度 $\theta = \text{atan2}(y - yc, x - xc)$ を算出し、これが**現在の開始角から終了角の範囲内（半円なら $0 \sim \pi$ の範囲）に収まっている場合のみ `true` とする**フィルタリングロジックを実装する。

##### 要件5: 共通API契約（9メソッド）の完全履行
Line/Curve/Rect と全く同一のシグネチャを持つ以下の9メソッドを自律実装し、コア層（Model/Renderer/InputTracker）を1行も汚すことなくシステムに結合させる [62, 94]。
1. `draw(ctx, t)`
2. `drawHandles(ctx)`
3. `hitTest(x, y, tolerance)`
4. `hitTestHandle(x, y, tolerance)`
5. `setVertex(vertexIndex, x, y)`
6. `translate(dx, dy)` : X/Y/開始角/終了角を含む**長さ5の points 配列の全要素**に対し `dx, dy` を正しく相対加算する。
7. `drawHover(ctx)`
8. `updateDraftEnd(x, y)`
9. `getVertexIndexForHandle(handleName)` : `{ start: 0, right: 1, up: 2 }[handleName] ?? null` （左端・下端の対称ハンドルも、ドラッグ時はそれぞれ右端「1」、上端「2」を返して setVertex 側で正規化処理させる）

#### 4. アーキテクチャ設計

*   **新設するモジュール** :
    *   `js/shapes/Ellipse.js` (新規) : 楕円弧（5頂点構造）の幾何データ・当たり判定・描画処理を自律的に担う。
*   **改修するモジュール** :
    *   `js/core/ShapeFactory.js` (改修) : `circle` および `arc` ケースを、Line フォールバックから `new Ellipse(...)` へ切り替える [102]。
*   **本Phase固有の設計原則 (Constraints)** :
    *   **「5頂点構造の一貫性」** :
        *   閉じた楕円（円・楕円）であっても、内部データは必ず長さ5の `points` 配列で保持する。これにより、将来「弧」へ変換された際も、ゲームエンジン側は単に time `t` に沿って `points` を Lerp 補間するだけでモーフィングアニメーションをバグなく再生できる。
    *   **「コア層への図形分岐非混入」** :
        *   `VectorModel.js` や `InputTracker.js` 側には、`Ellipse` 特有の if/switch 分岐（円か弧かの型判定など）を1ピクセルも混入させてはならない。すべて共通の9メソッド契約経由でポリモーフィックに解決させる。

#### 6. 完了の目安
*   **ゴール型** :
    1.  キャンバス上でパレットの「円」および「弧」ボタンをクリックすると、それぞれ活性ハイライトされる [92]。
    2.  キャンバス上を「1クリック目（中心点） ➡️ ドラッグ移動（半径サイズプレビュー） ➡️ 2クリック目」のフローで、円、または開いた半円（弧）が滑らかに作成・描画できる。
    3.  確定した円/弧を選択すると、中心に円形ハンドル、上下左右（弧の場合は存在意義のある端点）に対称な正方形ハンドルが表示され、それをドラッグすることで楕円全体の平行移動、およびX半径・Y半径の個別伸縮変形が、ハンドルのワープバグを起こさず直感的に行える。
    4.  縮退（rx/ryが0）させたり、弧の空隙部分をクリックしたりしても、計算の暴走や不当な選択誤爆（コンソールエラー含む）が一切発生しない。
