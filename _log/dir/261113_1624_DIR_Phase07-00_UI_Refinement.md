## 1. 大ゴール
着色のPhaseまで使った結果、画面の見づらさと操作の不足（カーソル位置の座標が分からない、フロートウィンドウが作業領域を占める、狙った位置に置けない、複数選択へ1つずつ追加できない）が出た。本Phaseでは、画面の構成をツールバー（上端）・定規・ツールパレット・ステータスバー（下端）へ組み替え、表示の切り替え、選択と移動の修飾キー、整数px・グリッドへのスナップを入れる。カーソル位置の座標の表示とスナップは、次の精度のPhase（頂点を狙った位置に置く）の前段であり、精度のPhaseで足す数値入力の置き場所は本Phaseで作る画面の構成の上で決める。作業データ形式・書き出し形式は変えない（版はどちらも2のまま。OZ Engineとの往復は行わない）。
* **完了の目安**: ゴール型。4章の実装要件がテストプレイで確かめられ、発注者が「この画面と操作で精度のPhaseへ進める」と判断した状態。ステータスバーの表示項目のうち、カーソル位置の座標以外（選択中の図形の外枠の幅と高さ・グリッド1マスの大きさ）は「入れられたら入れる」（発注者）であり、完了の条件にしない。

## 2. やらないこと（Non-goals）
* 作業データ形式・書き出し形式の変更、版上げ、OZ Engineへの連絡票 → 行わない（表示の切り替え・スナップの設定・パレットの表示状態は作業データに入れない）
* 表示の切り替え（アウトライン・背景・グリッド・パレットの表示）とスナップの設定の保存 → 意図的に行わない（ページを開くたびに初期状態。発注者の決定）
* 整列・分布、頂点の選択、頂点の座標・図形の大きさの数値入力、矢印キーでの微調整 → 精度のPhase
* 回転・拡大縮小・反転 → 変形・整理のPhase
* 定規の表示・非表示の切り替え → 作らない（常に表示する）
* ガイド → 入れない（グリッドを常に表示できるため）
* 100%で表示するキー（`Ctrl`+`1`）→ 見送り（ブラウザのタブの切り替えとぶつかる）
* 重なり順の定番キー（`Ctrl`+`]`／`[`）→ 入れない（JIS配列では刻印と位置が合わず、macOSではタブの切り替えとぶつかる。今の`Home`・`PageUp`・`PageDown`・`End`のまま）
* `Ctrl`+`D`（複製）の割り当ての変更 → 行わない
* `Ctrl`を押しながらの範囲選択での解除（反転）→ 行わない（追加のみ。2026-11-13 発注者の決定）
* グループ化、図形の一覧・フォルダ・表示/非表示・編集ロック → 図形の一覧のPhase
* スマートガイド・右クリックメニュー・ヒストリーパネル → 未定（使い込んでから検討）
* SVGのアイコン、エディタで描いたアイコン → 未定（2026-11-13 発注者の決定：本Phaseは絵文字と記号で作る。エディタの機能がもう少し進んだら、エディタで作成する予定）
* 独自のカラーピッカー・透明度 → 未定（ブラウザ標準の`<input type="color">`のまま）
* `Shift`による正方形の作成・編集時の矩形ロック → 未定（`_doc/PROJECT_MILESTONE.md`「図形編集」節。本Phaseの`Shift`は移動方向の限定のみ）
* 端点への吸い付きの対象を広げること（曲線・矩形・円・弧の点、パスの途中の頂点）→ 未定（精度のPhase以降）。本Phaseで足すのは整数px・グリッドへの丸めだけ
* 既存の図形の座標の丸め、書き出し時の丸め → 意図的に行わない（2026-11-08の発注者の判断のまま）
* `InputTracker`の再分離（状態の所有者設計を含む）→ 精度のPhase（本Phaseでの足し方の制約は4章「本Phaseで決定済みの事項」）
* 確認用ページ（`sprite-check.html`）の変更 → 行わない

## 4. サブフェイズごとの実装要件

### 本Phaseで決定済みの事項（全サブフェイズ共通。2026-11-13 発注者の決定）
* **データを変えない**：作業データの版・書き出し形式の版はどちらも2のまま。本Phaseで足す状態（表示の切り替え・スナップのON/OFFと単位・パレットの表示状態）は、作業データに入れず、取り消し/やり直しの対象にせず、ブラウザにも保存しない。
* **画面の構成（本Phaseの完了時）**：画面の上端にツールバー（左側に操作のボタン、続けてオプションバー）、その下と画面の左端に定規、画面の下端にステータスバーを固定で置く。フロートウィンドウはツールパレットとキャンバスパレットの2つ（`?dev`の確認用ウィンドウは今のまま）。今のコントロールパネル・図形選択パレット・プロパティパネルの3つのウィンドウはなくす（中身はツールバー・ツールパレット・ステータスバーへ移す）。キャンバスはツールバー・定規・ステータスバーを除いた領域に収める。
* **ボタン**：絵文字と記号のアイコンで表し、文字のラベルは付けない。説明（ショートカットを含む）は`title`で見せる。後でアイコンを差し替える予定があるため、アイコンの記述はボタンごとに1か所にまとめる。
* **`⌘`の扱い**：macOSの`⌘`は、今のショートカットと同じく`Ctrl`と同じに扱う（クリック・ドラッグの修飾キーを含む）。以下の「`Ctrl`」はすべて`⌘`を含む。
* **本Phaseで足すキー**：`Z`（アウトライン表示）・`X`（背景の白/黒）・`C`（グリッドの表示）・`Tab`（パレットを隠す/出す）・`D`（線を黒・塗りを白に戻す）・`I`（スポイト）・`Ctrl`+`I`（選択の反転）・`Ctrl`+`Shift`+`V`（同じ位置に貼り付け）。既存のキーの割り当ては変えない（`Ctrl`+`Z`・`Ctrl`+`X`・`Ctrl`+`C`は取り消し・切り取り・コピーのまま）。
* **修飾キー（マウス操作）**：`Ctrl`+クリック＝選択へ1つずつ追加・解除。`Ctrl`+範囲選択＝選択へ追加。`Alt`+ドラッグ＝複製して動かす。`Shift`+ドラッグ＝縦・横・45°に限定して動かす。`Ctrl`を押しながらのドラッグ＝スナップを一時的に無効にする。
* **スナップ**：単位は「1px」と「グリッド（10pxの固定値）」の2つから選ぶ。10pxは表示倍率で変わらない（画面のグリッドの細線は表示倍率80%以上で10px間隔のため、その範囲では細線と一致する）。ページを開いたときはON・1px。図形・頂点を動かすときは移動量を丸め、点を打つときは座標を丸める。端点への吸い付き（パスの基礎のPhase）を優先する。
* **`InputTracker`への足し方**：`js/core/InputTracker.js`は約1305行で、再分離は精度のPhaseで行う（`_doc/COWORK_STATUS.md` 2章A）。本Phaseで足す判定・計算の規則（選択集合の追加・解除・反転、移動方向の限定、座標・移動量の丸め等）は、`core/PointHitRules.js`と同じく状態を持たない関数として切り出して自動テスト（`node --test`）で確かめ、`InputTracker`には呼び出しと配線だけを足す。状態に依存しない操作（選択の反転・同じ位置に貼り付け・`D`・表示の切り替え）は`InputTracker`へ入れない（同2章C「`InputTracker`の肥大化防止」）。この制約の中で作れないと現場設計AIが判断した場合は、実装に入る前にDIR変更提案として親セッションへ返す。
* **実際のブラウザで確かめるもの**：実装AIの確認は合成イベントのみのため、修飾キー・`Tab`・`Alt`・macOSの`⌘`に関わる要件は、発注者のテストプレイ（実際のブラウザ）で確かめる。各サブフェイズのREQで確認項目を挙げること。

### Phase 07-01: 画面の骨組み
* **目的**: 画面をツールバー・ステータスバー・ツールパレット・キャンバスの領域に組み替え、コントロールパネルと図形選択パレットのウィンドウをなくす（以後のサブフェイズの置き場所を先に作る）。
* **実装要件**:
  * 画面の上端にツールバーが固定で表示され、キャンバスパレットの表示・非表示、取り消し、やり直し、削除、結合のボタンが並ぶ。各ボタンの働き・押せる/押せないの表示は今のコントロールパネルのボタンと同じ。
  * 画面の下端にステータスバーが固定で表示され、開いているキャンバスの名前（保存の問題があるときの`⚠`を含む）・表示倍率・表示のリセットのボタンがある。表示倍率はズームに追従する。
  * ツールパレット（フロートウィンドウ。既定の位置は画面の左端、縦並び）に、選択・キャンバス移動・直線・曲線・弧・矩形・円のボタンが並ぶ。図形のボタンを1回押すと、その図形を描く状態になる（今の「図形作成」を押してから図形を選ぶ2回の操作が1回になる）。今どのツールか（選択・キャンバス移動・どの図形か）が、ボタンの押し込みの表示で分かる。
  * ツールパレットは、選択・キャンバス移動の状態でも半透明にならず、ボタンを押せ、ヘッダーをドラッグして動かせる。
  * コントロールパネルと図形選択パレットのウィンドウがなくなっている。
  * キャンバスはツールバーとステータスバーを除いた領域に表示され、ツールバー・ステータスバーの下に図形が隠れない。ブラウザのウィンドウの大きさを変えても追従する。キャンバス上のクリック・ドラッグ・ホイールでのズームの位置が、カーソルの位置とずれない。
  * ツールバー・ステータスバー・ツールパレットのボタンは絵文字・記号のアイコンで表示され、マウスを載せると説明とショートカットが表示される。
  * 既存のショートカットは従来どおり働く（`V`・`H`・`Delete`・`J`・`Ctrl`+`Z`等）。数字キー（`1`〜`5`）と`P`は、押した結果がツールパレットの押し込みの表示と食い違わない（動きはREQ作成時に決める。下記メモ）。
  * プロパティパネルのウィンドウは今のまま残り、従来どおり使える（移すのはPhase 07-02）。
* **持ち越し事項**:
  * （`_doc/COWORK_STATUS.md` 2章B【Phase02-01/02】）選択・キャンバス移動モード中は図形パレットが`.disabled`でヘッダーもドラッグできず半透明になる件は、ツールパレットへの統合で解消する。完了時に同項目を2章から外す。
  * （同2章C「コントロールパネルの高さ」）コントロールパネルがなくなるため解消する。完了時に同項目を2章から外す。
  * （同2章C「初期表示の暗黙の結合」）`index.html`の初期の`.disabled`/`.active`と`InputTracker`の初期モード、ボタンidの命名規則（`palette-${type}`を`PaletteController`が照合する）を変える場合は、`index.html`と`main.js`を揃えること。
  * （同2章C「キー割り当ての手動同期」）ボタンの`title`と`SHORTCUT_BINDINGS`は手動で同期している。ボタンを作り直すときに`title`のキーの表記を落とさないこと。
  * （同2章C「Canvas・ウィンドウの動的生成を入れるとき」）`WindowManager`は起動時にDOMにある`.float-window`だけを検知する。ツールパレットは`index.html`に静的に置くか、検知の仕組みを足すかを決めること。
  * （同2章B【Phase02-04・低優先】）キーボードの拡大・縮小はキャンバス全体の中心基準。キャンバスの領域が変わっても中心がずれないことを確かめること。
  * 開発資料：`PROJECT_ARCHITECTURE.md`1章「存在しないもの」のツールバー、3章1.「読み込み完了前の操作」のフロートウィンドウ上のボタンの記述、`_doc/arch/01_index_html.md`（コントロールパネル・図形選択パレットの記述）を、本サブフェイズの完了時に実態へ改めること。
* **メモ**: Phase 07-02でツールバーにオプションバーを、Phase 07-03でツールバーにパレットの表示・非表示のボタンと、定規・ステータスバーの残りの項目を足す。ツールバー・ステータスバーは後から項目を足せる作りにすること。
  REQ作成時に決める論点：
  * 操作モード（選択・図形作成・キャンバス移動）と図形種別の持ち方：画面のボタンを統合するだけにするか、内部の状態も変えるか。キー`P`（図形作成モードへの切り替え）と数字キーの扱い。（261113_1827 訂正：初版は「今の数字キーは図形種別だけを変え、操作モードは変えない」としていたが誤り。数字キーは以前から、図形作成モード以外なら図形作成モードへ切り替えてから図形種別を変える。結果は5章の変更履歴）
  * キャンバスの領域の取り方（今はCSSで`100vw`/`100vh`。`resize`の経路と描画領域の大きさの求め方）。マウスの座標はキャンバスの`getBoundingClientRect`を基準に計算しているため、キャンバスの位置がずれても座標の計算は変わらない見込み。読み込み中の覆い要素`#canvas-loading-cover`が覆う範囲。
  * フロートウィンドウの既定の位置（ツールパレット・キャンバスパレット・プロパティパネル・`?dev`の確認用ウィンドウ）と、ツールバー・ステータスバーに重なる位置へ動かせるか。
  * ブラウザのウィンドウの幅が狭く、ツールバー・ステータスバーの項目が1行に収まらないときの扱い。
  * 絵文字・記号に該当するものが無い機能（結合・キャンバスパレットの表示等）のアイコンに何を使うか。

### Phase 07-02: オプションバー
* **目的**: プロパティパネルの中身（線・塗り・線の太さ・重なり順）をツールバーのオプションバーへ移し、プロパティパネルのウィンドウをなくす。
* **実装要件**:
  * ツールバーの操作のボタンの続きに、線のON/OFFのボタンと線の色の欄、塗りのON/OFFのボタンと塗りの色の欄、線の太さの欄、重なり順の4つのボタン（最前面へ・前へ・後ろへ・最背面へ）が並ぶ。
  * 線・塗りのON/OFFはチェックボックスではなく、アイコンボタンの通常（OFF）・押し込み（ON）で表される。複数の図形を選んでいてON/OFFがそろっていないときは、ONともOFFとも違う表示になる。
  * 働きは今のプロパティパネルと同じ：選択中の図形へ反映される（複数選択は一括）／図形を選んでいないときは新しく描く図形のスタイルを表示・変更する／塗れない形だけを選んでいるときは塗りの欄が無効の表示になる／色・太さがそろっていないときは混在と分かる／線の太さは1〜100の整数だけを受け付ける／変更はUndo1回で戻りRedo1回でやり直せる／重なり順のボタンは動かせるときだけ押せる。
  * プロパティパネルのウィンドウがなくなっている。
  * オプションバーの入力欄・ボタンを操作している間に、キーボードショートカットが誤って働かない（太さの欄に数字を打っても図形種別が切り替わらない。色の欄・ON/OFFのボタンにフォーカスがある状態の`Space`でキャンバスがパンしない）。
* **持ち越し事項**:
  * （`_doc/COWORK_STATUS.md` 2章C「入力欄を追加するとき」）`isTextInputElement`・`isSpaceOperatedInputElement`は`input`の`type`別に判定している（`checkbox`・`color`は対応済み）。チェックボックスをボタンに変えると、フォーカス中の`Space`・`Enter`の扱いが変わる。使う入力部品について確認項目を洗い出すこと（確認項目はRES `261031_2121` 5章）。
  * （同2章B【Phase02-04】）ボタンを押した直後は、`disabled`になった後もフォーカスがボタンに残る。押した直後の`Space`・`Enter`の動きを確かめること。
  * （同2章A・発注者案）精度のPhaseで、頂点の座標・図形の大きさの数値の欄を足す。置き場所は精度のPhaseのDIRで決めるため、本サブフェイズでは作らない。今の「段ごとにUI部品と配線を分ける」作り（`PROJECT_ARCHITECTURE.md`3章13.「2段構成」）に当たる分け方を、オプションバーでも保つこと。
  * （Phase 07-01由来。`_doc/COWORK_STATUS.md` 2章C「ツールバー・ステータスバー」）ツールバーは高さ1行の固定で、幅が狭いと右側の項目が画面の外に切れる（折り返し・横スクロールなし。発注者の決定）。オプションバーで項目が増えるため、1280px幅で全項目が収まるかと、切れる順を確かめること。項目のまとまりは`<div class="toolbar-group">`を足す形（既存のまとまりは変えない）。
  * （Phase 07-01由来。同上）存在しない`.disabled`クラスに触れるコメントが3か所に残っている（`index.html`の`#window-property-panel`のCSSコメント、`js/palette/PropertyShapeSection.js`・`js/palette/CanvasPalette.js`のJSDoc）。プロパティパネルをなくすときに合わせて整理すること。
  * 開発資料：`PROJECT_ARCHITECTURE.md`3章13.（「プロパティ」ウィンドウ・2段構成・精度のPhaseの「頂点」の段）と14.（「重なり順」の段）、1章「存在しないもの」のプロパティパネルの「頂点」の段、`_doc/arch/01_index_html.md`・`_doc/arch/13_palette.md`の該当の記述を、本サブフェイズの完了時に実態へ改めること。
* **メモ**: 反映の範囲・履歴の単位・色の欄の確定の扱い・太さの受理などの手順と規則（`edit/ShapeStyleEditor`・`edit/StylePanelRules`・`edit/ShapeOrderEditor`・`edit/ShapeOrderRules`）は変えず、画面の部品と配線を置き換えるのが基本の方針。
  REQ作成時に決める論点：
  * 今のパネルにある補助の表示（図形を選んでいるか・新しく描く図形のスタイルかの表示、色の欄の横の「混在」「表示できない色」、太さの「混在」）を、横1行のオプションバーでどう見せるか。

  * 今の入力欄の規則（`checkbox`にフォーカスがあるとき`Ctrl`なしのショートカットを止める）を、ボタンに変えた後も残すか。

### Phase 07-03: 表示

### Phase 07-05: スナップ
* **目的**: 点を打つとき・図形や頂点を動かすときに、座標・移動量を整数pxまたはグリッド（10px）へ丸め、狙った位置に置けるようにする。
* **実装要件**:
  * ステータスバーの右側に、スナップのON/OFFのボタンと単位（1px・グリッド10px）の切り替えがあり、今の状態が分かる。ページを開いたときはON・1px。
  * スナップがONのとき、図形を描くときに打つ点の座標が単位の倍数になる（ステータスバーの座標の表示、または出力した作業ファイルの値で確かめられる）。
  * スナップがONのとき、図形の移動・頂点（ハンドル）の移動は、移動量が単位の倍数になる。小数の座標を持つ既存の図形は、小数の部分を保ったまま動く。
  * グリッドの単位は10pxの固定で、表示倍率を変えても変わらない。
  * `Ctrl`を押している間のドラッグ・点を打つ操作では、スナップが働かない（離すと元に戻る。ON/OFFのボタンの状態は変わらない）。
  * 直線を描くとき・線の端点のハンドルをドラッグするときに端点へ吸い付いた場合は、吸い付いた端点の座標がそのまま使われ（丸められない）、従来どおり描き足し・結合・閉じるが行われる。
  * スナップがOFFのときは、従来と同じ座標になる。
  * 既存の図形の座標は、ファイルを開いただけ・スナップを切り替えただけでは変わらない。出力（作業ファイル・エンジン用）でも丸められない。
  * スナップの設定は取り消し/やり直しの対象にならず、ページを開き直すと初期状態（ON・1px）に戻る。
