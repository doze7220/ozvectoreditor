# 設計指針書 DIR: Phase 05 : パスの基礎
* ルール: `./PROJECT_CONSTITUTION.md`
* 開発資料: `./PROJECT_ARCHITECTURE.md`

## 1. 大ゴール
現在のエディタには、直線どうしをつないで1つの図形にする手段がなく、閉じた多角形を作れない。本Phaseでは、頂点の並びと「閉じているか」を持つパスの図形を新しく足し、直線・パスの結合と、端点へのスナップによる描き足しで、開いた折れ線と閉じた多角形を作れるようにする。パスを着色より先に作るのは、発注者が今いちばん欲しい機能が線の結合であり、また着色のPhaseで矩形・円・閉じたパスの塗りを1回で作れるようにするためである（並び順の理由は`_doc/PROJECT_MILESTONE.md`「Phase方針メモ」）。
* **完了の目安**: ゴール型。直線を描いてつなぎ、閉じた多角形を作り、作業データファイルへの保存・読み込みとスプライトJSの書き出しまで通せると発注者が判断した状態。

## 2. やらないこと（Non-goals）
* 線を閉じる操作の自動化（始点と終点が近づいたら自動で閉じる等）→ 意図的に行わない（開いたままの線が欲しい場合があるため。閉じるのは「結合」の操作か、描いているパスの始点を狙って描き終えたときだけ）
* 既存の図形（直線・曲線・矩形・円・弧）のパスへの統合、既存の図形の置き換え → 意図的に行わない（2026-11-09 発注者の決定。パスは新しい図形クラスとして足し、結合・描き足しの結果だけがパスになる）
* 矩形などを「パスに変換」する操作 → パスの編集のPhaseで再検討（2026-11-09 発注者の決定）
* 曲線（`Curve`）の結合、パスの曲線の区間、区間の直線/曲線の切り替え → パスの編集のPhase
* 頂点の選択、頂点の追加・削除、パスの分割、閉じたパスを開く操作 → 精度・パスの編集のPhase
* 矩形・円・弧・曲線の点へのスナップ → 精度のPhase（本Phaseの端点スナップは、結合できる線＝直線と開いたパスの端点だけが対象。2026-11-09 発注者の決定）
* 整数px・グリッドへのスナップ、スナップの一時無効の手段 → 精度のPhase
* パスを描く専用のツール（クリックで頂点を順に置いていく描画モード）→ 未定（本Phaseのパスは、結合と、直線の描き足しで作る）
* 3本以上を一度に選んだときの結合 → 意図的に行わない（つなぐ順番があいまいになるため。2本ずつ結合するか、描き足しを使う）
* パスの塗り → 着色のPhase
* 作業データの版（`version`）の版上げ → 意図的に行わない（2026-11-09 発注者の決定。新しい図形の種類を足すだけで移行関数が要らないため版1のまま。古いエディタで開くとパスは未知の種類として読み飛ばされ、「一部読めない」の通知が出る。これを許容する）
* 書き出し形式の版（`formatVersion`）の版上げ → 行わない（直線だけのパスは版1の`polyline`で表せるため。Phase 05-02で確定）
* `InputTracker`の再分離（状態の所有者設計を含む）→ 精度のPhase（頂点の選択で押下時の分岐へ手を入れるときにまとめて行う）
* `hitTestHandle`の優先順位の見直し、`Curve`の制御点の追加・削除とmoveハンドル → パスの編集のPhase（`_doc/COWORK_STATUS.md` 2章Aに残す）

## 4. サブフェイズごとの実装要件

### Phase 05-01: 図形クラスの共通の関数の切り出し
* **目的**: パスの図形クラスを足す前に、4つの図形クラスに重複している幾何の関数と図形データの検証を、`shapes/`の下の共通モジュールへ切り出す（振る舞いは変えない）。
* **実装要件**:
  * 切り出しの前に、今の4クラス（`Line`・`Curve`・`Rect`・`Ellipse`）の当たり判定（`hitTest`・`intersectsRect`）の自動テストが追加され、`node --test`で通る。
  * 線分と矩形の交差判定（現在4ファイルに同一のコードがある`#segmentIntersectsRect`）、点と線分の距離など、図形クラスの間で重複している幾何の関数が、`shapes/`の下の共通モジュールにまとまっている。
  * 図形データの共通項目（id・色・線の太さ・頂点の配列）の検証（現在4ファイルにある`#validateData`）が共通化されている。図形ごとの違い（エラー文のクラス名、受理する種別、頂点数）は各図形クラス側から渡せる。
  * 切り出しの後も、上の当たり判定のテストと既存の自動テスト（作業データの往復・書き出し等）がすべて通る。
  * テストプレイで、5種の図形（直線・曲線・弧・矩形・円）の作成・クリック選択・範囲選択・移動・ハンドル操作・保存と読み込み・書き出しが、これまでと同じに動く。
* **持ち越し事項**:
  * （`_doc/COWORK_STATUS.md` 2章A「図形クラスの重複」）`#segmentIntersectsRect`の4ファイル重複と`#validateData`の4ファイル重複。本サブフェイズで解消し、完了時に同項目を2章から外す。
* **メモ**: 共通化は継承（共通の基底クラス）ではなく、共通の関数の切り出しで行う（2026-11-09 発注者の決定）。各図形クラスが自分でメソッドを実装し、共通の基底クラスを持たない設計は変えない（`_doc/arch/12_shapes.md`では13メソッド。`_doc/PROJECT_MILESTONE.md`の方針メモには「12メソッド」とあるが、開発資料の記載を正とする）。`Curve`の曲線の関数（2次ベジェの点の計算・分割による近似等）も共通モジュールへ移すかはREQで決める（パスの編集のPhaseでパスの曲線の区間に使い回す候補）。`Ellipse`の近似（平均半径・100分割）は振る舞いを変えないこと。

### Phase 05-02: パスの図形
* **目的**: 頂点の並びと「閉じているか」を持つパスの図形クラスを足し、既存の図形と同じように表示・選択・移動・保存・書き出しができるようにする。
* **実装要件**:
  * パスの図形データを含む作業データファイルを開くと、パスが表示される。開いたパスは始点から終点まで直線でつながり、閉じたパスは終点から始点へも直線でつながって描かれる。
  * パスは、既存の図形と同じく、クリック選択・範囲選択・本体のドラッグによる移動・削除・複製/コピー＆ペースト・Undo/Redoの対象になる。
  * パスの各頂点のハンドルをドラッグすると、その頂点が動く。
  * パスを含むキャンバスを作業データファイルへ保存して開き直すと、頂点の並び・閉じているか・色・線の太さが元どおりに戻る（自動テストの往復テストにパスが含まれる）。
  * パスを含むキャンバスをスプライトJSへ書き出すと、エディタと同じ見た目で描かれ（確認用ページ`sprite-check.html`で確認できる）、外枠にパスが含まれる。書き出したJSをエディタで開き直すとパスが戻る。
  * パスの図形データは、区間ごとに種類を持てる形になっている（本Phaseの区間は直線のみ。曲線の区間はパスの編集のPhaseで足す）。
* **持ち越し事項**:
  * （Phase 05-01より）図形データの共通項目の検証`validateShapeData`（`js/shapes/ShapeDataValidation.js`）は、頂点数を固定の数でしか受け取れない。パスの図形（頂点数が固定でない）を足すときに引数を拡張する（RES `261109_2115` 5章。`_doc/COWORK_STATUS.md` 2章A）。パスの当たり判定には`js/shapes/ShapeGeometry.js`の`distanceToSegment`・`segmentIntersectsRect`を使い、図形クラスへ複製しない（`_doc/arch/12_shapes.md`「共通モジュール」）。
* **メモ**: 本サブフェイズでは、パスを画面上で新しく作る操作はない（作る操作はPhase 05-03・05-04）。テストプレイ用のパスは、手で書いた作業データファイル、または`?dev`の入力欄等で用意する（方法はREQで決める）。
  REQ作成時に決める論点・確かめる事項：
  * パスの図形データの形（`type`の値、閉じているかのキー、区間の種類の持ち方）。図形データの共通の形`{ type, id, points, strokeColor, strokeWidth }`に足すキーとして決め、開発資料2章「図形データ」に記載する。
  * 頂点数の下限（2点のパスを許すか）。結合の結果として頂点2つのパスが生じるか（直線どうしの結合は常に3頂点以上になるか）とあわせて決める。閉じたパスの頂点数の下限も決める。
  * 書き出し：直線だけのパスを書き出し形式の版1の`polyline`（`closed`あり、頂点数の制限なし）で出せることを確かめ、`formatVersion`を上げないことを確定する。上げる必要が出た場合は、開発資料2章のエンジンとの約束(c)に従い連絡票が要るため、DIR変更提案として親セッションへ返す。
  * 書き出したJSの描画処理（`CodeExporter`の`DRAW_SOURCE`）と図形の`draw`を揃え、`test/io/CodeExporter.test.js`の一致テストを通す（`_doc/COWORK_STATUS.md` 2章C「スプライトの書き出し」の注意）。
  * `ShapeFactory`への登録と、図形パレットにパスのボタンを置くか（本Phaseでは「パスを描くツール」は作らないため、置かない想定）。

### Phase 05-03: 結合の操作
* **目的**: 選んでいる線（直線・パス）を結合して、閉じたパス、または1本の開いたパスにできるようにする。
* **実装要件**:
  * 開いたパス1本（頂点3つ以上）を選んで結合すると、終点から始点への区間が足されて閉じたパスになる。頂点2つの線（直線、頂点2つのパス）1本を選んで結合しても何も起きない。
  * 線（直線・開いたパス）を2本選んで結合すると、いちばん近い端点どうしがつながり、1本の開いたパスになる。元の2本は消える。
    * つなぐ端点どうしが重なっていれば、1つの頂点にまとまる。
    * 離れていれば、その間に直線の区間が足されてつながる（足されるのはパスの中の区間であり、別の直線の図形ではない）。
  * 結合の対象にならない選択（3本以上、曲線・矩形・円・弧・閉じたパスを含む、何も選んでいない）で結合しても、アプリが停止せず、図形は変わらない。
  * 結合は、元の図形の削除と新しいパスの追加を含めてUndo1回で元に戻り、Redo1回でやり直せる。
  * 結合後のパスは、保存・読み込み・書き出しでPhase 05-02と同じに扱える。
* **持ち越し事項**:
  * （Phase 05-02より）パスは`js/shapes/Path.js`（図形種別`'path'`）。図形データは`{ type: 'path', id, points, closed, segments: [{ kind: 'line' }, ...], strokeColor, strokeWidth }`で、頂点数の下限は開いたパス2点・閉じたパス3点。区間の要素数は開いたパス`n - 1`・閉じたパス`n`（`n`＝頂点数）の不変条件がある。結合で頂点を足す・閉じる処理は、新しい`Path`をコンストラクタで作る（区間を作り直す）か、`points`・`closed`・`segments`をそろえて更新すること。コンストラクタは引数を検証しない（RES `261110_1037` 5章）。
  * （Phase 05-02より）パスは`ShapeFactory`に「読めるが作れない種別」として登録されている（`create`は`null`。図形パレット・数字キーには出ない）。結合の結果のパスは`ShapeFactory.create`ではなく`Path`のコンストラクタ等で作る。
* **メモ**: REQ作成時に決める論点：
  * 結合の操作の置き場所（ボタン・ショートカットのキー割り当て）。ボタンを足す場合、コントロールパネルの高さの余裕（`_doc/COWORK_STATUS.md` 2章C「コントロールパネルの高さ」）を確かめる。キー割り当てを足す場合、ボタンの`title`と`SHORTCUT_BINDINGS`の手動同期（同2章C）に注意する。
  * 「端点が重なっている」とみなす距離（座標の完全一致か、許容誤差を持つか）。
  * 結合後のパスの色・線の太さ（2本の色・太さが違う場合にどちらを採るか）、id、重なり順の位置。
  * 2本の結合で、どちらの線の向き（始点・終点）を保つか。
  * 結合の処理を置く場所。状態に依存しない操作は`InputTracker`へ入れず、`main.js`の注入コールバック側か別のクラスへ置く（`_doc/COWORK_STATUS.md` 2章C「`InputTracker`の肥大化防止」）。

### Phase 05-04: 端点へのスナップと描き足し
* **目的**: 直線を描くときに、直線・開いたパスの端点へ吸い付き、描き足し・結合・閉じる操作を描く流れの中で行えるようにする。
* **実装要件**:
  * 直線を描くとき、描き始める点・描き終える点が、直線または開いたパスの端点の近くにあると、その端点に吸い付く。吸い付いていることが画面上で分かる。曲線・矩形・円・弧・閉じたパスの点には吸い付かない。
  * 直線・開いたパスの端点から描き始めると、その線への描き足しになる（別の図形にならない）。直線から描き足した場合、その直線は開いたパスになる。
  * 他の直線・開いたパスの端点で描き終えると、その線と結合した1本の開いたパスになる。
  * 描き足している線自身の始点で描き終えると、閉じたパスになる（始点を狙って描き終えるのは閉じる意思の明示であり、「自動では閉じない」と矛盾しない）。
  * 端点から離れた位置で描き始め・描き終えた直線は、これまでどおり独立した直線の図形になる。
  * 描き足し・結合・閉じる操作は、既存の図形の書き換えを含めてUndo1回で元に戻り、Redo1回でやり直せる。
* **持ち越し事項**:
  * （Phase 05-02より）Phase 05-03の持ち越し事項（パスの区間の要素数の不変条件、パスは`ShapeFactory.create`では作れないこと）と同じ注意が、描き足し・閉じる処理にも当てはまる。
* **メモ**: 吸い付きは結合できる線の端点だけを対象にする（吸い付く＝描き足し・結合になる、の1対1。2026-11-09 発注者の決定）。結合の結果の扱い（端点の重なりの判定、色・太さ、向き、重なり順）はPhase 05-03で決めた規則に揃える。
  REQ作成時に決める論点：
  * ハンドルの移動（既存の直線・パスの端点のハンドルをドラッグしたとき）でも端点へ吸い付くか。吸い付く場合、離したときに結合するか。
  * 吸い付く距離（画面上のpxで一定にするか）と、吸い付き候補が複数あるときの選び方。
  * 吸い付いている表示の形。
  * 描き足しで、端点から描き始めた後に、描き終える前に取り消した場合の扱い。
  * 吸い付きの判定を置く場所。`InputTracker`（約1140行）へ足す量を抑える（`_doc/COWORK_STATUS.md` 2章A。再分離は精度のPhase）。
