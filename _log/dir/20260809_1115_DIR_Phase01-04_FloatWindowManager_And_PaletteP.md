### 設計指針書 DIR: Phase 01-04 : フロートウィンドウシステムの構築と図形パレットの統合
*  ルール: ./PROJECT_CONSTITUTION.md
*  開発資料: ./PROJECT_ARCHITECTURE.md

--------------------------------------------------------------------------------

#### 1. 設計目的
本Phaseは、将来的にエディタ内で確実に乱立する各種フロートウィンドウ（プロパティ、レイヤー、カラーサークル等）の「衝突バグ（z-index崩壊、イベント透過、ドラッグ移動ロジックの重複）」を構造的に100%防ぐため、**軽量かつ頑強な「フロートウィンドウシステム（WindowManager）」の共通基盤を先行して構築する** [105]。
その最初にして完璧な実証例として、「モード選択（コントロールパネル）」と「5大図形選択パレット」をそれぞれ独立したフロートウィンドウとしてこのシステムに登録し、共通規格に則って美しく連携・開通させる。

--------------------------------------------------------------------------------

#### 2. スコープ境界
##### やること
1. **`core/WindowManager.js` の新設**:
   * 画面上のすべての `.float-window` クラスを持つ要素を検出し、以下の共通機能を一元的に注入・統治する。
   * **ドラッグ移動（Drag & Drop）**: 各ウィンドウの `.window-header` を掴んで、キャンバス上で自由にドラッグ移動可能にする。
   * **アクティブ最前面化（Focus Bring-to-Front）**: ウィンドウ上の任意の場所をクリックした瞬間、そのウィンドウの `z-index` を自動的に最大値へ引き上げ、常に最前面に表示させる。
   * **イベント透過防止の一括適用**: ウィンドウ内での操作（mousedown/click/mousemove/mouseup）が背後のCanvas（InputTracker）へ突き抜けるのを、共通処理として一元的に `stopPropagation()` して防御する。
2. **既存コントロールパネル（右側パネル）の「フロートウィンドウ化」**:
   * `#control-panel` を `id="window-control-panel"`、`class="float-window"` の共通マークアップへ完全に移行し、WindowManagerの管理下に置く。
3. **新規「図形選択パレットウィンドウ」の追加（5大図形パイプラインの開通）**:
   * `id="window-shape-palette"`、`class="float-window"` を新設。
   * 直線、曲線、弧、矩形、円の5ボタンを並べ、選択（SELECT）モード中はウィンドウ全体を不活性（不透明度を下げてクリック不可）、描画（DRAW）モード中のみ活性化させる状態配線を行う。
4. **`ShapeFactory` への5大図形スタブの配備**:
   * `line, curve, arc, rect, circle` の分岐を用意。未実装の4種は暫定的に Line インスタンスを生成して返す「安全なスタブフォールバック」を実装し、エラーなしでパイプラインを通す。

##### やらないこと（Non-goals）
* **ウィンドウの最小化（折りたたみ）/ 閉じるボタンの機能化**:
  HTML/CSS上にボタン構造の用意（`×` ボタンなど）は行うが、状態が複雑化するのを避けるため、実際のトグル機能は将来のフェイズへ送る。
* **ウィンドウ位置の永続化（LocalStorage等）**:
  ブラウザのリロードで位置がリセットされてもデバッグ上支障がないため、今回は実装しない。
* **図形クラス（Curve.js等）の新規作成、および幾何計算**:
  本Phaseは「ウィンドウ基盤とパイプライン」に特化するため、新規図形クラスの作成は絶対に禁止とし、既存の Line.js へのポリモーフィックなフォールバックで代用する。

#### 3. 実装要件

##### 要件1: 共通マークアップ規格（フロートウィンドウDOM構造）
今後増えるすべてのウィンドウは、以下の構造に 100% 準拠する。
```html
<div id="window-[機能名]" class="float-window" style="top: [初期値]px; right: [初期値]px; z-index: 10;">
  <div class="window-header">
    <span class="window-title">[タイトル名]</span>
    <button class="window-close-btn">×</button>
  </div>
  <div class="window-body">
    <!-- 各ウィンドウ固有のコンテンツ -->
  </div>
</div>
```

##### 要件2: `core/WindowManager.js` による中央統治
* **初期化と自動検知**:
  * `main.js` からインスタンス化される際、`document.querySelectorAll('.float-window')` によって画面上のすべての対象ウィンドウを動的に検知・掌握する。
* **z-indexの動的管理（最前面化）**:
  * 内部でアクティブな z-index の基準カウンター（初期値: `10`）を保持する。
  * いずれかの `.float-window` で `mousedown`（または `click`）が発生した瞬間、そのウィンドウ要素の `style.zIndex` を `++currentMaxZIndex` に書き換える。
* **イベント透過の一括防止**:
  * 登録されたすべての `.float-window` に対し、`mousedown`, `click`, `mousemove`, `mouseup` に `e.stopPropagation()` を一元的に自動でバインドする。個別のウィンドウごとに stopPropagation リスナーを個別に書くことを一切禁止する。
* **ドラッグ移動ロジック（ヘルパー）の一元注入**:
  * `.window-header` がドラッグされた際、親要素の `.float-window` がマウス移動量（dx, dy）に同期してスムーズに追従移動するドラッグ＆ドロップ処理を自律的にバインドする。
  * ドラッグ中にマウスがウィンドウ外（またはブラウザ外）に外れた場合でも、追従が破壊されたり固まったりしないよう、`window`（または `document`）の `mousemove` / `mouseup` イベントを利用した安全なステートマシン（ドラッグドラフト）として実装すること。

##### 要件3: 二大ウィンドウの配線と活性化ガバナンス
* **コントロールパネル（モード選択）**:
  * モードが SELECT のときは、図形選択パレット（`#window-shape-palette`）に不透明度を下げるCSS（`.disabled` 等）を付与し、内部のボタンを非活性化する。
  * モードが DRAW のときは、パレットの不透明度を戻し、ボタンを活性化する。
* **図形選択パレット**:
  * ボタンクリック時、`inputTracker.setTool(type)` を呼び出してツールを切り替える。
  * この際、まだ未実装の type （`curve, arc, rect, circle`）であってもエラーにならず、`ShapeFactory` のスタブ分岐によって安全に作図が機能することを確認する。

#### 4. アーキテクチャ設計

* **新設するモジュール**:
  * `core/WindowManager.js` (新規) : 画面上の全フロートウィンドウのドラッグ、最前面化、イベント遮断を一元的に管理・統治するクラス。
* **改修するモジュール**:
  * `core/ShapeFactory.js` (改修) : 5大図形タイプを受け入れ可能にするスタブ分岐の拡張。
  * `main.js` (改修) : `WindowManager` のインスタンス化と、コントロールパネル ＆ パレットの動的な活性・非活性制御の連携。
* **本Phase固有の設計原則**:
  * **「ウィンドウコード内でのイベント遮断・ドラッグ移動記述の禁止」**:
    * 個々のウィンドウ用JS、あるいは `main.js` において、個別ウィンドウに対して `e.stopPropagation()` やドラッグ移動のマウスイベント処理をベタ書きすることを一切禁止する。
    * これらは必ず `WindowManager.js` が、HTMLのクラス指定（`.float-window`, `.window-header`）をトリガーにして一元的に、自動注入（デリゲーション）する設計でなければならない。これにより、将来的な「衝突」を100%排除する。

#### 5. 関連フォルダと物理ファイル構成
* `index.html` : 既存パネルのマークアップを規格に適合させ、新規パレットを追加。
* `style.css` (または `index.html` 内のstyleタグ) : `.float-window`, `.window-header`, `.window-body` などの共通スタイル定義、およびドラッグ可能を示す `cursor: move;` 等の設定。
* `./js/core/WindowManager.js` : 新規。フロートウィンドウの全ドラッグ・z-index統治ロジック。
* `./js/core/ShapeFactory.js` : 分岐の拡張（`line, curve, arc, rect, circle`）。
* `./js/main.js` : WindowManagerの初期化、活性連携。

#### 6. 完了の目安
* ゴール型。
* コントロールパネルとパレットが、それぞれ美しいフロートウィンドウとして画面に出現し、以下の挙動を完璧に示すこと。
  1. ヘッダーをドラッグすることで、2つのウィンドウがキャンバス上をスムーズに別々に移動すること。
  2. ウィンドウをクリックした際、そのウィンドウが必ず最前面（他方の手前）に滑らかに浮き上がること。
  3. ウィンドウ内でのいかなるクリック・操作も背後のCanvasへ透過（誤爆）せず、かつボタン操作は完璧に機能すること。
  4. 5大図形のどのボタンを選んでも、エラーでクラッシュすることなく、すべてが「Lineのスタブ」によって綺麗に作図できること。
