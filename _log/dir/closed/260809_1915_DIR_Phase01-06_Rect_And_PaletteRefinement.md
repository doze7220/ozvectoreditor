### 設計指針書 DIR: Phase 01-06 : 矩形（Rect.js）の実装および図形パレット・ツール切替のハードコード排除
*  ルール: ./PROJECT_CONSTITUTION.md
*  開発資料: ./PROJECT_ARCHITECTURE.md

--------------------------------------------------------------------------------

#### 1. 設計目的
本Phaseは、図形ポリモーフィズムの実証第二弾として、**4頂点構造を持つ「矩形（Rect.js）」**を完全に実装・統合すると同時に、将来的にあらゆる図形（Ellipse、Polygon等）やモード（パン、ズーム等）が際限なく追加されてもUIの配線が1行も壊れないように、**「図形選択パレット・ツール切り替えボタンのハードコーディング（相互排他ロジック）を完全に排除・汎用化する」**ことを達成する。

--------------------------------------------------------------------------------

#### 2. スコープ境界

##### やること
1.  **shapes/Rect.js の新規実装** :
    *   4頂点（points配列の長さ4固定）による「矩形（長方形）」のデータ保持、描画、当たり判定、ホバー、ハンドル制御を完全実装する。
    *   最初は「4つの角を個別に自由にドラッグして歪められる四角形」として振る舞い、後続のUI充実フェイズにおける「SHIFTキーでの対角連動スナップ（矩形維持）」に向けた完璧なデータ設計（pointsの長さは4、頂点順序は topLeft / topRight / bottomRight / bottomLeft で固定）を敷く。
2.  **main.js / PaletteController.js のツール切替排他ロジックの汎用化（ハードコード排除）** :
    *   `main.js` のツールボタン制御（旧 `createToolClickHandler` 等）が持っていた「ボタンAを光らせてボタンBを消す」という2ボタン限定の個別配線を完全撤去する。
    *   コントロールパネル（select, line）およびパレット（line, curve, arc, rect, circle）のすべてのボタンを、ツール名（'select', 'line', 'rect'等）をキーとして一括して一元トグル管理できる、美しく汎用化された「アクティブトグルシステム」へリファクタリングする。
3.  **ShapeFactory.js の rect 分岐の実装接続** :
    *   現在 `Line` スタブを返している `'rect'` の分岐を撤去し、新設する `Rect` クラスのインスタンス生成へ物理結線する。

##### やらないこと（Non-goals）
*   **SHIFTキーによる「正方形」作図、および「矩形維持」変形連動** :
    *   本フェイズのスコープ外とする。データ構造（pointsの長さ4）のみを先行して敷き、操作連動は「UI・操作充実フェイズ（Phase 2以降）」のSHIFTスナップ要件としてクリーンに実装する。
*   **塗りつぶし（Fill）機能の実装** :
    *   本フェイズでは「枠線（Stroke）のみ」の描画とし、塗りつぶしON/OFFやカラーピッカー連携は将来のプロパティ編集フェイズへ引き継ぐ。
*   **arc / circle の本実装** :
    *   これらは `Line` スタブフォールバックのまま現状維持とする（P1-7にて楕円弧クラスとして美しく統合実装するため、本フェイズでは一切触らない）。

#### 3. 実装要件

##### 要件1: js/shapes/Rect.js の新規実装
*   **データ構造** : 
    *   `this.points = [{x, y}, {x, y}, {x, y}, {x, y}]` (長さ4固定)
    *   インデックスの意味合い:
        *   `points[0]`: topLeft (左上)
        *   `points[1]`: topRight (右上)
        *   `points[2]`: bottomRight (右下)
        *   `points[3]`: bottomLeft (左下)
    *   コンストラクタは `(x1, y1, x2, y2)` を受け取り、対角線をなす2点から初期矩形（4点）を計算して `points` に格納する。
*   **作図プレビュー追従 (`updateDraftEnd(x, y)`)** :
    *   1回目のクリック座標を `P0`（topLeft）とし、現在のカーソル座標を `P2`（bottomRight）として追従させる。
    *   このとき、もう一方の対角線である `P1(x_current, y_start)` および `P3(x_start, y_current)` を動的に再計算して `points` に反映する。
    *   これにより、作図中は常にマウスに連動して「水平・垂直が保たれた長方形」のガイドが美しく描画される。
*   **描画 (`draw(ctx, t = 0)`)** :
    *   `points[0]` ➡️ `points[1]` ➡️ `points[2]` ➡️ `points[3]` の順で `ctx.lineTo` を回し、`ctx.closePath()` で閉じる。
*   **ハンドル描画 (`drawHandles(ctx)`)** :
    *   4つの角すべてにハンドルを表示する。
    *   4点すべてを、視覚的に分かりやすい「正方形（一辺8px、白塗り青枠）」で描画する。
*   **当たり判定 (`hitTest(x, y, tolerance)`)** :
    *   4つの辺（P0-P1, P1-P2, P2-P3, P3-P0）の各線分に対する最短距離が、いずれか1辺でも `tolerance` 以内であれば `true` を返す。
*   **ハンドル判定 (`hitTestHandle(x, y, tolerance)`)** :
    *   4つの角それぞれとの距離判定を行い、優先順位 `'topLeft'` ➡️ `'topRight'` ➡️ `'bottomRight'` ➡️ `'bottomLeft'` で対応する識別子を返す。
*   **共通APIの完備** :
    *   `Line.js` や `Curve.js` と全く同名・同シグネチャの9メソッド（`draw / drawHandles / hitTest / hitTestHandle / setVertex / translate / drawHover / updateDraftEnd / getVertexIndexForHandle`）を自律実装すること。

##### 要件2: main.js のツール切替・アクティブトグルシステムの汎用化
*   **ツールボタンの一括動的管理** :
    *   `main.js` に登録されているすべてのツール切替ボタン（コントロールパネルの `select`, `line`、パレットの `line`, `curve`, `arc`, `rect`, `circle`）を、一対一でマップする汎用的なオブジェクトまたは配列を構築する。
    *   例:
        ```javascript
        const toolButtons = {
            'select': document.getElementById('tool-select'),
            'line': document.getElementById('palette-line') || document.getElementById('tool-line'),
            'curve': document.getElementById('palette-curve'),
            'rect': document.getElementById('palette-rect'),
            // ... 他のボタンも同様にマッピング
        };
        ```
*   **汎用的な `applyTool(tool)` の設計** :
    *   現在の `applyTool(tool)` をリファクタリングし、引数 `tool` が渡された際、上記 `toolButtons` のすべてのボタンを走査して、キーが `tool` と一致するボタンには `.active` クラスを付与し、それ以外からは剥奪するループ処理を実装する。
    *   これにより、ボタンの追加や新しいツールの増設時に、UIトグルロジック（`main.js`）を1行も追加・修正する必要のない、完璧な開閉原則（O-C原則）が成立する。
*   **コントロールパネル「直線ツール」とパレット「直線」の一致問題の解決** :
    *   同じ `'line'` ツールを指すコントロールパネルのボタンとパレットボタンが、ループによる汎用排他処理によって**双方同時に正しくアクティブ化・非アクティブ化される**ことを保証する。

#### 4. アーキテクチャ設計

*   **新設するモジュール** :
    *   `js/shapes/Rect.js` (新規) : 矩形（4頂点構造）の幾何データ・当たり判定・描画処理を自律的に担う。
*   **改修するモジュール** :
    *   `js/core/ShapeFactory.js` (改修) : `'rect'` typeのインスタンス生成を、`Line` スタブから `new Rect(...)` へ切り替える。
    *   `js/main.js` (改修) : ツールボタンの一括トグル化（汎用 `applyTool` のリファクタリング）を実装し、個別相互排他を完全撤去する。

*   **本Phase固有の設計原則 (Constraints)** :
    *   **「4頂点構造の一貫性」** :
        *   `Rect` 内の頂点は必ず4点（topLeft, topRight, bottomRight, bottomLeft）で初期化・保持し、作図確定後（編集時）は各頂点を個別に動かせる仕様（平行四辺形や任意の歪んだ四角形を許容）を崩さないこと。これによりトポロジーの一貫性を100%維持する。
    *   **「コア層への図形分岐非混入」** :
        *   `VectorModel.js` や `InputTracker.js` 側には、`Rect` 特有のif/switch分岐を新たに1ピクセルも混入させてはならない。

#### 8. 完了の目安
*   **ゴール型** :
    1.  キャンバス上で「矩形」パレットを選び、ドラッグして意図通りのサイズで矩形を作成・プレビュー追従・確定できること。
    2.  確定した矩形を選択すると、4つの角に正方形のハンドルが表示され、それをドラッグすることで4つの角を個別に自由に変形できること。
    3.  コントロールパネルやパレットのどのボタンをクリックしても、コンソールエラーが一切発生せず、対応する全ボタン（同一キーを持つものを含む）が美しく相互排他的にアクティブハイライトされること。
