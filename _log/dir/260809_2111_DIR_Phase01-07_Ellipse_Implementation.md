#### 1. 設計目的
本Phaseの目的は、円・楕円・弧という幾何学的に同根の図形を、将来の相互型変換およびモーフィング（Lerp）時のトポロジー破綻から100%保護するため、**「`Ellipse.js`（楕円弧クラス）」の1枚に完全一元化して設計・実装すること**である [221, 265]。
UI（パレット）側は矩形と同様に「円」ボタン1つで楕円を自由作図するシンプルな操作モデルから開始し、将来的にSHIFTキーによる正円ロックや、タイムライン上での弧（開始・終了角）への再編集・モーフィングを行き来可能にするための、極めて強固な幾何学データ基盤（9メソッド契約）を確立する [87, 94]。

#### 2. スコープ境界
##### やること
1.  **shapes/Ellipse.js の新規実装** :
    *  将来の「弧（Arc）」へのシームレスな移行・変形を完全に保証するため、最初から**「頂点数（points配列の長さ）を5で完全固定」**した一元データ構造を構築する [60, 87]。
    *  初期（P1-7）は「開始角 $0$、終了角 $2\pi$」でロックされた、純粋な「閉じた楕円（円・楕円）」として振る舞わせる [60]。
    *  ホバー強調、4隅（または外接矩形基準）のドラッグハンドルによる直感的なサイズ変形（X/Y半径の個別伸縮）を自律実装する。
2.  **ShapeFactory.js の circle/arc 分岐の一元接続** :
    *  現在 Line スタブを返している `circle` および `arc` のケースを、いずれも新設する `Ellipse` クラスのインスタンス生成へ物理結線する [51, 102]。
    *  作図の入口が「円」であっても「弧」であっても、生成されるデータの実体は同じ `Ellipse` である状態を作る。

##### やらないこと（Non-goals）
*   **作図・編集時における「開始角・終了角」の可変ハンドルの表示・操作** :
    *  本フェイズのスコープ外とする。データ構造（pointsの長さ5）として角度制御点を裏側で先行保持するのみに留め、操作ハンドルおよび角度フィルタリング（ピザスライス描画）の有効化は、後続の「弧・プロパティ拡張フェイズ」へクリーンに送る。
*   **SHIFTキーによる「正円」作図スナップ** :
    *  矩形と同様、UI・操作充実フェイズへ持ち越し、本フェイズでは対角ドラッグ比率通りの自由な楕円作図を許容する [87]。

#### 3. 実装要件

##### 要件1: shapes/Ellipse.js の幾何データ構造（トポロジーロックの伏線）
将来「閉じた楕円」から「一部が切り欠かれた弧」への行き来や、補間再生（Lerp）時の頂点数不一致を永久に防ぐため、`points` 配列は最初から以下の **長さ5で固定保持** する [60, 221]。

*   `points[0]`: **中心点 (Center)**
*   `points[1]`: **右端制御点 (Right Control)** ➡️ 中心からの距離を X半径 ($r_x$) とする。
*   `points[2]`: **上端制御点 (Top Control)** ➡️ 中心からの距離を Y半径 ($r_y$) とする。
*   `points[3]`: **開始角制御点 (Start Angle Control)** ➡️ 最初は `points[1]`（右端）と同一座標でダミー保持。
*   `points[4]`: **終了角制御点 (End Angle Control)** ➡️ 最初は `points[1]`（右端）と同一座標でダミー保持。

##### 要件2: 2クリック作図とドラフト追従（updateDraftEnd）
1.  1回目のクリック（始点 $P_0$）を「楕円の外接矩形の角（例: 左上）」とするのではなく、ユーザーにとって最も直感的な**「楕円の中心点 $P_c$」**として固定する。
2.  2回目のクリック（またはドラフト中のマウス座標 $P_{current}$）への追従において、中心からマウスまでの絶対距離をそれぞれ $r_x = |x_{current} - xc|, r_y = |y_{current} - yc|$ として算出する。
3.  この $r_x, r_y$ を基に、`points[1]`（右端: $xc + r_x, yc$）および `points[2]`（上端: $xc, yc - r_y$）の座標を動的に再計算して `points` に反映する。

##### 要件3: 描画（draw）と 4頂点ハンドル
*   **楕円描画** :
    *   Canvas2D の `ctx.ellipse(xc, yc, rx, ry, rotation, startAngle, endAngle)` を用いる。
    *   本フェイズでは、回転角 `rotation = 0`、開始角 `startAngle = 0`、終了角 `endAngle = 2 * Math.PI` で固定描画する。
*   **ハンドル描画（drawHandles）** :
    *   中心点 `points[0]`（平行移動用ハンドルとして、Line/Curveのmoveと同等に円形ハンドルで描画）
    *   右端 `points[1]`（X半径伸縮ハンドル、正方形）
    *   上端 `points[2]`（Y半径伸縮ハンドル、正方形）
    *   左端（$xc - r_x, yc$）および下端（$xc, yc + r_y$）にも、操作性の観点から対称位置ハンドル（正方形）を計算によって表示・ドラッグ可能にする（ドラッグ時はそれぞれ `points[1]`, `points[2]` の対応座標成分を反転連動させる）。
    *   開始角（`points[3]`）および終了角（`points[4]`）のハンドルは、本フェイズでは**描画・衝突判定ともに対象外（非表示・操作不可）**とする。

##### 要件4: 楕円方程式に基づく当たり判定（hitTest）
*   入力点 $(x, y)$ に対し、中心 $(xc, yc)$ からの正規化された距離が、一定の許容誤差（tolerance）の範囲内（境界線付近）にあるかを以下の楕円方程式で判定する：
    $$\frac{(x - xc)^2}{rx^2} + \frac{(y - yc)^2}{ry^2} \approx 1$$
*   線の太さ（strokeWidth）と tolerance を加味し、内側や外側に外れすぎている場合は false を返し、輪郭線上のみでホバー強調されるようにする。

##### 要件5: 共通API契約（9メソッド）の完全履行
Line/Curve/Rect と全く同一のシグネチャを持つ以下の9メソッドを自律実装し、コア層（Model/Renderer/InputTracker）を1行も汚すことなくシステムに結合させる [62, 94]。
1. `draw(ctx, t)`
2. `drawHandles(ctx)`
3. `hitTest(x, y, tolerance)`
4. `hitTestHandle(x, y, tolerance)`
5. `setVertex(vertexIndex, x, y)`
6. `translate(dx, dy)`
7. `drawHover(ctx)`
8. `updateDraftEnd(x, y)`
9. `getVertexIndexForHandle(handleName)`

#### 4. アーキテクチャ設計

*   **新設するモジュール** :
    *   `js/shapes/Ellipse.js` (新規) : 楕円弧（5頂点構造）の幾何データ・当たり判定・描画処理を自律的に担う。
*   **改修するモジュール** :
    *   `js/core/ShapeFactory.js` (改修) : `circle` および `arc` ケースを、Line フォールバックから `new Ellipse(...)` へ切り替える [102]。
*   **本Phase固有の設計原則 (Constraints)** :
    *   **「5頂点構造の一貫性」** :
        *   閉じた楕円であっても、内部データは必ず長さ5の `points` 配列で保持する。これにより、将来「弧」へ変換された際も、ゲームエンジン側は単に time `t` に沿って `points` を Lerp 補間するだけでモーフィングアニメーションをバグなく再生できる。
