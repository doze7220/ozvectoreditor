# 設計指針書 DIR: Phase 09 : 曲線のパス
* ルール: `./PROJECT_CONSTITUTION.md`

## 1. 大ゴール
パスに曲線の区間を持たせ、曲線のツールでクリックごとに点を打って、打った点をなめらかに通る曲線を続けて引けるようにする。あわせて、区間の直線⇔曲線の切り替え、今の曲線・弧の結合（曲線と弧を組み合わせた閉じた形を塗る）、書き出しの対応を行う。区間の種類を増やす作業を本Phaseにまとめ、次の変形のPhase（拡大縮小・回転・反転）を区間の種類が出そろった状態で1回の設計で作れるようにする（`_doc/PROJECT_MILESTONE.md`「Phase方針メモ」の「曲線のパス・変形・パスの編集の順番」）。直線の連続作成は、前のInterrupt「線を続けて引く」で入っている（`PROJECT_ARCHITECTURE.md` 3章22.）。
* **完了の目安**: ゴール型。4章の実装要件がテストプレイで確かめられ、曲線の区間を持つパスを書き出したJSがOZ Engineで正しく描かれ、発注者が「この形で変形のPhaseへ進める」と判断した状態。

## 2. やらないこと（Non-goals）
* 方向のハンドル（Photoshopのペンのように、点から伸びる2本のハンドルで曲がり方を直接いじる）は出さない。曲線の形は打った点だけで決まる（発注者の決定、2026-11-18）。ハンドルでの調整を入れるかは未定。
* 区間をクリックして選ぶ仕組みは作らない。区間は両端の頂点を選んで指す（発注者の決定、2026-11-18）。
* 引きながらの混ぜ書き（引いている途中にキーで直線と曲線を切り替える）は入れない（発注者の決定、2026-11-18）。混ぜるときは、引いた後の区間の切り替えか、端点から別のツールで描き足す。
* ドラッグによるフリーハンドの線（未定。`_doc/PROJECT_MILESTONE.md`のアイデアメモ）。
* `Enter`・`Ctrl`＋クリックで引くのを終える操作（見送り。同アイデアメモ）。
* 頂点の追加（Phase 09-02の「曲線に」で中点に点を足す場合を除く）・削除、パスの分割、パスを開く・閉じる、区間の削除（パスの編集のPhase）。
* 拡大縮小・回転・反転、外枠のハンドル、大きさと角度の数値入力、円・弧の回転（変形のPhase）。ただし、曲線の区間は、変形のPhaseで点を拡大縮小・回転したときに曲線の形も同じように拡大縮小・回転する表し方にする（4章 Phase 09-01 のメモ）。
* 端点以外への吸い付き（曲線の途中の点・矩形・円の点など。`_doc/COWORK_STATUS.md` 2章Aの「Phase05-04由来」の項。変形のPhaseで拾う候補のまま）。
* 円（`circle`）・矩形（`rect`）の結合（端点を持たないため）。
* 直線の区間と曲線の区間のつなぎ目をなめらかにすること（発注者の決定、2026-11-19。つなぎ目は常に角が立つ。Phase 09-02の「角」は両側とも曲線の点だけで操作できる）。
* 今の曲線（1本の2次の曲線）への制御点の追加・削除、平行移動のハンドルの追加（`_doc/COWORK_STATUS.md` 2章Aの「Phase01-05 DIR6章の設計決定」の項）。曲線のツールの置き換えで、今の曲線を新しく作ることはなくなるため。この項を閉じるかは本Phaseのクローズで現場設計が判断する。

## 4. サブフェイズごとの実装要件

### Phase 09-01: 曲線の連続作成（曲線の区間を持つパス）
* **目的**: パスに曲線の区間を足し、曲線のツールで打った点をなめらかに通る曲線を続けて引けるようにする。
* **実装要件**:
  * 曲線のツールは、クリックごとに点を打って続けて引くツールになる（今の、1本の曲線を作り、曲がりを引っ張る点が線の外にあるツールの置き換え。発注者の決定、2026-11-18）。
  * 点を2つ打った時点では、2点を結ぶ直線になる。3つ目を打つと、始点・2点目・3点目のすべてを通る曲線に変わる。2点目は曲がりを引っ張る点ではなく、曲線が通る点である（発注者案、2026-11-18）。
  * 4つ目以降は、点を足すたびに、打った点すべてをなめらかに通る1本の曲線になる。点と点のつなぎ目に角が立たない。点を足すと、前の区間の形も少し変わる（発注者案、2026-11-18）。
  * 引いている途中は、直前の点からカーソルまでの曲線（または直線）が付いてくる。
  * 終わり方・既存の線とのつながり・途中の戻し・`Shift`の45°刻み・スナップ（1px・グリッド。`Ctrl`の間は働かない）は、直線のツールの連続作成とそろえる（発注者の決定、2026-11-18。今のふるまいは`PROJECT_ARCHITECTURE.md` 3章22.、了承済みの細かいふるまいは`_doc/COWORK_STATUS.md` 2章Aの「Interrupt「線を続けて引く」由来」の項）。具体的には次のとおり。
    * 最後に打った点をもう1回クリック、`Esc`、ツールの切り替えで、開いたまま終える。始点に吸い付いた状態でクリックすると、閉じた形になって終わる。
    * 開いた線の端点から引き始めると、その線の続きとして伸びる。引いている途中に別の開いた線の端点に吸い付いてクリックすると、その線とつながる。直線だけのパス・直線にも、曲線のツールで描き足せる（描き足した分が曲線の区間になる）。
    * `Backspace`/`Delete`・`Ctrl`+`Z`で最後に打った点を消し、引き続けられる。
  * 閉じた曲線の形は、塗りを付けると内側が塗られる（着色のPhaseの「塗れる形」と同じ）。内側のクリックで選べる。
  * 曲線の区間を持つパスを、選択（`V`）で選んで動かせる。範囲選択で選べる。線の上のクリックで選べる。
  * 頂点の選択（`A`）では、曲線が通る点が頂点として表示され、選んで動かせる。点を動かすと、曲線は打った点をなめらかに通ったまま形が決まり直し、前後の区間の形も少し変わる（発注者の決定、2026-11-18）。
  * 位置の数値入力・矢印キーでの微調整・整列と分布・複製・コピー＆ペースト・削除・取り消し/やり直しが、曲線の区間を持つパスにも今までどおり働く。
  * 曲線の区間を持つパスを保存して開き直すと、同じ形に戻る。今までに描いた曲線（1本の2次の曲線）は今までどおり読めて、描かれ、選べて、頂点（曲がりを引っ張る点を含む）を動かせる。
  * 曲線の区間を持つパスをスプライトのJSとして書き出すと、エディタで見たとおりの形で描かれる（エディタの確認用ページで確かめる。OZ Engineでの確認はPhase 09-04）。
* **持ち越し事項**:
  * `_doc/COWORK_STATUS.md` 2章Aの「Interrupt「線を続けて引く」由来」の項：線を引いている途中かの判定（今は「作成途中の図形が結合できる線か」）を、曲線のツールの作成途中の図形に合わせて見直す。了承済みの細かいふるまい（クリックの判定の順・ダブルクリックの2回目・`Ctrl`+`Z`の押しっぱなし・縮小表示での終わり方）を曲線にもそろえる。
  * `_doc/COWORK_STATUS.md` 2章Aの「Phase05-02由来」の項：曲線の区間を足すと、今の書き出し形式（版2）の`polyline`でパスを表せなくなる。新しい`kind`の追加と書き出し形式の版上げ、`Path`の描画・当たり判定・`toDrawElement`・`fromJSON`、`SpriteSerializer`の外枠、`CodeExporter`の`DRAW_SOURCE`をそろえる。区間の要素の判定を共通モジュールへ移すかの見直し。
  * `_doc/COWORK_STATUS.md` 2章Cの`CodeExporter`の`DRAW_SOURCE`と各図形の`draw`を手でそろえている件（パスの曲線の区間で両方を直し、一致テストを通す）。
* **メモ**:
  * **曲線の区間の表し方（REQ作成時に確認）**：作業データに「点を通るなめらかな曲線」の区間として持つか、ベジェの制御点に直して持つかは、実コードを見て決める。発注者が決めたのはふるまい（点を動かすと、なめらかなまま前後も形が決まり直す）だけである。変形のPhaseのため、点を拡大縮小・回転（縦横別の倍率を含む）すれば曲線の形も同じように変わる表し方にする（点を通る曲線の作り方によっては、縦横別の倍率で形が崩れるものがある）。Phase 09-03で今の曲線（2次）・弧を区間として取り込むため、その形を保てるかも合わせて考える。
  * **直線の区間と曲線の区間のつなぎ目（REQ作成時に発注者へ確認）**：直線のパスの端点から曲線のツールで描き足したとき、つなぎ目の点で角が立つか、なめらかにつながるか。閉じた曲線の始点のところも同じ。
  * **点が2つで終えたときの図形の種類（REQ作成時に確認）**：直線のツールで点2つで終えると直線（`line`）になる。曲線のツールで点2つで終えたときも直線にするか、曲線の区間を持つパスにするか。
  * **作業データの版・書き出し形式の版（REQ作成時に確認）**：書き出し形式は版3に上げる見込み（エンジンとの約束(c)。連絡票はPhase 09-04で出す）。作業データの版を上げるか（パスを足したときは上げなかった。`PROJECT_ARCHITECTURE.md` 2章）は実コードを見て決める。本Phaseの中で版を上げるのは1回にし、Phase 09-02・09-03で書き出しに足すものが出ても同じ版の中で扱う。

### Phase 09-02: 区間の直線⇔曲線の切り替えと点の滑らかさ
* **目的**: 引いた後に、パスの区間や単独の直線・曲線を、直線と曲線の間で切り替えられるようにする。あわせて、曲線の連なりの途中の点を、なめらかにつなぐか角を立てるか選べるようにする（髪の毛の先端のような形を作るため）。
* **実装要件**:
  * 頂点の選択（`A`）で、パスの隣り合う2つの頂点を選ぶと、オプションバーの「直線に」「曲線に」のボタンでその間の区間を切り替えられる。3つ以上続けて選んでいれば、その間の区間をまとめて切り替えられる（発注者の決定、2026-11-18。区間をクリックして選ぶ仕組みは作らない）。
  * まっすぐな区間を「曲線に」すると、区間の中点に曲線が通る点が1つ足される。その時点では形はほぼ変わらず、その点を動かして曲げる（発注者の決定、2026-11-18。両隣に区間がないと、点を通る曲線は曲がらないため）。
  * 単独の直線（`line`）も「曲線に」で同じように中点に点が足され、曲線になる。今の曲線（1本の2次の曲線）は「直線に」で、両端を結ぶ直線になる（曲がりを引っ張る点は捨てられ、形が変わる）。
  * 区間の切り替えで、塗りの色は保たれる。閉じたパスの区間を切り替えても、閉じたままで塗りも残る（`_doc/PROJECT_MILESTONE.md`「P11：パスの編集」節の「塗りとの関係」）。
  * 切り替えは取り消し（`Ctrl`+`Z`）1回で戻る。
  * ボタンは、切り替えられる頂点を選んでいないときは押せない（押しても何も起きない形でもよい。REQで決める）。
  * **点の滑らかさ**（発注者案・決定、2026-11-19）：頂点の選択（`A`）で点を選ぶと、オプションバーに「角」のチェックボックスが出る（表示の語は「角」。発注者の決定、2026-11-19）。
    * チェックが外れているとき、その点の両側の曲線はなめらかにつながる。チェックを入れると、両側の曲線がその点でそれぞれ終わり、角が立つ（曲線の連なりがその点で切れる）。
    * 操作できるのは、両側とも曲線の区間の点だけ（発注者の決定、2026-11-19）。片側でも直線の区間の点は、実際に角が立っているため、チェックが入ったまま操作できない。開いたパスの端の点、曲線の区間を持たない図形の点も操作できない（チェックの表示はREQで決める）。
    * 曲線のツールで打った点、曲線の区間どうしがつながった点は、初めはチェックが外れている（なめらか。今のふるまいと同じ）。
    * 切り替えは取り消し（`Ctrl`+`Z`）1回で戻る。保存して開き直しても、書き出しても保たれる（書き出したJSでも、角を立てた点は角が立って描かれる）。
* **持ち越し事項**: なし。
* **メモ**:
  * 「曲線に」で足す点の位置と、足した後の形がほぼ変わらないことの程度（REQ作成時に確認）：区間の両隣が曲線の場合、中点に点を足すと形がわずかに変わることがある。許容範囲は発注者と決める。
  * 「曲線に」で足した点で頂点の数が増える。パスの編集のPhaseの頂点の追加とは別の操作として扱い、そちらのPhaseで頂点の追加を作るときに整理する。
  * 単独の直線・今の曲線が切り替え後に何の図形の種類になるか（パスになるか）は、REQ作成時に確認する。図形の`id`・重なり順・選択が切り替えの前後で保たれるかも確認する。
  * ボタンの置き場所は、オプションバーのまとまり（`.toolbar-group`）を1つ足す作り（`PROJECT_ARCHITECTURE.md` 3章13.）が使える見込み（REQ作成時に確認）。
  * **点の滑らかさの持ち方（REQ作成時に確認）**：点ごとの情報をデータでどう持つか（頂点に持つか、区間の側に持つか）、作業データの版を2のままにできるか（古いエディタで開くと角を立てた点がなめらかに描かれる等の扱い）。今の形の決め方は「曲線の連なりの切れ目では仮の点を使う」作りのため（Phase 09-01のメモ）、角を立てた点を連なりの切れ目として扱う形が使える見込み。書き出しの`bezierPath`は制御点を座標で明示するため、書き出し形式の版は3のままで扱える見込み。
  * **点の滑らかさで決めること（REQ作成時に発注者へ確認）**：複数の点を選び、チェックの状態が混ざっているときの見せ方と、押したときの結果。操作できない点が混ざっているときの扱い。区間を一度「直線に」してから「曲線に」戻したとき、その点を角にするか。「曲線に」で中点に足した点のチェック。
  * 「この点は角」のアイデア（Phase 09-01のメモ、2026-11-19）は、本サブフェイズの「点の滑らかさ」として扱うと決めた（発注者、2026-11-19）。
  * **REQ作成時の決定（2026-11-19）**：
    * 分け方（発注者の承認済み）：`a`＝点の滑らかさ（「角」のチェックボックス。REQ `261119_1323_REQ_Phase09-02a_Corner_Point`）、`b`＝区間の直線⇔曲線の切り替え。「曲線に」で点を足すときに角の情報も保つ必要があるため、角を先に作る。
    * 発注者の決定：チェックボックスはオプションバーの右端に常に置き、使えないときは押せない見た目／複数の点を選んでいるときは角を操作できる点だけで見た目と結果を決める（混ざっていれば「−」で、押すと全部角。全部角なら押すと全部なめらか）。

### Phase 09-03: 曲線・弧の結合

* **実装要件**:
  * 今の曲線と弧の端点も、直線・パスの端点と同じく、端点のドラッグでほかの線の端点に吸い付いて結合でき、結合のボタン（ツールバーの結合）でも結合できる。結合すると、パスの曲線の区間に変わる（発注者の要望、2026-11-09・2026-11-11。発注者の決定、2026-11-18）。

  * 弧は、結合した後は弧の半径のハンドルでの編集はできなくなり、パスの頂点として編集する（発注者の決定、2026-11-18）。
  * 曲線・弧・直線・パスを組み合わせて端点をつなぎ、閉じた形にすると、塗れる（着色のPhaseでは弧を塗らないため。発注者の要望、2026-11-11）。
  * 曲線のツール・直線のツールで引いている途中に、今の曲線・弧の端点に吸い付いてクリックすると、その線とつながる。今の曲線・弧の端点から引き始めると、その線の続きとして伸びる。
