## 1. 大ゴール
画面の並びと構成を、Photopea（ブラウザで動く、Photoshopに近い画像編集ソフト）を手本に組み替える。上端にメニューバーとオプションバー、左端に固定のツールバー、右側に積んだパネル（キャンバスの一覧・図形の一覧）、下端にステータスバーという形にし、浮いているウィンドウ（フロートウィンドウ）をなくす。機能を増やすPhaseではなく、今ある操作の置き場所を整える。塗りの表現のPhaseの前に置き、そこで増える欄（アルファ付きの色・線の位置など）を、決まった骨組みの中に足せるようにする（発注者の考え、2026-11-27）。
* **完了の目安**: ゴール型。4章の実装要件がテストプレイで確かめられ、発注者が「この画面で、塗りの表現の部品を足していける」と判断した状態。

## 2. やらないこと（Non-goals）
* アイコンの絵の描き直し・差し替え（発注者の決定、2026-11-28：アイコンはそのまま）。エディタで描いた絵への差し替えは、絵ができたときに単発の作業で入れる。
* キャンバスのタブでの切り替え（キャンバスの一覧は右のパネルに固定で出す。発注者の決定、2026-11-28）。
* パネルをドラッグして好きな場所へ動かす・つなぎ替える仕組み（Photoshopのドッキング）、パネルの幅の変更。
* 配色の切り替え（明るい配色・暗い配色を選ぶこと）。
* 新しい編集の機能。操作の働き・キーの割り当ては変えない（置き場所が変わるだけ）。
* 塗りの表現の欄（アルファ付きの色・線の位置・グラデーション）。置き場所だけを空けておく（塗りの表現のPhase）。
* 右クリックメニュー、ヒストリーパネル、スマートガイド（未定）。
* 作業データ・書き出し形式の変更と版上げ、OZ Engineへの連絡票。
* 確認用ページ（`sprite-check.html`）の変更。

## 4. サブフェイズごとの実装要件

### 本Phaseで決定済みの事項（全サブフェイズ共通。発注者の決定、2026-11-28）
* **画面の構成（本Phaseの完了時）**：上端にメニューバー、その下にオプションバー（1行）。左端にツールバー（縦一列、固定）。右側にパネルの列（上にキャンバスの一覧、下に図形の一覧）。下端にステータスバー（今のまま）。定規は今のまま、キャンバスの領域の上端と左端。
* **フロートウィンドウをなくす**：ツールパレットは左端の固定のツールバーに、キャンバスパレットは右側の図形の一覧の上の固定のパネルになる。
* **データを変えない**：作業データの版・書き出し形式の版は変えない。本Phaseで足す状態（パネルの高さの配分・折りたたみ・メニューの開閉）は、作業データに入れず、取り消し/やり直しの対象にしない。
* **キーは変えない**：今のショートカットは、すべて今までどおり働く。

### Phase 13-01: 画面の骨組み
* **目的**: 画面を、メニューバー・オプションバー・左のツールバー・右のパネルの列・ステータスバーの形に組み替え、フロートウィンドウをなくす（以後のサブフェイズの置き場所を先に作る）。
* **実装要件**:
  * 左端に、ツールバーが縦一列で固定して出る（今のツールパレットのボタンと同じもの・同じ順。発注者の決定、2026-11-28）。ドラッグで動かすことはできない。今どのツールかが、今までどおりボタンの押し込みで分かる。
  * 右側に、パネルの列が固定で出る。上がキャンバスの一覧、下が図形の一覧（発注者の決定、2026-11-28）。
  * キャンバスの一覧のパネルでは、今のキャンバスパレットと同じく、キャンバスの切り替え・名前・削除ができる。
  * キャンバスの一覧と図形の一覧の境目をドラッグすると、高さの配分が変わる（発注者の決定、2026-11-28）。初期はキャンバスの一覧が小さめ。各パネルは見出しを押すと折りたためる。
  * `Tab`で、左のツールバーと右のパネルの列が隠れる・出る（発注者の決定、2026-11-28）。メニューバー・オプションバー・定規・ステータスバーは残る。隠すとキャンバスの領域が広がる。
  * 上端に、メニューバーとオプションバーの行が並ぶ（中身は Phase 13-02・13-03 で入れる。本サブフェイズの間は、今のツールバーの2行の中身を仮にここへ置いてよい）。
  * キャンバスの領域は、左のツールバー・右のパネルの列・上端の2行・ステータスバーを除いた範囲になり、全体表示・中心へのズーム・定規は、その範囲を基準に働く。
  * 今のパレットを開閉するボタン（🧰・📁）はなくなる（固定になるため）。
  * すべての操作が、本サブフェイズの前と同じように働く。
* **持ち越し事項**: なし。
* **メモ**:
  * パネルの折りたたみ・初期の配分・高さの配分を覚えるかは、リード設計の案（初期の配分は REQ で決める。配分と折りたたみはページを開き直すと初期に戻る＝表示の切り替えと同じ扱い。REQ作成時に発注者へ確認）。
  * `?dev`の確認用ウィンドウは、フロートウィンドウのまま残してよい（開発用のため。REQ作成時に確認）。フロートウィンドウを動かす仕組み（`WindowManager`）を残すかもREQ作成時に決める。
  * 今の`Tab`はフロートウィンドウ（`.float-window`）を隠す作り（`PROJECT_ARCHITECTURE.md` 3章15.「パレットをまとめて隠す/出す」）。対象を左のツールバーと右のパネルの列に変える。
  * 狭い画面（1280px幅）で、キャンバスの領域がどれだけ残るかを確かめる。左のツールバーの幅、右のパネルの列の幅（今の図形の一覧の幅240pxを使うか）はREQ作成時に決める。
  * 右のパネルの列は、塗りの表現などで後からパネルを足せる作りにしておく（本Phaseでは足さない）。

### Phase 13-02: メニューバー
* **目的**: 上端にメニューバーを置き、ツールバー1行目のボタンとファイルの操作をメニューへまとめる。
* **実装要件**:
  * 上端のメニューバーに、メニューの名前が並ぶ。名前を押すとプルダウンが開き、項目を押すとその操作が働く。開いている間は、ほかのメニューの名前にカーソルを動かすと、そのメニューに切り替わる。`Esc`・メニューの外のクリックで閉じる。
  * 項目には、割り当てのあるキーが表示される。今使えない操作の項目は、押せない見た目になる（今のボタンと同じ判定）。
  * 今のツールバー1行目のボタン（取り消し・やり直し・削除・結合）は、メニューへ移り、画面からなくなる（発注者の決定、2026-11-28）。キーは今までどおり働く。
  * ファイルの操作（新規・開く（ファイル）・インポート・出力（作業ファイル）・出力（エンジン用））は、「ファイル」メニューへ移る（発注者の決定、2026-11-28）。キャンバスの一覧のパネルからは、これらのボタンがなくなる。
  * 表示の切り替え（アウトライン・背景・グリッド）・全体を画面に収める・パネルを隠すも、「表示」メニューから使える。ステータスバーの切り替えのボタンは今のまま残る（発注者の決定、2026-11-28）。
* **持ち越し事項**: なし。
* **メモ**:
  * **メニューの分け方（リード設計の案。REQ作成時に発注者へ確認）**：「ファイル」（新規・開く（ファイル）・インポート・出力（作業ファイル）・出力（エンジン用））、「編集」（取り消し・やり直し・切り取り・コピー・貼り付け・同じ位置に貼り付け・複製・削除・すべて選択・選択の反転）、「パス」（結合・分割・区間を消す・フォルダにまとめる・フォルダの解除・複合パス・重なり順）、「表示」（アウトライン・背景・グリッド・全体を画面に収める・パネルを隠す）。PNG出力が先に入っていれば「ファイル」に入れる。
  * キャンバスの削除・新規作成のうち、どれを「ファイル」メニューに、どれをキャンバスの一覧のパネルに置くかは、REQ作成時に決める（キャンバスの削除の確認の小窓は今のまま）。
  * メニューを`Alt`キーで開く操作は入れない見込み（`Alt`の単独押下は今、抑止している。`PROJECT_ARCHITECTURE.md` 4章`core/AltKeyGuard.js`）。
  * 項目の押せる/押せないの判定は、今のボタンの判定と1か所にまとめる（2通りにしない）。REQ作成時に確認。
  * メニューを開いている間のキー操作（ショートカットが働くか）をREQ作成時に決める。

### Phase 13-03: オプションバーの入れ替え
* **目的**: オプションバーを1行にし、今のツールと選んでいるものに関係する欄だけを出す。
* **実装要件**:
  * オプションバーの中身が、今のツールと選んでいるものに合わせて入れ替わる（発注者の決定、2026-11-28。Photopea・Photoshopと同じ）。関係のない欄は出ない。
  * 線・塗りの色と線の太さ（今のツールバー1行目のスタイル）は、オプションバーに出る（発注者の決定、2026-11-28）。図形を描くツールと、図形を選んでいるときに出る。
  * 欄の働き（位置・大きさ・角度・基準点・反転・整列・分布・角・曲線に・分割・区間を消す・色・太さ）は、今までどおり。
  * オプションバーは1行に収まる。
* **持ち越し事項**: なし。
* **メモ**:
  * **ツールごとの中身（リード設計の案。REQ作成時に発注者へ確認）**：選択（`V`）＝色・太さ、位置・大きさ・角度・基準点・反転、整列・分布。頂点の選択（`A`）＝頂点の位置、角・曲線に、分割・区間を消す。図形を描くツール＝色・太さ。キャンバス移動・スポイト＝なし、または色・太さ。何も選んでいないときの選択（`V`）の中身も決める。
  * 1280px幅で1行に収まらないときの扱い（右側が切れる今の作りのままか）をREQ作成時に決める。
  * 塗りの表現のPhaseで、色の欄（アルファ付き）・線の位置の欄をここへ足す。足せる余白・まとまりの作りにしておく。
  * オプションバーは、まとまり（`.toolbar-group`）ごとにUI部品1つと`main.js`の配線ブロック1つを持つ作り（`PROJECT_ARCHITECTURE.md` 3章13.）。出す・隠すの判定を1か所にまとめる形をREQ作成時に決める。

### Phase 13-04: 配色
* **目的**: 画面の配色を、Photopeaに合わせる。
* **実装要件**:
  * メニューバー・オプションバー・左のツールバー・右のパネル・ステータスバー・定規の配色が、Photopeaに合わせた配色になる（発注者の決定、2026-11-28：並びとカラーリングを合わせる）。
  * ボタンの押し込み・カーソルを置いたとき・押せないときの見た目が、新しい配色の上で見分けられる。図形の一覧の行の選択・描き込む先の線・隠した行のうすさなども、見分けられる。
  * アイコンの絵は変えない。絵文字・記号・エディタで描いた矢印が、新しい配色の上で見える。
  * キャンバスの背景（白・黒の切り替え）と図形の色は変わらない。
* **持ち越し事項**: なし。
* **メモ**:
  * **色の決め方（REQ作成時に発注者へ確認）**：Photopeaの標準の配色は暗い灰色の見込み。具体的な色は、発注者にPhotopeaの画面を見てもらいながら決める。色の定義は、CSSのカスタムプロパティなど1か所にまとめる。
  * 選択・頂点の選択のボタンの矢印（黒い矢印・白い矢印の絵）が暗い背景で見えにくくならないかを確かめる。見えにくい場合も、絵は変えず、ボタンの背景などで見せる（2章）。
  * 図形の一覧の目・鍵のアイコン（データURIのSVG）の色も、新しい配色に合わせる必要があるかを確かめる。
