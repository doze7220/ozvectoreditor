# RES: 作業計画・作業レポート (Phase 07-05) : スナップ（点を打つとき・図形や頂点を動かすときの整数px／グリッド10pxへの丸め、`Ctrl`での一時無効、ステータスバーのスナップの部品と座標の表示）
* 参照元REQ: `./_log/req/261114_1330_REQ_Phase07-05_Snap.md`

## 1. 作業目的
スナップ（座標・移動量を単位＝1pxまたはグリッド10pxの倍数へ**丸める**こと。吸い付き先は探さない）を足す。スナップがONのとき、図形を描くときに打つ点の**座標**と、図形・頂点（ハンドル）を動かすときの**移動量**が単位の倍数になる。ステータスバーの右側にスナップのON/OFFのボタン（🧲。仮）と単位のボタン（`1`／`10`）を置く。`Ctrl`（macOSの`⌘`を含む。`event.ctrlKey || event.metaKey`）を押している間は、スナップも端点への吸い付きも働かない。ステータスバーのカーソル位置の座標は、スナップがONで最後の`mousemove`で`Ctrl`が押されていなかったときは丸めた値を表示する。

* **用語**（本RES・コード・資料で使い分ける）：**スナップ**＝本作業で足す丸め。**端点への吸い付き**＝Phase 05-04の既存の機能（`shapes/EndpointSnapRules.js`・`edit/EndpointSnapper.js`・`InputTracker`の`#snapAssist`・`#drawStartSnap`・`#drawEndSnap`・`#dragEndpoint`・`#dragSnap`・`#showSnap`・`#resetSnapState`・`VectorModel`の`setSnapPoint`／`clearSnapPoint`／`getSnapPoint`）。既存の識別子の`snap`はすべて端点への吸い付きを指す（改名しない）。
* **本作業で足す識別子はすべて`UnitSnap`／`unitSnap`／`unit-snap`を含む名前にする**（端点への吸い付きの識別子は`snap`・`EndpointSnap`・`Snap`だけを含み`Unit`を含まないため、名前だけで区別できる）。丸めの関数名は`round…ToUnit`とする。
* 作業データ形式・書き出し形式は変えない（版はどちらも2のまま）。スナップの設定は作業データ・履歴・ブラウザの保存先に入れず、取り消し/やり直しの対象にしない。既存の図形の座標は、開いただけ・スナップを切り替えただけでは変わらず、出力でも丸めない。
* **スナップがOFFで`Ctrl`を押していないとき**、既存の振る舞い（`VectorModel`へ渡す座標・呼び出しの回数と順を含む）は今と同じ。変わるのは、ステータスバーにまとまりが1つ増えること、ページを開いたときにスナップがON・1pxであること、`Ctrl`を押している間は端点への吸い付きが働かなくなることだけ。
* 自己監査の結果、REQ要件9の制約（`InputTracker`には呼び出しと配線・作業用フィールドだけを足す）の中で作れると判断した（DIR変更提案は無い）。

### 要件2: 丸めの規則（`js/core/UnitSnapRules.js`）
* ファイル先頭の責務定義（3行以内）：「責務: スナップ（座標・移動量を刻みの倍数へ丸めること。端点への吸い付きとは別）の規則を、状態を持たない関数として提供する。引数を書き換えず新しいオブジェクトを返す。importなし・DOMなし（図形・VectorModel・表示倍率・修飾キーを知らない）。」
* **刻み（`step`）の約束**：正の有限の数値なら丸める。それ以外（`null`＝スナップOFF・`Ctrl`を押している間。ほかの値も同じ扱い）は**丸めない**＝入力と同じ値（`Object.is`で同じ値。`-0`の入力もそのまま）を新しいオブジェクトで返す。非公開のモジュール関数`isRoundingStep(step)`（`typeof step === 'number' && Number.isFinite(step) && step > 0`）で判定する。
* **1つの値の丸め**（非公開のモジュール関数`roundScalarToUnit(value, step)`）：`Math.sign(value) * Math.round(Math.abs(value) / step) * step`。**ちょうど中間の値は0から遠い側へ丸める**（`2.5`→`3`、`-2.5`→`-3`。符号について対称で、同じ入力には常に同じ結果）。結果が`0`（`-0`を含む）なら`0`を返す（`-0`を返さない）。有限の数値を前提とする（`NaN`・`Infinity`は扱わない）。
* **公開する関数**（すべて`export`）：
  * `resolveUnitSnapStep(activeStep, suppressed)` → `number|null`：今効いている刻みと「一時無効か」（呼び出し側が読んだ`Ctrl`の有無）を組み合わせる**唯一の箇所**。`suppressed`が真なら`null`、偽なら`activeStep`をそのまま返す。`InputTracker`と`main.js`（座標の表示）が使う。
  * (a) `roundPointToUnit(point, step)` → `{ x, y }`：軸ごとに独立に`roundScalarToUnit`。
  * (b) `roundDeltaToUnit(delta, step)` → `{ dx, dy }`：軸ごとに独立に`roundScalarToUnit`。
  * (c) `roundConstrainedDeltaToUnit(delta, step)` → `{ dx, dy }`：`MoveDirectionRules.constrainMoveDirection`の結果を、限定した直線の上に保ったまま丸める。丸めないときは入力と同じ値。丸めるとき：`dx`・`dy`とも0なら`{ dx: 0, dy: 0 }`、`dy === 0`なら横＝`{ dx: roundScalarToUnit(dx), dy: 0 }`、`dx === 0`なら縦＝`{ dx: 0, dy: roundScalarToUnit(dy) }`、それ以外は斜め＝`s = roundScalarToUnit((|dx| + |dy|) / 2, step)`（0以上）として`{ dx: Math.sign(dx) * s, dy: Math.sign(dy) * s }`（`-0`は`0`にする）。斜めは`|dx| === |dy|`が厳密に成り立つ（軸ごとに独立に丸めると中間の値で45°が崩れるため(b)とは別の規則。JSDocに理由を書く）。`MoveDirectionRules`をimportしない（入力の形だけを前提にする）。
  * (d) `roundPointFromOriginToUnit(origin, target, step)` → `{ x, y }`：丸めないときは`{ x: target.x, y: target.y }`（`origin + (target − origin)`を計算しない。浮動小数の誤差で今の値と変わらないため）。丸めるときは`d = roundDeltaToUnit({ dx: target.x − origin.x, dy: target.y − origin.y }, step)`として`{ x: origin.x + d.dx, y: origin.y + d.dy }`（`-0`は`0`にする）。基準点が小数の座標でも小数の部分が保たれる（頂点のハンドルが使う）。
* 単位の値（1・10）はこのファイルに書かない（`UnitSnapSettings.js`が唯一の定義箇所）。

* **`handleMouseMove`の`DRAWING`**（置き換え後の形）：

### 要件5: 頂点（ハンドル）の移動（`DRAGGING_HANDLE`）
* **図形クラスの共通メソッド（第17メソッド）**：`getHandlePosition(handleName)` → `{x, y}|null`。`hitTestHandle`が返し得るすべての名前（移動用の`'move'`を含む）に対し、そのハンドルの位置（ワールド座標）を**新しいオブジェクト**で返し、それ以外の名前（`null`・未知の文字列・文字列以外を含む）は`null`。位置は`hitTestHandle`・`drawHandles`と同じ式で求める。既存のメソッド（`hitTestHandle`・`drawHandles`・`setVertex`・`getVertexIndexForHandle`・`draw`等）は変えない。
  * `Line`：`'start'`＝`{x1, y1}`、`'end'`＝`{x2, y2}`、`'move'`＝`{ (x1 + x2) / 2, (y1 + y2) / 2 }`。
  * `Curve`：`'start'`＝`points[0]`、`'control'`＝`points[1]`、`'end'`＝`points[2]`の写し（`getVertexIndexForHandle`の対応と同じ）。
  * `Rect`：`'topLeft'`・`'topRight'`・`'bottomRight'`・`'bottomLeft'`＝`points[0..3]`の写し（`getVertexIndexForHandle`で番号を得て写す）。
  * `Ellipse`：`xc = points[0].x`・`yc = points[0].y`・`rx = Math.abs(points[1].x − xc)`・`ry = Math.abs(points[2].y − yc)`（`hitTestHandle`と同じ式）として、`'move'`＝`{xc, yc}`、`'right'`＝`{xc + rx, yc}`、`'up'`＝`{xc, yc − ry}`、`'left'`＝`{xc − rx, yc}`、`'down'`＝`{xc, yc + ry}`。
  * `Path`：`getVertexIndexForHandle(handleName)`が番号を返せば`points[番号]`の写し、`null`なら`null`（`'move'`は`hitTestHandle`が返さないため`null`）。
  * 5クラスのクラスJSDocの契約の列挙を「17メソッド：…・drawOutline・getHandlePosition」へ改める。
  * **この形を採る理由**：円・弧の左端・下端は`points`の頂点ではない計算上の位置で、`setVertex(1, x, y)`は`y`を、`setVertex(2, x, y)`は`x`を無視し中心からの距離として半径を求める。ハンドルの位置を基準に「位置＋丸めた移動量」を渡せば、左端なら`rx' = |xc − rx + 丸めた dx − xc| = |rx − 丸めた dx|`となり、半径の変化が刻みの倍数になる。`points[頂点の番号]`を基準にすると右端の位置が基準になり、左端のドラッグでは成り立たない。図形種別の知識は各図形クラスに閉じ、`InputTracker`はポリモーフィックに呼ぶだけ（`getVertexIndexForHandle`と同じ）。
* **`InputTracker`**：
  * 作業用フィールド`#unitSnapHandleOrigin = null`（`DRAGGING_HANDLE`を始めた時点のそのハンドルの位置。`{x, y}|null`）。
  * `#beginLeftDrag`：既存の`this.#dragSnap = null;`の直後に`this.#unitSnapHandleOrigin = null;`。`if (nextState === InputState.DRAGGING_HANDLE && target) { … }`の中で、既存の`resolveDragEndpoint`の処理に続けて`const shape = this.model.getShapes().find((s) => s.id === target.shapeId); this.#unitSnapHandleOrigin = shape ? shape.getHandlePosition(target.handle) : null;`（図形がまだ動いていない時点）。
  * `#applyLeftDragUpdate`の`DRAGGING_HANDLE`（置き換え後の形）：
    ```js

    const suppressed = hasCtrlModifier(event);
    let target = { x, y };
    let snap = null;
    if (this.#dragEndpoint) {

        this.#dragSnap = snap;
    ```

  * `#finishLeftDrag`：`this.#unitSnapHandleOrigin = null;`（必ず消す）。
  * 位置が得られない（`null`）ときは丸めずカーソル位置を使う。`Shift`は頂点のハンドルに効かせない。離したときの結合・閉じる（`#onLeftDragEnd`の`joinDraggedEndpoint`）は今までどおり直前の追従の`#dragSnap`で決まる。

### 要件6: `Ctrl`による一時無効のまとめ

## 5. 懸念事項・要確認ポイント
* **計画時の判断と注意**
  * **描き終え・離したときは直前の照会結果で決まる**：直線を描いている途中で端点へ吸い付いた状態で止めてから`Ctrl`を押してクリックすると、結合・描き足しになる（`commitDrawnLine(#drawStartSnap, #drawEndSnap)`はクリック位置で取り直さないため。マウスを動かせば外れる）。端点のハンドルのドラッグも、吸い付いた状態で止めて`Ctrl`を押して離すと結合・閉じるになる（`joinDraggedEndpoint`は直前の追従の`#dragSnap`）。この動きは変えない（REQ要件3・5）。
  * **トラックパッドのピンチ**：ピンチは`ctrlKey`が真の`wheel`として届くため、ドラッグ中のピンチの直後の追従のし直し（`handleWheel` → `#applyLeftDragUpdate`）だけは丸められない位置・端点へ吸い付かない状態になり、次の`mousemove`で戻る（許容。REQ要件6）。
  * **`Ctrl`を押した・離しただけでは反映しない**：作成途中の図形・ドラッグ中の図形・座標の表示は、次にマウスを動かしたとき（または`wheel`）に切り替わる（キーの購読は足さない）。
  * **座標の表示と実際の点が違う場合**：端点へ吸い付いているとき、図形の移動中・ハンドルのドラッグ中（表示はカーソル位置を丸めた値で、移動量の丸め・ハンドルの元の位置を基準にした格子とは一致しないことがある）。
  * **ちょうど中間の値は0から遠い側へ丸める**（`Math.round`の`-2.5`→`-2`の非対称を避け、`f(−v) = −f(v)`にするため）。
  * **小数の部分の保持は浮動小数の誤差の範囲**：小数の座標に整数を足す（`translate`・`origin + d`）ため、`0.1`のような値は`1e-15`程度の誤差を含み得る（今の移動と同じ性質）。
  * **曲線の制御点**：描いたときは始点と終点の中点のまま（丸めない。`.5`になり得る）。
  * **`Rect`の隅のハンドル**：`setVertex`はその隅だけを動かす（矩形を保たない今の約束のまま）。丸めはその隅の移動量に掛かる。
  * **`main.js`の`syncCursorReadout`の`world === null ? null : …`**：位置「なし」の受け渡しで、丸めるかの判定ではない（判定は`getActiveStep`と`resolveUnitSnapStep`）。
  * **`hasCtrlModifier`のexport**：`InputTracker`のクラスの公開APIは増やさないが、モジュールのexportが1つ増える（REQ要件8の「`Ctrl`の読み取りを二重に定義しない」ため）。
  * **単位のボタンの`title`**：文言は`スナップの単位: 1px`／`スナップの単位: グリッド (10px)`。定義は`palette/UnitSnapGroup.js`の`UNIT_TITLE_FORMATS`の1か所で、数値は`UnitSnapSettings`の`unitStep`から作る（単位の値を二重に書かない）。キー`'pixel'`・`'grid'`は`UnitSnapUnit`の値の写し（`palette/`はimportを持たないため）。
