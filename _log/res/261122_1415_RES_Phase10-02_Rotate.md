### 要件A: 円・弧の点の読み方（`shapes/Ellipse.js`）
点の並びと数（`points[0]`＝中心・`[1]`＝右端の制御点・`[2]`＝上端の制御点・`[3]`＝開始角の制御点・`[4]`＝終了角の制御点）、`type`、開始角・終了角の決まり方（`this.startAngle`＝円0・弧π、`this.endAngle`＝2π。`type`から決まり保存しない）、`toJSON`・`fromJSON`は変えない。`u = points[1] − points[0]`、`w = points[2] − points[0]`、輪郭`P(t) = 中心 + u·cos t − w·sin t`（`t`は`this.startAngle`〜`this.endAngle`）。今の約束の位置（`u = (rx, 0)`・`w = (0, −ry)`）では今の読み方と同じ形。`points[3]`・`[4]`は今も読まれず（`P(開始角)`・`P(終了角)`の位置にあたり、変形では一緒に写る）、これからも読まない。

* **typedef`EllipseGeometry`（非公開のJSDoc。exportしない）**：`{ x, y, radiusX, radiusY, rotation, startAngle, endAngle, axisAligned }`。`ctx.ellipse(x, y, radiusX, radiusY, rotation, startAngle, endAngle)`（時計回り。`anticlockwise`は渡さない）にそのまま渡せる値と、縦横に沿った枝で求めたか（`axisAligned`）。
* **`#readGeometry()` → `EllipseGeometry`（形を求める唯一の箇所）**：`c = points[0]`、`ux = points[1].x − c.x`・`uy = points[1].y − c.y`・`wx = points[2].x − c.x`・`wy = points[2].y − c.y`。`TWO_PI = Math.PI * 2`（ローカル）。
    1.  **縦横に沿った枝**（`uy === 0 && wx === 0`）：`radiusX = Math.abs(points[1].x − c.x)`・`radiusY = Math.abs(points[2].y − c.y)`（今の式そのもの）、`rotation = 0`、`axisAligned = true`。開始角・終了角：**円は常に`this.startAngle`・`this.endAngle`**（全周のため向きによらない）。弧は`flipX = ux < 0`・`flipY = wy > 0`で、どちらも偽なら`[this.startAngle, this.endAngle]`（今の値そのもの）、`flipX`だけ→`[π − end, π − start]`、`flipY`だけ→`[−end, −start]`、両方→`[start − π, end − π]`（`start`・`end`は`this.startAngle`・`this.endAngle`。`flipX`・`flipY`は描く向きが逆になる形で、範囲を取り直して時計回りのまま同じ輪郭を描く）、その後に下の「角度の正規化」。結果：今の約束の位置の弧は`[π, 2π]`、左右に裏返した弧も`[π, 2π]`（同じ上半分）、上下に裏返した弧は`[0, π]`（下半分）、両方は`[0, π]`。
    2.  **一般の枝**（それ以外）：`M = [[ux, −wx], [uy, −wy]]`（列が`u`と`−w`）を`M = R(φ)·diag(sx, sy)·R(θ)`に分解する（2×2の閉じた式。計画時にnodeで検算済み）：`E = (ux + (−wy)) / 2`・`F = (ux − (−wy)) / 2`・`G = (uy + (−wx)) / 2`・`H = (uy − (−wx)) / 2`、`Q = Math.hypot(E, H)`・`R = Math.hypot(F, G)`、`sx = Q + R`・`sy = Q − R`、`a1 = Math.atan2(G, F)`・`a2 = Math.atan2(H, E)`、`θ = (a2 − a1) / 2`・`φ = (a2 + a1) / 2`。`radiusX = sx`・`radiusY = |sy|`・`rotation = φ`・`axisAligned = false`。開始角・終了角：円は`this.startAngle`・`this.endAngle`のまま。弧は`sy ≥ 0`なら`[start + θ, end + θ]`、`sy < 0`（裏返った形）なら`[−(end + θ), −(start + θ)]`、その後に「角度の正規化」。
    3.  **角度の正規化**（弧だけ）：`start < 0`の間`start += TWO_PI; end += TWO_PI`、`start >= TWO_PI`の間`start −= TWO_PI; end −= TWO_PI`（開始角を`[0, 2π)`に入れる。差は保つ。今の約束の位置の弧の`π`は動かない）。
    4.  分解の取り方により、同じ形に対して`rotation`・半径の並び（どちらを`radiusX`にするか）・開始角が別の等価な値になることがある（例：45°回した弧は`radiusX`が長いほうの半径になる）。読む側（描画・書き出しの読み手）はどの値でも同じ形を描く。
* **局所座標・輪郭の点・弧の角度（非公開ヘルパ。`#readGeometry`の結果を受ける）**：
    *   `#toLocalPoint(g, x, y)` → `{ x, y }`：`g.axisAligned`なら`{ x: x − g.x, y: y − g.y }`（今の`dx`・`dy`そのもの）。そうでなければ`dx = x − g.x`・`dy = y − g.y`・`cos = Math.cos(g.rotation)`・`sin = Math.sin(g.rotation)`として`{ x: dx·cos + dy·sin, y: −dx·sin + dy·cos }`。
    *   `#pointOnOutline(g, theta)` → `{ x, y }`：`g.axisAligned`なら`{ x: g.x + g.radiusX·Math.cos(theta), y: g.y + g.radiusY·Math.sin(theta) }`（今の式そのもの）。そうでなければ`ex = g.radiusX·cos θ`・`ey = g.radiusY·sin θ`として`{ x: g.x + ex·cosR − ey·sinR, y: g.y + ex·sinR + ey·cosR }`。
    *   弧の角度：`g.axisAligned`なら`Math.atan2(local.y, local.x)`（今の式）、そうでなければ媒介変数の角度`Math.atan2(local.y / g.radiusY, local.x / g.radiusX)`（半径が1以上の枝でだけ呼ぶ）。縦横に沿った枝の範囲の端は0・π・2πの倍数のため、今の角度でも判定が正しい。
* **各メソッド**（今の式・判定順・早期`return`は、`#readGeometry`の値に置き換えるだけで変えない）：
    *   `draw`・`drawHover`・`drawOutline`：`ctx.ellipse(g.x, g.y, g.radiusX, g.radiusY, g.rotation, g.startAngle, g.endAngle)`。円だけ`closePath`。今の約束の位置では呼び出しの引数が今と同じ（回転0）。
    *   `hitTest(x, y, tolerance)`：`g`を読み、`g.radiusX < 1 || g.radiusY < 1`なら`#distanceToOutline(x, y, g) <= tolerance + strokeWidth / 2`。それ以外は`local = #toLocalPoint(g, x, y)`、`value = (lx·lx)/(rx·rx) + (ly·ly)/(ry·ry)`・`r = √value`・`r_avg = (rx + ry) / 2`・`allowedDiff = (tolerance + strokeWidth / 2) / r_avg`（今の平均半径の近似のまま。半径は主軸の半径）。弧は角度`angle`を求め、**`(g.endAngle − 2π, g.endAngle]`へ写して**（`angle <= g.endAngle − TWO_PI`の間`+= TWO_PI`、`angle > g.endAngle`の間`−= TWO_PI`）`angle < g.startAngle`なら`false`。今の約束の位置の弧（`endAngle = 2π`）では`angle <= 0`なら`+2π`・`angle < π`で外れ、今の`if (angle <= 0) angle += 2π; if (angle < startAngle || angle > endAngle)`と同じ判定になる。
    *   `#distanceToOutline(x, y, g)`（非公開。引数を`xc, yc, rx, ry`から`g`へ変える）：サンプル点を`#pointOnOutline(g, θ)`で求める（`θ = g.startAngle + (g.endAngle − g.startAngle)·i/N`）。ほかは今のまま。
    *   `hitTestFill(x, y)`：塗る条件・`rx·rx > 0 && ry·ry > 0`の確認は今のまま（`rx`・`ry`は`g`の半径）。`local`で`(lx·lx)/(rx·rx) + (ly·ly)/(ry·ry) < 1`。JSDocの「回転を入れるときは見直すこと」の注意を、局所座標で判定することに書き換える。
    *   `intersectsRect(minX, minY, maxX, maxY)`：早期棄却の外接矩形の半分の幅・高さは、`g.axisAligned`なら`rx`・`ry`（今のまま）、そうでなければ縦横とも`Math.max(rx, ry)`（回した楕円を必ず含む保守的な値。回した楕円の正確な極値の式を`Ellipse`に持たないため。早期棄却だけに使い結果は変えない）。サンプル点は`#pointOnOutline`。
    *   `toDrawElement()`：`{ kind: 'ellipse', id, x: g.x, y: g.y, radiusX: g.radiusX, radiusY: g.radiusY, rotation: g.rotation, startAngle: g.startAngle, endAngle: g.endAngle, closed: type === 'circle', strokeColor, strokeWidth, fillColor }`（キー順。`rotation`は`radiusY`の後＝`ctx.ellipse`の引数の順）。今の約束の位置では`rotation: 0`で、ほかの値は今と同じ。
    *   `createTransformed(transform)`：`Error`をやめ、`new Ellipse(中心x, 中心y, 中心x, 中心y, this.type, strokeColor, strokeWidth, fillColor)`で作り、`points`を`this.points.map((p) => applyAffineTransformToPoint(transform, p))`で置き換え、`id`を入れる（`Rect`と同じ形。自身と点を共有しない）。Phase 10-01の「上下の裏返しのときに中心を下げる」仮の扱いと`#updatePointsFromRadii`の呼び出しをやめる（`#updatePointsFromRadii`自体は`setVertex`・`updateDraftEnd`が使うので残す）。
* **到達不能の枝（消さない・直さない）**：`drawHandles`・`hitTestHandle`・`getHandlePosition`・`setVertex`・`getVertexIndexForHandle`は今の式のまま（`rx = |points[1].x − xc|`等の今の約束の位置を前提にした式）。JSDocに「選択（`V`）・頂点の選択（`A`）のどちらからも呼ばれない。回した・裏返した円・弧では正しい位置・形にならない（今の約束の位置を前提にした式）」と書き足す。`updateDraftEnd`（描いている途中。回っていない）・コンストラクタも今のまま。
* **JSDoc**：先頭の責務定義（3行以内）に「傾いた楕円・楕円の弧」を足す。クラスJSDoc・`points`のプロパティのJSDocに`u`・`w`の読み方を書く。`ELLIPSE_TYPES`のJSDocの「種別で分岐する全箇所」の列挙を実態に合わせる（`createTransformed`は種別で分岐しなくなる。`#readGeometry`は分岐する）。`fromJSON`の「描画・当たり判定は`points[0..2]`と角度のみに依存」は今のまま正しい。

### 要件B: 弧の読み替え（`shapes/PathJoinRules.js`の非公開`arcChainSourceOf`）
弧の`toJSON()`の値の`points[0]`〜`[2]`から、`xc = center.x`・`yc = center.y`・`ux = right.x − xc`・`uy = right.y − yc`・`wx = top.x − xc`・`wy = top.y − yc`・`k = QUARTER_ELLIPSE_BEZIER_K`。頂点は**始点`P(π) = 中心 − u`・頂上`P(3π/2) = 中心 + w`・終点`P(2π) = 中心 + u`**（`points[3]`・`[4]`は今までどおり読まない）。次の**計算の順のまま**書く（今の約束の位置の弧で今と同じ値になるよう、点を先に求めてから`k`倍のずれを足す）：
* `startX = xc − ux`・`startY = yc − uy`、`apexX = xc + wx`・`apexY = yc + wy`、`endX = xc + ux`・`endY = yc + uy`。
* 区間0：`control1 = { x: startX + k·wx, y: startY + k·wy }`・`control2 = { x: apexX − k·ux, y: apexY − k·uy }`。区間1：`control1 = { x: apexX + k·ux, y: apexY + k·uy }`・`control2 = { x: endX + k·wx, y: endY + k·wy }`。
* 今の約束の位置（`ux = rx`・`uy = 0`・`wx = 0`・`wy = −ry`）では、`xc − rx`・`yc − k·ry`・`xc − k·rx`・`yc − ry`等、今の式と同じ値になる（`yc + k·(−ry)`は`yc − k·ry`と浮動小数で一致し、`+ k·0`は値を変えない）。

* JSDoc（`arcChainSourceOf`・`chainSourceOf`・`lineEndpointOf`・`QUARTER_ELLIPSE_BEZIER_K`）の「左端・頂上・右端」「`rx = |right.x − xc|`」等の記述を、`u`・`w`の読み方（今の約束の位置では左端・頂上・右端）に合わせる。

## 5. 懸念事項・要確認ポイント
* **「`Esc`で中断できるドラッグ」の状態の一覧を`InputModes`に置くこと（計画の設計判断）**：REQの要件4-7（「`Esc`で中断できるドラッグの照会が回転のドラッグでも真」のテスト）は、判定の1か所`InputTracker.isScalingSelection()`が`DragTracker`・DOMに依存してテストを置けないため、そのままでは確かめられない。判定は`InputTracker`の1か所のまま（名前も変えない）、対象の入力状態の一覧だけを値`CANCELABLE_DRAG_STATES`として`InputModes`に置き、テストは一覧の中身と`findCancelableDragBinding`への受け渡しで確かめる。`isScalingSelection()`が一覧を使うことそのものは`node --test`で確かめられない（発注者のテストプレイの6.）。
* **離したときの再描画（計画の設計判断）**：回している間の外枠は`InputTracker`の控え（`getRotationDragView`）から描くため、離した・中断した瞬間に図形の変更通知が無いと、次にマウスを動かすまで傾いた外枠が残る。今の`model.onChange`の経路だけで縦横の外枠に戻すため、離したときは控えを消した後に**今の図形のインスタンスそのもの**を`replaceShapesKeepingIds`へ渡して1回通知する（図形・作業データは変わらず、取り消しは1件のまま）。中断は今の拡大縮小と同じく控えのインスタンスへ戻す差し替えが通知になる（控えを消してから戻す）。機能専用の再描画の経路・新しい通知は足さない。
* **`core/RotationRules → shapes/ShapeGeometry`の`import`文（新しい例外）**：回している間の外枠の角・ハンドルの位置を変換で写すのに、変換の式の唯一の箇所`applyAffineTransformToPoint`を使う（REQの「変換の形は今の箇所を使い写しを作らない」）。`core/`から`shapes/`を`import`文でimportするのは今は`ShapeFactory`だけで、これが2つ目になる（下向きで依存方向は逆転しない・`ShapeGeometry`は何もimportしないため循環しない）。資料1章に例外として明記する。
* **外枠の中心の式を1か所にすること**：回転の中心・辺のハンドルの位置・`Alt`の中心は同じ「外枠の中心」の式`(min + max) / 2`のため、`collectFrameCorners`と同じく`ScaleHandleRules`に`computeFrameCenter`を足して唯一の箇所にし、`collectScaleFrame`の`cx`・`cy`・`computeBoundsScale`（非公開の`readAxis`へ引数で渡す）・`RotationRules.computeRotationCenter`がこれを使う（`RotationRules`に式を写さない）。同じ被演算子に同じ式を当てるだけのため、今の拡大縮小の値は1ulpも変わらない見込み（タスク2で既存のケースがそのまま通ることで確かめる。変わる箇所があればその箇所では使わず、理由をここに追記する）。`readAxis`は非公開のため、引数を足しても公開の名前・ふるまいは変わらない。
* **回した楕円の外接矩形の式は`io/`にだけ持つ**：書き出し・外枠のハンドルの位置に使う回した楕円・楕円の弧の極値は`SpriteSerializer.ellipseRange`（描画要素の値だけから求める。`io/`は`shapes/`をimportできないため）。`Ellipse.intersectsRect`の早期棄却は正確な極値を求めず、回した形では`max(rx, ry)`の保守的な矩形を使う（式を二重に持たないため。結果は変わらない）。
* **分解の取り方で`rotation`・開始角が等価な別の値になる**：`#readGeometry`の一般の枝は2×2の特異値分解の閉じた式で、同じ形でも「どちらの半径を`radiusX`にするか」「`rotation`」「開始角」が直感と違う等価な値になることがある（例：45°回した弧は長いほうの半径が`radiusX`で`rotation`が−45°）。描画・書き出しの見た目は同じ。テストは輪郭の点と半径の組で比べる（要件I）。
* **弧の角度の判定**：縦横に沿った枝（今の約束の位置・裏返し）は今の`atan2(dy, dx)`、一般の枝は媒介変数の角度`atan2(ly / ry, lx / rx)`。一般の枝で`rotation`がちょうど0になる形（例：90°回した弧。`#readGeometry`の値が`rotation` 0・開始角3π/2）も、`axisAligned`が偽のため媒介変数の角度で判定する（範囲の端が軸の上に無いため。これを`rotation === 0`で分けると誤る。計画時にnodeの試作で確かめた）。
* **90°の倍数のちょうどの値**：`toRotationTransform`は角度が90°の倍数から`1e-9`ラジアン以内ならちょうどの`cos`・`sin`を使う（`Shift`の90°・180°で矩形等の座標に`1e-16`程度の誤差を入れないため）。`1e-9`ラジアン以内の回転が90°の倍数に寄るのは見た目に影響しない。
* **左右に裏返した弧・裏返した円の`points`**：5つの点をそのまま写すため、裏返した円・弧の`toJSON()`の`points[1]`〜`[4]`は約束の位置にそろえ直されない（見た目・描画要素は同じ）。既存のテストの期待値の変更(d)-1に列挙した。左右に裏返した弧は、結合したときの始点が右側（弧の描く向きの始点）になる。`fromJSON`で`points[1]`を中心より左・`points[2]`を中心より下に置いた弧も点のとおりに裏返った弧として読むため、その端点を確かめる既存のテスト1件の期待値が変わる（(d)-3）。エディタはこの形を作らず、版2のファイルは版2→3の変換で約束の位置にそろうため、今あるデータの見た目は変わらない。
* **版2→3の変換の`points[3]`・`[4]`**：REQの現場設計の決定（REQ:60）どおり、`points[3]`・`[4]`も今の約束の位置（エディタが今作る円・弧の位置：`points[4]`＝右端、`points[3]`＝円は右端・弧は左端）にそろえる。今あるデータの値を変えないため、右端・上端と同じく、すでに約束の位置にあるものは値をそのまま写す（計算し直さない）。`points[4]`と円の`points[3]`は右端の値を写す（エディタが作ったデータでは右端とちょうど同じ値のため変わらない）。弧の`points[3]`（左端）は、エディタが半径から`xc − rx`で求めるため`c.x − |右端.x − c.x|`と数ulpずれ得るので、比`1e-9`の許容量で「約束の位置にある」と判定して値をそのまま写す（許容量の外＝手で書いた値だけを`(c.x − rx, c.y)`にする）。これにより、版1の弧の`points[3]`が約束の位置にない既存のテストの期待値が変わる（要件Iの(d)-4）。`points[3]`・`[4]`は版2・版3のどちらの読み方でも形に効かないため、見た目は変わらない。
* **到達不能の枝**：`Ellipse`の`drawHandles`・`hitTestHandle`・`getHandlePosition`・`setVertex`・`getVertexIndexForHandle`は今の約束の位置を前提にした式のまま（回した円・弧では正しくない旨をJSDocに書く）。Phase 10-01で残した`PressActionRules`の`dragHandle`・`CursorShapeRules`の(7)・各図形の`drawHandles`・`CanvasManager.render`の`showHandles`も消さない（去就はPhaseのクローズ）。
* **回転の範囲の上のホバー**：回転の範囲の上でも、下にある図形の本体のホバーの強調は今のまま出る（押せば回転が優先され、カーソルは回転のカーソル）。スポイトの待ち受け中は外枠は出たままだが押下は何も始めず、カーソルは`'cell'`（(3a)が(3c)より前）。
* **幅0の外枠の角の名前**：水平・垂直な直線では同じ位置の角が2つずつ重なり、並びの先（上端・左端は`nw`、下端・右端は`se`。高さ0の外枠では左端`nw`・右端`ne`）の向きのカーソルになる。
* **色の欄のピッカー操作中の回転**：拡大縮小と同じく、ピッカーを開いたまま（確定前に）回すと、その色の変化は記録されず捨てられる（3章13.の「確定前に他の操作が起きた場合」と同じ種類。対処しない）。色の欄にフォーカスがある間は、回転のドラッグ中でも`Esc`で中断しない（今の`Esc`と同じ）。
* **OSが使う修飾キー付きの`Esc`**：Windowsでは`Ctrl`+`Esc`・`Alt`+`Esc`等をOSが先に使い、ページに`keydown`が届かないことがある。その場合はウィンドウのフォーカスが外れ、`DragTracker`のblurの中断で同じく引き始めの形に戻る。
