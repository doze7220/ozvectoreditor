*   **SoloVisibilityRules.js**：その行だけの表示（目の`Alt`＋クリック）の見分け・次の表示の値・覚える内容を求める規則`resolveSoloToggle`を、状態を持たない関数として提供する（Phase 11-05で新設。記憶の持ち主は`edit/ItemStateEditor`＝`14_edit.md`、流れは`PROJECT_ARCHITECTURE.md`3章28.）。
    *   **公開**：`resolveSoloToggle({ items, id, memory = null })`と、typedef`SoloDisplay`・`SoloMemory`。
    *   **typedef**：`SoloDisplay`＝`{ visibleById: Map<string, boolean>, knownIds: Set<string> }`（1回の「その行だけ」にした直後の控え。`visibleById`＝その時点で覚えている行（今ある行だけ）の、直後の値、`knownIds`＝その時点の全部の行のid）。`SoloMemory`＝`{ visibleById: Map<string, boolean>, displays: SoloDisplay[] }`（`visibleById`＝覚えている行の、はじめの前の値、`displays`＝はじめから今までの控え。古い順）。
    *   **行ごとの目標の値**（非公開`buildTargets`）：その行と上のフォルダは`true`、その行と上のフォルダそれぞれの兄弟は`false`（`ItemPlaceRules.findItemLocation`の`siblings`・`ancestorIds`から）。その行の中のもの・兄弟の中のもの・非表示にしたフォルダの中のものは入らない（値を変えない）。行が無ければ`null`。
    *   **今の表示に当たる控え**（非公開`findMatchingDisplay`）：`displays`のうち、`memory.visibleById`にある今ある行のすべてで、今の値（`ItemStateRules.listItemStates`の自分の表示`visible`）が「控えの`visibleById`の値（控えに無い行は`memory.visibleById`の値）」と同じもの。複数あれば最後のもの。覚えている行が1つも今無い・当たるものが無い・`memory`が無いなら`null`。取り消しで前の「その行だけ」に戻ったときは、その前の控えに当たる。
    *   **その行だけの表示か**（非公開`isSoloDisplay`）：目標の値が今の値とすべて同じ。当たる控えがあるときは、目標が`false`の行のうちその控えの`knownIds`に無いもの（その後に増えた行）を見ない。
    *   **`resolveSoloToggle({ items, id, memory })`** → `{ changes: Array<{ id, visible }>, memory: SoloMemory|null }`：`changes`は今の値と違うものだけ（`ItemStateEditor`が`setItemStates`へ渡す）。次の順に決める。
        1.  行が無ければ`{ changes: [], memory }`。
        2.  `id`が「その行だけの表示」のとき（`memory`はそのまま返す）：覚えている表示が使える（当たる控えがある、または`id`の目標の行がすべて`memory.visibleById`にある）なら、`memory.visibleById`のうち今ある行を元の値へ戻す。**戻すものが無ければ`changes`は空**（何も起きず、履歴にも入らない）。使えない（覚えている表示が無い、または`id`に要る分が無い）なら、全部の行を表示にする（入れ子の中の非表示も表示になる）。
        3.  それ以外：`id`の目標の値にする。当たる控えがあれば記憶を保って継ぎ足し、無ければ（間に目の切り替え・取り消し等で、どの控えとも違う表示になっている）新しく始める。新しい`memory`＝`{ visibleById: (保つなら今までのもの) に、まだ無い目標の行の今の値を足したもの, displays: (保つなら今までのもの) の末尾に今回の控えを足したもの }`。
    *   **契約**：引数（`memory`を含む）は書き換えない。戻す・変えるのは自分の表示`visible`だけで、ロックには触れない。
    *   **読むもの**：渡された入れ子の`kind`・フォルダの`id`・`children`と、`itemIdOf`の結果、`ItemStateRules.listItemStates`の自分の表示だけ。図形のほかのプロパティを読まない。
    *   **知らないこと**：DOM・`VectorModel`・図形クラス・図形種別・選択・折りたたみ・描き込む先・操作モード・履歴。状態を持たない（記憶の持ち主は`edit/ItemStateEditor`）。importは`core/GroupTreeRules`（`itemIdOf`）・`core/ItemPlaceRules`（`findItemLocation`）・`core/ItemStateRules`（`listItemStates`）のみ。
    *   **使う側**：`edit/ItemStateEditor.toggleSolo`だけ（結果の`changes`が空なら何もせず記憶も変えない。空でなければ記憶を置き換えてから1件の編集として`setItemStates`する）。記憶は保存しない・履歴の対象にしない・取り消し／やり直しで変わらない（次の`Alt`＋クリックで、今の表示に当たる控えを値から探すため）。忘れるのはキャンバスの切り替え（`forgetSolo`）だけ。
    *   **置き場所の理由**：「その行だけの表示」の見分けと戻し方は、行・兄弟・上のフォルダの関係と覚えている値から決まる複雑な規則で、手順（`ItemStateEditor`）・配線（`ItemListWiring`）に置けず、`node --test`で確かめるため、状態を持たない関数として`core/`に置いた。循環は無い（`GroupTreeRules`・`ItemPlaceRules`・`ItemStateRules` ← `SoloVisibilityRules`）。
    *   **注意**：もう一度押しても何も変わらない（`changes`が空で、履歴にも入らない）のは、その行が「その行だけの表示」で、覚えている表示が使え、かつはじめの前の表示が今の表示と同じ（戻すものが無い）ときだけ。例：いちばん外側の行Aだけが表示の絵で、ほかの外側の行Bを押してからAを押すと、Aだけの表示（はじめの前と同じ）になり、Aをもう一度押しても何も変わらない（外側の行を挟んだ場合は、覚える値が外側の行だけでAの表示と同じに戻るため）。フォルダの中の行を挟んだ場合は、その兄弟のはじめの値も覚えるため違う：外側の行Aが表示でフォルダGが非表示、Gの中のXを押してからAを押すと、Aを押した後もXは表示のままで、Aをもう一度押すとXの兄弟Yがはじめの値へ戻り、履歴に1件入る（`test/edit/VisibilityAndLock.flow.test.js`の確認項目10の2件）。覚えている表示が無いときは、この押し直しで全部の行が表示になる。上のフォルダを押したときも、はじめの前の表示へ戻る。「その行だけ」にした後に描いた図形は、兄弟でも「間に表示が変わった」とみなさない（増えた行はそのまま）。兄弟の無い行をはじめからその行だけの表示のまま、覚えている表示無しで押すと、全部の行が表示になる（取り消し1回で戻る）。手で目を切り替えて控えと同じ表示に戻したときは、値からは区別できず、控えに当たるとみなす。
