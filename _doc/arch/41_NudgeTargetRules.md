*   **NudgeTargetRules.js**：矢印キーの微調整で動かす対象（図形の組／頂点の組）の決定と、続けた微調整を取り消し1件にまとめるための「まとめの鍵」の組み立てを、状態を持たない関数として提供する（Phase 08-03で新設。流れは3章19.）。
    *   **公開**：`resolveNudgeTarget(mode, selectedIds, selectedVertices)` → `NudgeTarget`（`{ type: 'shapes', shapeIds }`または`{ type: 'vertices', vertices: [{ shapeId, handle }] }`）または`null`。`buildNudgeGroupKey(target)` → 文字列または`null`。typedef`NudgeTarget`。
    *   **`resolveNudgeTarget`**：`mode`が`OperationMode.SELECT`で図形の選択が1つ以上なら`shapes`、`OperationMode.VERTEX`で頂点の選択が1つ以上なら`vertices`、それ以外（`CREATE`・`PAN`・未知のモード・選択なし）は`null`。**モードに対応しない側の選択は見ない**（`VERTEX`で図形だけ選んでいて頂点が0件なら`null`。`SELECT`で頂点の選択が残っていても見ない）。並びは与えられた順のまま。引数を書き換えず、毎回新しい配列・オブジェクトを返す。
    *   **`buildNudgeGroupKey`**：対象が`null`なら`null`、そうでなければ対象の`JSON.stringify`。同じ対象（種類・図形の並び・頂点の並び）を続けて動かしたときだけ同じ鍵になる。区切り文字を自前で決めないのは、図形のidの形・ハンドル名の文字（`-`等）を知らないまま文字の衝突を起こさないため。鍵の約束（畳む条件・往復で消える・鍵を忘れる契機）は`HistoryManager`側（`_doc/arch/08_HistoryManager.md`）。
    *   **読むもの**：渡された配列と`InputModes`の`OperationMode`だけ。importは`core/InputModes`のみ。頂点の位置・頂点インデックスは求めない（図形を知らないため。`edit/NudgeEditor`が求める）。ハンドル名は文字列として運ぶだけ。
    *   **知らないこと**：DOM・`VectorModel`・図形クラス・図形種別・図形固有のプロパティ名・履歴・表示倍率・スナップの設定・移動量。
    *   **使う側**：`edit/NudgeEditor`（`nudge`の手順①②）と`edit/PositionInputEditor`（位置の数値入力の対象の決定。Phase 08-04）と`edit/TransformInputEditor`（幅・高さ・角度・反転の対象の決定。`resolveNudgeTarget`だけ。Phase 10-03。3章27.）と`core/VertexTargetRules`（頂点の選択から`{ shape, vertexIndex }`を集める唯一の箇所。`resolveNudgeTarget`だけ。`'vertices'`のときだけ使う。Phase 12-02。`edit/PathCornerEditor`・`edit/PathVertexEditor`・`edit/PathSplitEditor`はこの規則を通して間接に使い、`NudgeTargetRules`を直接importしない。`PathCornerEditor`・`PathVertexEditor`は、Phase 09-02a・09-02b・12-01の時点では`#collectTargets`で直接使っていたが、Phase 12-02で`VertexTargetRules`へ替えた。`core/`内の規則どうしのimportは一方向＝`VertexTargetRules → NudgeTargetRules`）。`main.js`・`KeyboardShortcuts`は使わない。
    *   **置き場所の理由**：対象の決定は操作モードの知識を要し、`edit/`は操作モードを知らない約束のため`edit/`には置けない。`main.js`は判定を持たず、`InputTracker`は矢印キーの経路に関わらない。そこで状態を持たない規則として`core/`に置いた（`edit/NudgeEditor`は`getMode`の戻り値を解釈せずこの規則へ渡すだけ）。`edit/`から`core/`をimportする最初の例だが、`main.js → edit → io → core → shapes`の下向きに沿い、循環しない。
    *   **テスト**：`test/core/NudgeTargetRules.test.js`（16件。`resolveNudgeTarget`＝各モードと選択の組合せ・対象なし・並びを保つ・引数を書き換えず新しい値を返す、`buildNudgeGroupKey`＝`null`・同じ内容で同じ鍵・並びや種類やハンドル名の違いで別の鍵・区切り文字を含むid／ハンドル名でも衝突しない）。
