*   **ItemListRules.js**：図形の一覧の行の操作（押す・カーソルを置く・名前の編集・行のドラッグ・三角）の判定を、状態を持たない関数として提供する（Phase 11-02で新設。Phase 11-03で`canSetInsertTargetByRow`・`canStartRowDrag`・`shouldSelectPressedRow`を追加。Phase 11-04aで、行の並び`buildItemRows`を`ItemRowRules`（`61_ItemRowRules.md`）へ移し、`canToggleGroup`を追加し`canStartRowDrag`に`hasGroups`を足した。流れは`PROJECT_ARCHITECTURE.md`3章28.）。
    *   **公開**：`ROW_PRESS_ACTION`・`resolveRowPressAction`・`isListLocked`・`ROW_HOVER_ACTION`・`resolveRowHover`・`isOwnHover`・`canStartNameEdit`・`resolveNameEditKey`・`canSetInsertTargetByRow`・`canStartRowDrag`・`shouldSelectPressedRow`（後ろ3つはPhase 11-03）・`canToggleGroup`（Phase 11-04a）。Phase 11-04aで`buildItemRows`とtypedef`ItemRow`は`ItemRowRules`へ移した（`ItemListRules`はもう行の並びを作らない）。
    *   **`buildItemRows`（Phase 11-04aで`ItemRowRules`へ移した）**：行の並びは`core/ItemRowRules.buildItemRows`（フォルダも行にし、折りたたんだフォルダの中身は行にしない。`61_ItemRowRules.md`）。この規則は行の並びを作らず、渡された行のidと状態だけで判定する。
    *   **`resolveRowPressAction({ mode, isPicking, isDragging, isLocked })`**：行を押したときの動作`ROW_PRESS_ACTION`（`none`・`select`・`switchAndSelect`。凍結）。上から、ロック中または`isDragging`なら`none`／`isPicking`（スポイトの待ち受け中）なら`switchAndSelect`／選択・頂点の選択なら`select`／キャンバス移動なら`switchAndSelect`／それ以外（図形作成・未知の値）は`none`。`switchAndSelect`は呼び出し側が選択ツールへ切り替えてから、修飾キーによらずふつうのクリックとして選ぶ。`none`は何もしない（ツール・選択・引いている途中の線に触れない）。
    *   **`isListLocked({ loading, busy })`**：`canvasLibrary.getState()`の`loading`または`busy`が真ならロック中。`loading`は起動時だけ真で、キャンバスの切り替え中は`busy`が真になる（キャンバスの名前の変更・削除の間も`busy`のため、その短い間も一覧の操作を受け付けない。切り替えと区別する照会が無く、区別を足していない）。
    *   **`resolveRowHover({ id, hoveredRowId, hoveredId, isDragging, queryLocked, queryExists })`**：行へのカーソルの動きに対するホバーの扱い`ROW_HOVER_ACTION`（`none`・`record`・`set`・`clear`。凍結）。上から、`id`が`null`なら`clear`／`id`が`hoveredRowId`とも`hoveredId`とも同じなら`none`／`isDragging`が真、またはロック中なら`clear`／`id`が`hoveredId`と同じ（記録だけが違う）なら`record`／そのidの図形が今あれば`set`／なければ`clear`。`queryLocked()`・`queryExists(id)`は照会の関数で、その行まで進んだときだけ呼ぶ（`isDragging`が真なら`queryLocked`も呼ばない。同じ行の上の`mousemove`では2.で終わり、照会が走らない）。`record`があるのは、今のアプリがカーソルがキャンバスの外へ出てもホバーを消さないため、キャンバスで出たホバーの図形の行に最初に乗ることがあり、その行から外れたときにも消えるようにするため。
    *   **`isOwnHover(hoveredRowId, hoveredId)`**：`hoveredRowId`が`null`でなく`hoveredId`と同じなら真（一覧が出したホバーか。キャンバス側が出したホバーを消さないための判定）。
    *   **`canStartNameEdit({ isDragging, isLocked, hasModifier })`**：`!isDragging && !isLocked && !hasModifier`。`Ctrl`・`Shift`を押したままのダブルクリックでは始めない（2回のクリックが追加・解除／範囲選択の操作であるため。計画での判断）。操作モードは見ない（どのツールでもできる）。
    *   **`resolveNameEditKey(key, isComposing)`**：名前の欄のキー。変換中は`null`、`Enter`は`'commit'`、`Escape`は`'cancel'`、それ以外は`null`。`ItemListPanel`へコールバックとして注入される（パネルは`Enter`・`Escape`の意味を知らない）。
    *   **`canSetInsertTargetByRow({ mode, isPicking, isDragging, isLocked })`**（Phase 11-03）：描くツール（作成モード）で行を押したとき、描き込む先を変えてよいか。作成モードで、スポイトの待ち受け中・ドラッグ中・ロック中でないときだけ真（`mode === OperationMode.CREATE && !isPicking && !isDragging && !isLocked`）。`resolveRowPressAction`は既存のテストが作成モード＝`none`を確かめているため変えず、`ItemListWiring.#handleRowClick`が`none`のときだけこちらを見て、真なら`model.setInsertTarget(id)`を呼ぶ（決まるのは行のクリック＝離したとき。`Ctrl`・`Shift`は読まない）。
    *   **`canStartRowDrag({ button, hasModifier, isEditingRow, isDragging, isLocked, hasGroups = false })`**（Phase 11-03。`hasGroups`はPhase 11-04a）：行のドラッグを始めてよいか。左ボタン（`button === 0`）で、`Ctrl`（`⌘`）・`Shift`なし（`hasModifier`は呼び出し側が求める）・編集中の行でない（名前の欄は編集中の行にしか無いため、欄の中の押下も含む）・キャンバスの左ドラッグ／パン中でない（`isDragging`）・ロック中でない・**フォルダが無い絵**（`hasGroups`が偽。省けば偽＝今までどおり）のときだけ真。フォルダのある絵では行のドラッグ（並べ替え）を始めない（今回手を付けない操作。行の並びはフォルダの行を含み、`ListDragRules`・`ItemListRowDrag`は図形だけの並びを前提にするため。呼び出し側`#handleRowPress`が`hasGroupItem(model.getItems())`を渡す）。**操作モードは見ない**（描くツール・`H`・スポイト待ち受け中でも始められる）。
    *   **`shouldSelectPressedRow({ mode, isPicking, isSelected })`**（Phase 11-03）：行のドラッグが始まったとき、押した行を選ぶか。選択・頂点の選択モードで、スポイトの待ち受け中でなく、押した行が選ばれていないときだけ真。それ以外（描くツール・キャンバス移動・待ち受け中・既に選ばれている行）では選択を変えない。
    *   **`canToggleGroup({ isDragging, isLocked })`**（Phase 11-04a）：フォルダの行の三角（折りたたみ・開く）を押してよいか。`!isDragging && !isLocked`。選択・操作モードは見ない（どのツールでもできる）。呼び出し側`ItemListWiring.#handleGroupToggle`が真のときだけ`model.setGroupCollapsed`を呼ぶ。
    *   **読むもの**：渡された値だけ（`ROW_PRESS_ACTION`等は`mode`・フラグ、`resolveRowHover`は`id`と照会の関数）。importは`core/InputModes`（`OperationMode`）のみ（Phase 11-04aで`core/ItemTreeRules`のimportをなくした）。
    *   **知らないこと**：DOM・`VectorModel`・`InputTracker`・`CanvasLibrary`・図形のプロパティ・図形種別。状態を持たない。
    *   **使う側**：`wiring/ItemListWiring`だけ（`ItemListPanel`には`resolveNameEditKey`が注入される。`canToggleGroup`は`#handleGroupToggle`、`canStartRowDrag`は`#handleRowPress`、`shouldSelectPressedRow`は`ItemListRowDrag`への注入の中、`canSetInsertTargetByRow`は`#handleRowClick`が呼ぶ）。
    *   **置き場所の理由**：行の操作の判定を`wiring/`（判定を持たない）にも`palette/`（何もimportしない）にも置けず、`node --test`で確かめるため、状態を持たない関数として`core/`に置いた。
