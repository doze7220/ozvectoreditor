*   **wiring/ItemListRowDrag.js**：図形の一覧の行のドラッグ（並べ替え）の進行（押下・閾値・移動・離す・取りやめ・自動スクロールの毎フレーム）のみを担う（Phase 11-03で新設。クラス`ItemListRowDrag`。流れは`PROJECT_ARCHITECTURE.md`3章28.）。判定・計算は`core/ListDragRules`へ渡し、結果をパネル・注入された関数へ渡すだけ。図形・選択・履歴・操作モードは知らない。
    *   **公開**：コンストラクタ`({ panel, getRowIds, isSelected, shouldSelectPressedRow, selectRow, applyOrder, onDragStart })`と、`press(id, event, canStart)`・`cancel()`・`cancelIfRowsChanged()`・`isActive()`・`isMoving()`・`consumeSuppressedClick()`・`refresh()`。`ItemListWiring`だけが生成して持つ（`wiring/`内のimportと、`wiring/`が`core/`の状態を持つ部品（`DragTracker`）を生成して持つのは今回が初めて）。
    *   **コンストラクタ**：注入を控え、`DragTracker`を1つ持つ（`new DragTracker((event) => ({ x: event.clientX, y: event.clientY }))`＝クライアント座標。コードは変更せず使い回す）。`window`のcaptureの`mousedown`を登録し、行のドラッグ中（`isActive()`の間）の押下を`preventDefault()`＋`stopPropagation()`で止める（キャンバスの中ボタンのパン等を始めさせない。`InputTracker`に状態・照会を足さないため）。それ以外では何もしない。
    *   **注入するもの（`ItemListWiring`）**：`panel`（`ItemListPanel`。`setDraggedRows`・`showDropMark`・`getListArea`・`setScrollTop`）・`getRowIds()`（今の行の並び＝`buildItemRows(model.getItems())`のid）・`isSelected(id)`・`shouldSelectPressedRow(id)`（`ItemListRules.shouldSelectPressedRow`へ操作モード等を渡す）・`selectRow(id)`（`model.setSelectionByUser([id])`・起点の更新・`sync({ allowScroll: false })`）・`applyOrder(orderedIds)`（`main.js`の`shapeOrderEditor.applyOrder`）・`onDragStart()`（自分の出したホバーを消す）。`VectorModel`・`InputTracker`・`HistoryManager`・操作モードを知らない。
    *   **`press(id, event, canStart)`**：必ず先に`clearSuppressedClick()`。`canStart`（`canStartRowDrag`の結果）が真なら`DragTracker.begin`（閾値3px＝キャンバスと同じ値をファイル内の定数で持つ・`suppressClick: 'whenMoved'`）。
    *   **進行**：`onStart`（閾値を超えたとき。押した行が行の並びに無ければ取りやめ）→ 行の並びを控える → `onDragStart()` → `shouldSelectPressedRow(id)`が真なら`selectRow(id)` → `resolveDraggedIds`（選ばれている行の再計算は`isSelected`で）→ `panel.setDraggedRows` → 自動スクロールの`requestAnimationFrame`を始める。`onMove`・`refresh()`（一覧のスクロール時）・毎フレームは、最後のポインター位置から`resolveDropIndex` → `resolveDropMark` → `panel.showDropMark`（毎フレームは先に`resolveAutoScrollTop`で`panel.setScrollTop`）。`onEnd`は、始まっていなければ何もしない（続く`click`は今までどおり）。始まっていれば、後始末（表示と控えと`requestAnimationFrame`）を**先に**行い、`isSameOrder(控えた並び, 今の並び)`が偽なら何もせず、ドロップ位置が`null`なら何もせず、そうでなければ`applyOrder(toDrawOrder(reorderRowsForDrop(…)))`。
    *   **取りやめ**：`cancel()`は`DragTracker.cancel({ suppressClick: true })`（`onCancel`で後始末だけ）。押している間（閾値以前を含む）なら真を返す。始まる前の`Esc`も同じ（キャンバスの拡大縮小・回転の`Esc`と同じ範囲）。`cancelIfRowsChanged()`は、始まっていて行の並びが控えと違えば取りやめる（`ItemListWiring.sync`の先頭から呼ばれる）。
    *   **照会**：`isActive()`（押下から。閾値以前を含む）・`isMoving()`（始まった後）・`consumeSuppressedClick()`（終わった直後の`click`を無視すべきなら抑止を解いて真）。
    *   **持つ値（すべて一時的。保存・履歴・作業データ・書き出しに入れない）**：`DragTracker`・押した行のid・始まった時点の行の並び（`null`なら始まっていない）・動かす行のid・最後のポインター位置・`requestAnimationFrame`のID・前のフレームの時刻。
    *   **import**：`core/DragTracker`・`core/ListDragRules`。`palette/ItemListPanel`は型の参照だけ。`core/VectorModel`・`core/InputTracker`・`edit/`・`io/`はimportしない。
    *   **知らないこと**：判定・計算（`ListDragRules`・`ItemListRules`）・DOMの更新の中身（`ItemListPanel`）・図形・選択集合・履歴・操作モード。並べ替えの記録は`applyOrder`（`ShapeOrderEditor`）の側。
    *   **キャンバスのドラッグと同時に始まらない**：始めるときは`canStartRowDrag`が`inputTracker.isDragging()`（`ItemListWiring`の`isDragging`）を見る。逆向き（行のドラッグ中のキャンバスの中ボタンのパン等）は上の`window`のcaptureの`mousedown`で止める。
    *   **使う側**：`wiring/ItemListWiring`だけ。`Esc`・ショートカットの照会は`ItemListWiring.isRowDragging()`・`cancelRowDrag()`を通る。
    *   **置き場所の理由**：押下から離すまでの進行・`requestAnimationFrame`・取りやめの購読を持つため、`core/`の規則にも`palette/`にも置けない。`ItemListWiring`に書くと橋渡しだけという役割を超えるため、行のドラッグだけを切り出した`wiring/`の部品にした。
    *   **テスト**：なし（DOM・`requestAnimationFrame`・`window`の購読。`_doc/arch/16_test.md`の「テストできない箇所（11-03の追加）」）。判定・計算は`ListDragRules`・`ItemListRules`に出してあり、テストプレイで確かめる。
