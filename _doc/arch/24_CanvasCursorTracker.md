*   **CanvasCursorTracker.js**：キャンバス上の最後のカーソル位置（スクリーン座標。キャンバスの外なら「なし」）と、その`mousemove`で`Ctrl`が押されていたかの保持と変更通知のみを担う（Phase 07-03で新設。キャンバスの`mousemove`・`mouseleave`の購読を含むため、`InputTracker`へは入れず分けた。`Ctrl`の保持はPhase 07-05で足した）。
    *   **公開メソッド**：`constructor(canvas, { getScreenPoint, screenToWorld, readCtrlModifier })`・`getScreenPosition()`（`{x, y}`のコピーまたは`null`。定規の印に使う）・`getWorldPosition()`（呼んだ時点の`screenToWorld`の結果または`null`。ステータスバーの座標に使う。ビュー変換が変わった後に呼べば、最後のカーソル位置から求め直した値になる）・`isCtrlPressed()`（最後の`mousemove`で`Ctrl`が押されていたか。位置が「なし」なら偽。Phase 07-05）・`onChange(callback)`（関数以外は無視）。
    *   **注入**：`getScreenPoint`・`screenToWorld`が関数でなければ`Error`。`main.js`が`(event) => inputTracker.getScreenCoordinate(event)`と`(x, y) => viewTransform.screenToWorld(x, y)`を渡す（スクリーン座標の求め方・変換を二重に書かない）。**省略可の`readCtrlModifier`**（`(event: MouseEvent) => boolean`。Phase 07-05）：省略時（`undefined`）は常に偽。指定されていて関数でなければ既存の2つと同じく`Error`。実体は`main.js`が注入する`InputTracker.js`の`hasCtrlModifier`（`Ctrl`（`⌘`を含む）の読み取りの唯一の定義。二重に書かない）。
    *   **契約**：`mousemove`で位置と`Ctrl`の状態（`Boolean(readCtrlModifier(event))`）を記録し、**位置も`Ctrl`の状態も前と同じなら通知しない**（どちらかが前と違うときは両方を記録して通知する。位置が同じで`Ctrl`だけ変わったときも通知する）。`mouseleave`で位置を「なし」にして`Ctrl`の状態も偽に戻し、前が「なし」でなければ通知する（前が「なし」なら何もしない）。ページを開いた直後（まだ`mousemove`が無い）は「なし」・`Ctrl`は偽。
    *   **動き（実コードで確認済み）**：ドラッグ中・パン中もキャンバス要素の`mousemove`は発火するため、カーソルがキャンバスの上にある間は追跡が続く（パン中は`DragTracker`のwindowのcaptureの`mousemove`が先、続いてキャンバスの`mousemove`が来るため、1回の移動の後の表示は正しい値になる）。ドラッグのままツールバー・定規・ステータスバー・フロートウィンドウの上へ出るとキャンバスの`mouseleave`で「なし」になり、ドラッグ自体は`DragTracker`が続ける。フロートウィンドウはキャンバスの祖先ではない兄弟要素のため、キャンバスからウィンドウへ移ると`mouseleave`で「なし」になる。読み込み中は覆い要素がキャンバスの上にあり`mousemove`が来ないため「なし」のまま。**`Ctrl`は`mousemove`のイベントでだけ読む**（キーの購読は足さない）ため、マウスを動かさずに`Ctrl`を押した・離しただけでは通知されず、座標の表示は次の`mousemove`で切り替わる。
    *   **使う側**：`main.js`（`renderRulers`と`syncCursorReadout`を`cursorTracker.onChange`へ登録。座標の表示は`viewTransform.onChange`・`unitSnapSettings.onChange`でも求め直す）。`syncCursorReadout`は`getWorldPosition()`と`isCtrlPressed()`から、スナップがONで`Ctrl`が押されていなければ丸めた座標を表示する（3章15.・17.）。通知はキャンバス全体を再描画せず、更新するのは定規とステータスバーの座標の文字だけ。`Ctrl`の状態だけが変わった通知でも`renderRulers`は呼ばれるが、定規は位置から毎回描くため結果は同じ。
    *   **知らないこと**：`VectorModel`・`ViewTransform`・図形・`InputTracker`・スナップの設定・丸めの規則（importしない。必要な関数は注入）。`Ctrl`が何の意味を持つか（丸めの一時無効）を知らず、押されていたかの真偽値を保持して返すだけ。
    *   **注意**：ホバーの強調がキャンバスの外で残る件（カーソルがキャンバスの外へ出ても`InputTracker`のホバーは解除されない）は変えていない。
    *   **テスト**：対象外（`canvas`を購読するためテストプレイで確かめる）。
