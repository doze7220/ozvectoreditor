*   **palette/** : ツールバー・カラーピッカー等のUI部品。
    *   **PaletteController.js** : 図形選択パレット（図形種別一覧に対応するボタン）の配線を担う自己完結UI部品。`constructor(paletteRootElement, shapeTypes, onTypeSelected)`で、図形種別一覧`shapeTypes`（正本は`ShapeFactory.js`の`SHAPE_TYPES`。`main.js`が注入）と、図形種別選択時に呼び出す汎用コールバック`onTypeSelected(type)`（`main.js`側の`applyShapeType`）を受け取る。importは持たず、`InputTracker`・`ShapeFactory`へ直接依存しない。各種別のボタンをid規則`palette-${type}`で解決して配線する。照合はコンストラクタ実行時の1回のみで、ルート要素内の`[id^="palette-"]`要素だけを対象とし、①種別一覧にあるのにボタンが見つからない種別、②ルート要素内にあるのに種別一覧にない`palette-`要素を、いずれも`console.warn`で報告して配線しない（以後のDOMの追加・削除は検知しない）。公開メソッド`setEnabled(enabled)`でパレット本体の`.disabled`制御を、`setActiveType(type)`で配線済みボタンの`.active`排他制御を行う。操作モードの知識は持たない（活性/非活性の判断は`main.js`側の責務）。`WindowManager`と同様、`VectorModel`・図形データ・選択状態には一切関与しないDOM操作専任のクラスである。
    *   **DevPanel.js** : 開発者向け確認用ウィンドウ（`#window-dev-panel`）のDOM操作専任の自己完結UI部品。`constructor(rootElement, { onExport, onImport })`でルート要素内のボタン（`#dev-export`/`#dev-import`）・テキスト欄（`#dev-json`）・結果表示（`#dev-result`）を解決し、1つでも欠ければ`console.warn`のうえ一切配線しない。`onExport(): string`の戻り値（作業データ形式のJSON文字列）をテキスト欄へ表示し、`onImport(text): ImportSummary`（`{ ok, restoredCount, reassignedCount, skipped: [{ index, type, reason }], error }`）を結果表示欄へ整形して表示する。`show()`でルート要素の`hidden`を解除する。作業データの中身は解釈せず、importを持たず、`VectorModel`・`InputTracker`・`DocumentSerializer`・図形インスタンスを参照しない（受け取るのは文字列と要約オブジェクトのみ）。コールバックの例外は捕捉しないため、`onImport`側の処理を増やす場合は例外を漏らさないこと（漏れると結果表示が更新されない）。
    *   **コントロールパネルの位置づけ** : コントロールパネルは、操作モードの切り替え・頻繁に使う操作（削除・取り消し/やり直し・ビューのリセット等）と、他のパレットの**呼び出し口**（開閉ボタン。キャンバスパレットの`#launcher-canvas`が最初の例）を置く場所である。頻繁には使わない機能はパレットに分け、呼び出し口から開閉する。
        *   **呼び出し口の追加手順** : ①`index.html`へ呼び出し口のボタン（コントロールパネル内）とパレットのDOM（`.float-window`。`hidden`で初期非表示。`.window-close-btn`を含むヘッダー）を静的に置く（`WindowManager`の検知のため）②`main.js`の対応表`paletteLaunchers`へ`{ button, palette }`の1エントリを追加する（`PaletteLauncher`の変更は不要）。パレットの中身の配線は、そのパレットのUI部品を`palette/`に新設して行う。必要ならコントロールパネルの高さの変化に合わせて`#window-shape-palette`の`top`を再調整する。
    *   **PaletteLauncher.js** : 呼び出し口のボタンと開閉式パレットの対応づけと開閉を担うDOM操作専任のクラス。`constructor(bindings)`（`bindings`は`[{ button, palette }]`。要素が欠けるエントリは`console.warn`して配線しない）で、ボタンの`click`で開閉を反転し、パレット内の`.window-close-btn`の`click`で閉じる。開閉は`palette.hidden`の切り替えとボタンの`.active`（開いている間の押された見た目）のみで、起動時はパレットの`hidden`の現状に`.active`を合わせる。importを持たず、パレットの中身・`WindowManager`には関与しない。対応表に無いウィンドウの`×`は無機能のままである。
    *   **CanvasPalette.js** : キャンバスパレット（キャンバス一覧・新規作成・名前の変更・削除・ファイル操作（書き出し・開く・インポート）・保存状態とファイル操作の通知の表示）のDOM操作専任の自己完結UI部品。`constructor(rootElement, { onOpen, onCreate, onRename, onDelete, onExport, onOpenFile, onImportFile })`（コールバックが関数でなければ`Error`。ルート要素内の`#canvas-create`・`#canvas-list`・`#canvas-notice`・`#canvas-export`・`#canvas-open-file`・`#canvas-import`・`#canvas-open-file-input`・`#canvas-import-file-input`・`#canvas-file-notice`が1つでも欠ければ`console.warn`のうえ一切配線しない）。`render(state)`は`CanvasPaletteState`（`CanvasLibraryState`＋`fileNotice`。実体は`CanvasFileOperations.getState()`の戻り値で、`busy`はファイル操作の処理中も真）から一覧を作り直し（最終更新日時の新しい順。開いているキャンバスの行に`.current`）、`busy || !canManage || loading`のとき新規作成・開く（ファイル）・各行のボタンを`disabled`にし、書き出し・インポートは`busy || loading`のとき`disabled`にする（`'unavailable'`（`!canManage`）でも書き出し・インポートは押せる）。読み込み中は一覧の代わりに「読み込み中…」を、`issue`があれば対応表`ISSUE_MESSAGES`（このファイルが唯一の定義箇所）の文言を`#canvas-notice`へ表示し、`fileNotice`があれば対応表`FILE_NOTICE_MESSAGES`（種類→文言。ファイル名・件数を埋める関数。このファイルが唯一の定義箇所）の文言を`#canvas-file-notice`へ`issue`とは独立に表示する（`null`・未知の種類は`hidden`）。ファイル操作：書き出しは`click`で`blur()`→`onExport()`。開く・インポートは共通のprivate`#bindFilePicker(button, input, onFile)`で、ボタンの`click`で`blur()`→`input.click()`（利用者操作の要件のため`click`内で同期的に呼ぶ）、`input`の`change`で`files[0]`を取得→`input.value = ''`（同じファイルを続けて選んでも`change`が起きるように）→`input.blur()`→ファイルがあれば`onFile(file)`（キャンセルでは`change`が起きず何も呼ばない）。`File`は不透明に渡し、中身・名前を読まず、読み込みの判定を置かない。名前は`textContent`のみで設定し`innerHTML`は使わない（利用者の入力をHTMLとして解釈しないため）。一覧の操作（行の名前＝開く・`✎`＝名前の変更・`🗑`＝削除）は`#canvas-list`への1本のイベント委譲で扱い、名前の変更は`window.prompt`、削除は`window.confirm`で確認して、確定した場合のみコールバックを呼ぶ（キャンセル時は何も呼ばない。空の名前等の受理判定は`CanvasLibrary`側）。コールバックの戻り値は待たない。押されたボタンは処理前に`blur()`する（フォーカスが残ると`Enter`で再度押されるため）。importを持たず、`CanvasLibrary`・`VectorModel`・図形データ・IndexedDBを参照しない（受け取るのは`state`とコールバックのみ）。typedef`CanvasLibraryState`は`CanvasLibrary.js`と本ファイルの二重定義、typedef`FileNotice`は`CanvasFileOperations.js`と本ファイルの二重定義のため、形を変える場合は両方を揃えること。
