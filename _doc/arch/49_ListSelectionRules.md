*   **ListSelectionRules.js**：一覧の行（図形・フォルダ）のクリック・`Ctrl`＋クリック・`Shift`＋クリックでの次の選択（図形とフォルダ）と、`Shift`の起点の次の値を、状態を持たない関数として提供する（Phase 11-02で新設。Phase 11-04aでフォルダの行を含む`resolveRowClickSelection`を足した。流れは`PROJECT_ARCHITECTURE.md`3章28.）。
    *   **公開**：`resolveListClickSelection({ rowIds, selectedIds, hitId, additive, range, anchorId })` → `{ ids, anchorId }`（typedef`ListClickSelection`）。`rowIds`は行の図形idの並び（上の行から）、`selectedIds`は今の選択、`hitId`は押した行、`additive`は`Ctrl`（`Meta`）、`range`は`Shift`、`anchorId`は今の起点（無ければ`null`）。Phase 11-04aで、フォルダの行を含む`resolveRowClickSelection`（下の項）を足した（既存の関数は変えていない）。
    *   **規則**：`range`（`additive`によらず優先）＝起点（`anchorId`が`rowIds`にあり`selectedIds`に含まれるならそれ、そうでなければ`rowIds`の順で最初の選ばれている行、無ければ`hitId`）から`hitId`までの`rowIds`の連続した部分（逆向きも可。`rowIds`の並びで返す）。返す`anchorId`は**渡されたまま**（起点は、ふつうのクリックか`Ctrl`＋クリックでだけ変わる）。`additive`＝`SelectionRules.resolveClickSelection(selectedIds, hitId, true)`の`ids`（選択中なら外し、未選択なら末尾へ足す）。`anchorId`は`hitId`（外したときも。外した行は選ばれていないため、次の`Shift`では「いちばん上の選ばれている行」に切り替わる）。どちらでもなければ`ids = [hitId]`・`anchorId = hitId`。`hitId`が`rowIds`に無いときは、選択の写しと渡された起点をそのまま返す（防御）。引数を書き換えず、新しい配列を返す。
    *   **`resolveRowClickSelection({ rows, selectedIds, selectedGroupIds, hitId, additive, range, anchorId })` → `{ ids, groupIds, anchorId }`**（Phase 11-04a。typedef`RowClickSelection`）：`rows`は`ItemRowRules.buildItemRows`の見えている行、`selectedIds`は折りたたまれて行の無い図形も含めた今の選択の全体（`model.getSelectedIds()`）、`selectedGroupIds`は今選んでいるフォルダ。行ごとの「選ばれている」を、図形の行＝`selectedIds`にある、フォルダの行＝自分か上のフォルダが`selectedGroupIds`にある、とし、そのidの並びで`resolveListClickSelection`を呼んで次の行のidと起点を得る（起点・範囲の規則を二重に書かない）。ふつう・`Shift`：結果の行の`shapeIds`の和（重複なし）が`ids`、結果の行のうちフォルダが`groupIds`。`Ctrl`で足すとき：今の`selectedIds`＋押した行の`shapeIds`、今の`selectedGroupIds`＋（フォルダなら）そのid。`Ctrl`で外すとき（`resolveListClickSelection`の結果に`hitId`が含まれないとき）：今の`selectedIds`−押した行の`shapeIds`、`selectedGroupIds`−（押したid・その中のフォルダ`groupIds`・上のフォルダ`ancestorIds`＝選んでいるフォルダの中の図形を外すと外側のフォルダも選んでいる状態から外れる。ほかの図形は選ばれたまま）。`Shift`の範囲ではフォルダの行が全中身を選ぶため、範囲の外の中身も選ばれる。`hitId`の行が無ければ今の選択と起点をそのまま返す（防御）。引数を書き換えず、新しい配列を返す。
    *   **読むもの**：渡された配列と値だけ（`resolveRowClickSelection`は行の`id`・`kind`・`ancestorIds`・`shapeIds`・`groupIds`）。importは`core/SelectionRules`（`resolveClickSelection`）のみ（`core/`の規則どうしのimport。循環しない）。
    *   **知らないこと**：DOM・`VectorModel`・図形・`InputTracker`・操作モード・修飾キーのイベント（`Ctrl`・`Shift`の読み取りは呼び出し側）。起点を覚えない（覚えるのは`wiring/ItemListWiring`の一時的な値`#anchorId`。保存・履歴・作業データ・書き出しに入れない）。
    *   **使う側**：`wiring/ItemListWiring`だけ（`#handleRowClick`）。結果を`model.setSelectionByUser(ids, { groupIds, keepsCollapsed: true })`へ（Phase 11-04aで`resolveRowClickSelection`に差し替え、`groupIds`と`keepsCollapsed: true`を足した。一覧の選択では閉じたフォルダを開かない）、`anchorId`を起点へ渡す。
    *   **注意**：キャンバスの切り替え（`openCanvasId`が変わった）で`wiring/`が起点を忘れる（図形のidは別のキャンバスと同じ値になり得るため）。選択から外れた図形の頂点の選択は、`VectorModel`が今の規則で落とす（`wiring/`は`clearSelectedVertices()`を呼ばない）。
