*   **ListDragRules.js**：図形の一覧の行のドラッグ（出し入れ・並べ替え）の規則を、状態を持たない関数として提供する（Phase 11-03で新設。Phase 11-04bで、行の並びの添字ではなく入る場所（`ItemPlaceRules`＝`62_ItemPlaceRules.md`）で話すよう書き直した。流れは`PROJECT_ARCHITECTURE.md`3章28.）。動かすもの・ドロップ位置（場所）・線と目立たせる行・行の並びの比較・自動スクロールの量を求める。
    *   **公開**：`resolveDraggedUnitIds`・`resolveDraggedRowIds`・`resolveDropPlace`・`resolvePlaceMark`・`isSameRows`・`resolveAutoScrollTop`と、typedef`ListArea`・`PlaceMark`。定数（自動スクロールの帯24px・最小90px/秒・最大900px/秒・経過時間の上限50ms、割合の境0.5・0.25・0.75、送り切りの余裕1px）はファイル内のもので、exportしない。旧`resolveDraggedIds`・`resolveDropIndex`・`resolveDropMark`・`reorderRowsForDrop`・`isSameOrder`・`toDrawOrder`と、typedef`RowIds`・`DropMark`は消した（並びごと組み直す手順は、`ItemPlaceRules.moveItems`の1回の計算に置き換えた）。
    *   **`resolveDraggedUnitIds({ unitIds, pressedId })`**：動かすまとまりのid。`unitIds`（選んでいるまとまり。前順。折りたたまれて行の無いものも含む）に`pressedId`があれば`unitIds`の写し、無ければ`[pressedId]`（選んでいるフォルダの中の行は`unitIds`に無いので、その行だけになる）。新しい配列。**`resolveDraggedRowIds({ rows, draggedIds })`**：うすく見せる行のid（動かすものの行と、動かすフォルダの中の行）。`row.id`か`row.ancestorIds`のどれかが`draggedIds`にある行のid（行の並びの順）。
    *   **`resolveDropPlace({ pointerX, pointerY, area, rows })`** → 場所（`ItemPlace`）または`null`：`area`＝`ListArea`（`{ left, right, top, height, scrollTop, maxScrollTop, rowHeight }`。クライアント座標px）、`rows`＝ドラッグが始まった時点の見えている行（`ItemRowRules.buildItemRows`の結果）。上から順に：(1) `pointerX`が`left`未満・`right`より大きい → `null`（左右へ外れた）／(2) `rows`が空・`rowHeight`か`height`が正でない → `null`／(3) `y`＝`pointerY`を`[top, top + height]`へ収め、`− top + scrollTop`（上下へ外れたときは見えている端として扱う）／(4) 次のどちらかなら`{ bottom, null }`（いちばん外側の一番下）：(a) `y >= rows.length × rowHeight`（最後の行より下の空いている所）、(b) `pointerY >= top + height`（収める前の値）かつ`scrollTop >= maxScrollTop − 1`（一番下まで送り切って下へ外れた。(b)が要るのは、`height`（`clientHeight`）は整数へ丸められ`scrollTop`は小数を取り得て、送り切っても(a)の和が行の総高に1px未満だけ足りないことがあるため。例：見える高さ498.4px・20行 → 498 ＋ 221.6 ＝ 719.6 ＜ 720。表示倍率が125%等でも届く）／(5) `index = floor(y / rowHeight)`、`fraction`＝その行の中の割合。図形の行：`fraction < 0.5`なら`{ above, row.id }`、そうでなければ`{ below, row.id }`。フォルダの行：`fraction < 0.25`なら`above`、`fraction < 0.75`なら`inside`、それより下は、開いていて中身がある（`!row.collapsed && !row.isEmpty`）なら`inside`、折りたたみ・空なら`below`。一番上の行より上へ外れると`y`が0になり、その行の`above`（いちばん外側の一番上）になる。入れられない場所かどうか（自分の中など）はこの関数では見ない（`ItemPlaceRules.canMoveItems`。`ItemListRowDrag`が注入された`canDrop`で見る）。
    *   **`resolvePlaceMark({ rows, place })`** → `{ id, edge: 'before'|'after'|'inside', indent }|null`（typedef`PlaceMark`）：場所から、線を出す行（または目立たせる行）と見せ方。`place`が`null`・行が無い → `null`。`above` → その行の`'before'`・`resolveRowIndent(row.depth)`（線は行の字下げの位置から）。`below` → `'after'`・同じ字下げ。`inside` → `'inside'`・字下げ0（線は出さず、行を目立たせる＝`ItemListPanel`の`drop-inside`）。`{ bottom, null }` → 最後の行の`'after'`・字下げ0。`place.id`の行が`rows`に無い・`{ bottom, フォルダ }`（ドロップ位置には現れない） → `null`。
    *   **`isSameRows(a, b)`**：2つの行の並びが同じか。長さと、各位置の`id`・`depth`・`collapsed`・`isEmpty`が同じなら真（並びのidが同じでも、入れ子・折りたたみが変わったら取りやめるため）。
    *   **`resolveAutoScrollTop({ pointerX, pointerY, area, elapsedMs })`** → `number|null`：動かさないなら`null`。左右へ外れている・`height`が正でない・`maxScrollTop`が正でないなら`null`。上端・下端の帯（24px。`height / 2`を超えない）に入った深さの割合（帯の外へ外れていれば1）に応じて90〜900px/秒、経過時間は50msまでとして量を求め、`0`〜`maxScrollTop`に収め、今の`scrollTop`と同じなら`null`。帯の境目ちょうど（`y === top + band`）は帯の外（Phase 11-03から変えていない）。
    *   **フォルダの無い絵**：`above(行i)`／`below(行i)`は、旧規則の`dropIndex = i`／`i + 1`と同じ並びになる（境目の0.5は下側＝`Math.round`と同じ。テストで`moveItems`の結果と一致を確かめている）。
    *   **読むもの**：渡された配列・数値・`area`・行の`kind`・`depth`・`collapsed`・`isEmpty`・`ancestorIds`だけ。importは`core/ItemTreeRules`（`ITEM_KIND`）・`core/ItemRowRules`（`resolveRowIndent`）・`core/ItemPlaceRules`（`PLACE_KIND`）のみ（`ItemRowRules`は`ListDragRules`をimportしない）。
    *   **知らないこと**：DOM・`VectorModel`・図形・操作モード・履歴・`requestAnimationFrame`。状態を持たない。引数を書き換えない。
    *   **使う側**：`wiring/ItemListRowDrag`だけ（`main.js`・`ItemListWiring`は直接使わない）。
    *   **置き場所の理由**：行のドラッグの判定・計算を`wiring/`（判定を持たない）にも`palette/`（何もimportしない）にも置けず、`node --test`で確かめるため、状態を持たない関数として`core/`に置いた。行の操作の判定（ドラッグを始めてよいか等）は操作モードを知る`ItemListRules`に置き、ここには操作モードを知らない計算だけを置く。
