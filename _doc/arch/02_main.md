*   **main.js** : アプリケーションのエントリポイント。3章1.の各クラスのインスタンス化・依存の注入（`ViewTransform`→`InputTracker`等）とイベントバインドを担う。取り消し・やり直しの操作関数も、既存モジュールのAPIを決められた順に呼ぶモジュール間の連携としてここに置く（判定ロジック・作業データの中身の解釈は持たない。持たせる必要が生じたら別モジュールへ分離する。履歴のスナップショットの取得・適用は`edit/SnapshotAdapter`へ、キャンバス管理の処理本体は`edit/CanvasLibrary`へ分離済み）。行数が約500行に達しているため、今後配線を追加する場合は配線ブロックの切り出しを検討すること。
    *   **履歴（取り消し・やり直し）配線** : `// 3.5.`の1ブロック（`ViewTransform`の生成後・`InputTracker`の生成前）に、`snapshotAdapter`の生成（`model`と、注入関数`shouldRestoreSelection`＝「選択モードのときのみ選択集合を復元する」規則の実体`() => inputTracker.getMode() === OperationMode.SELECT`）・`historyManager`の生成（`capture`/`restore`に`snapshotAdapter`を注入）・`performUndo()`/`performRedo()`（3章6.の適用の流れ）をこの順に置く。`HistoryManager`は`InputTracker`のコンストラクタへ`EditRecorder`として注入するため、`InputTracker`より先に生成する。`shouldRestoreSelection`の実体・`performUndo`・`performRedo`は後で宣言される`inputTracker`を参照するが、呼ばれるのは起動完了後の取り消し・やり直し時のみである（起動処理中に`undo()`/`redo()`を呼ぶ変更をする場合は注意）。`core/`から`io/`をimportしないため、`DocumentSerializer`を使う処理は`main.js`と`edit/`が持つ。
    *   **取り消し・やり直しボタン** : ボタンの要素取得・`syncHistoryButtonState()`・onChange登録・click登録は`// 6.`（コントロールパネル配線）内に置く。`click`は`performUndo()`/`performRedo()`を呼ぶのみ（ショートカットと同一経路。`historyManager.undo()`/`redo()`を直接呼ばない）。押せる/押せない状態は`syncHistoryButtonState()`が担い（取り消し：履歴がなく作成途中の図形もない場合に`disabled`、やり直し：やり直す履歴がない場合に`disabled`）、`model.onChange`（作成途中の図形の有無）と`historyManager.onChange`（記録・適用・リセット）の両方に登録する。
    *   **操作モード・図形種別の切替** : `applyMode(mode)`が操作モード切替を一元管理する。`InputTracker.setMode`呼び出し後に`getMode()`で実状態を読み返して`.active`を同期し、パレットの活性（図形作成モード時のみ）と図形種別ハイライトは`PaletteController`へ委譲する。新規モードボタンは`modeButtons`（キーは`OperationMode`の値）へのエントリ追加で対応する（`index.html`のDOM要素と`InputTracker`の`OperationMode`の値も追加が必要）。図形種別の切替は`applyShapeType(type)`（パレットの`onTypeSelected`コールバック）が担う。図形種別一覧`SHAPE_TYPES`は正本の`ShapeFactory.js`から直接importし、`PaletteController`のコンストラクタへ渡す。
    *   **起動時の同期** : 起動時に`applyMode(OperationMode.SELECT)`でUI初期表示を内部状態へ同期し、初期化の最後に`renderCurrentState()`・`syncZoomDisplay()`・`syncDeleteButtonState()`・`syncHistoryButtonState()`・`syncCanvasNameDisplay()`・`syncLoadingCover()`・キャンバスパレットの`render`を明示的に1回ずつ呼ぶ（初回の描画・表示を`onChange`通知や`index.html`の初期記述に依存させない。`start()`前の`canvasLibrary.getState().loading`は真のため「読み込み中」として表示される）。その後に`canvasLibrary.start()`を`await`せずに呼ぶ（3章1.）。
    *   **ビュー関連UI** : `viewTransform.onChange`に`renderCurrentState`と`syncZoomDisplay`（倍率表示`#view-zoom-display`）を登録する。リセットボタン`#view-reset`は`viewTransform.reset()`を呼ぶのみ（操作モード・選択集合には触れない）。
    *   **削除ボタン** : `#selection-delete`の`click`は`inputTracker.deleteSelection()`を呼ぶのみ（受理条件の判定は`InputTracker`側。`model.deleteShapes`を直接呼ばない）。押せる/押せない状態は`model.onChange`に登録した`syncDeleteButtonState()`（選択集合が空なら`disabled`）が担う。
    *   **クリップボード配線** : `// 7.5.`の1ブロック（モードボタンのクリック登録の後・`// 8.`の前）で、`ShapeInserter`（`model`・`editRecorder`＝`historyManager`を注入）と`ClipboardController`（`model`・`inserter`＝`shapeInserter`・`deleteSelection`＝`() => inputTracker.deleteSelection()`を注入）を生成するのみ。コピー・切り取り・貼り付け・複製の処理本体は`edit/`が持つ。
    *   **キャンバス管理配線** : `// 7.6.`の1ブロック（`// 7.5.`の後。`applyMode`・`viewTransform`・`historyManager`の生成後であること）で、生成・注入コールバック・表示の同期・イベントの配線のみを行う（処理本体は`CanvasLibrary`）。
        *   呼び出し口の対応表`paletteLaunchers`（唯一の定義箇所）と`PaletteLauncher`の生成。
        *   `CanvasLibrary`の生成（`storage`＝`new CanvasStorage()`・`model`・`historyManager`・`prepareSwitch`＝`() => applyMode(OperationMode.SELECT)`・`resetView`＝`() => viewTransform.reset()`）。
        *   `CanvasPalette`の生成（`onOpen`/`onCreate`/`onRename`/`onDelete`を`canvasLibrary`の`openCanvas`/`createCanvas`/`renameCanvas`/`deleteCanvas`へ委譲するのみ）。
        *   `syncCanvasNameDisplay()`（`#canvas-name-display`と`document.title`。読み込み中は「読み込み中…」／`OZ Vector Editor`、それ以外は`<キャンバス名> - OZ Vector Editor`、保存の問題があれば表示の先頭に`⚠ `）と`syncLoadingCover()`（`#canvas-loading-cover`の`hidden`を`!getState().loading`に設定）。これらとパレットの`render`を`canvasLibrary.onChange`へ登録する。
        *   ページ非表示時の確定：`document`の`visibilitychange`（`hidden`のとき）と`window`の`pagehide`で`canvasLibrary.flushPendingSave()`を呼ぶ。
    *   **キーボードショートカット配線** : `KeyboardShortcuts`を生成し、操作コールバック（`isDragging`/`setMode`/`setShapeType`/`zoomStep`/`resetView`/`cancel`/`selectAll`/`deleteSelection`/`undo`/`redo`/`copy`/`cut`/`paste`/`duplicate`）を注入する（`undo`/`redo`は`performUndo`/`performRedo`。ドラッグ中でなければ常に`true`を返す）。`copy`/`cut`は`clipboardController.copy()`/`cut()`の戻り値をそのまま返す（何もしなかった場合は`false`）。`paste`はクリップボードが空なら何もせず（モードも切り替えない）、空でなければ選択モード以外のとき先に`applyMode(OperationMode.SELECT)`を呼んでから`clipboardController.paste()`を呼ぶ。`paste`/`duplicate`は常に`true`を返す（ブラウザ標準の貼り付け・ブックマーク追加の抑止）。`paste`/`duplicate`はドラッグ中を自ら判定せず、ドラッグ中は`KeyboardShortcuts`の受理判定で呼ばれないだけである（`undo`/`redo`がコールバック内で判定するのとは異なる。ショートカット以外から呼ぶ場合は呼び出し側でドラッグ中の判定が必要）。モード自動切替を伴う操作（数字キー→図形作成モード、全選択→選択モード）は、コールバック内で先に`applyMode`を呼ぶ。`selectAll`は常に`true`を返す（図形0個でもページ全選択を防ぐ）。拡大・縮小はキャンバス中心を基準に`WHEEL_ZOOM_STEP`（`InputTracker.js`からimport）で`viewTransform.zoomAt`へ委譲する。
    *   **開発者向け確認用ウィンドウ配線** : `URLSearchParams(window.location.search).has('dev')`が真のときのみ`DevPanel`を生成して`show()`する（判定結果・関数・インスタンスを`window`へ公開しない）。注入するコールバックは、`onExport`＝`DocumentSerializer.serializeToString(model.getShapes())`、`onImport(text)`＝キャンバスの読み込み中（`canvasLibrary.getState().loading`が真）なら図形一式・履歴に触れず失敗（`error: 'キャンバスの読み込み中です'`）を返し（読み込み完了時の切り替えで復元内容が消されるため）、それ以外は`DocumentSerializer.deserializeFromString(text)`の結果が成功のときのみ`inputTracker.abortOngoingOperation()`→`historyManager.beginEdit()`→`model.replaceAllShapes(result.shapes)`→`historyManager.commitEdit()`を行い（1件の編集操作として記録）、要約（`ImportSummary`）を返す（失敗時はキャンバスを変更せず記録もしない）。再描画・ボタンの同期は呼ばず、`model.onChange`・`historyManager.onChange`経路に任せる。`DevPanel`はコールバックの例外を捕捉しないため、`onImport`から例外を漏らさないこと（現状`try/catch`は持たず、例外を投げる処理も書かない方針）。
