    *   **`updateShapeStyles(changes)`**：`changes`＝`[{ id, style: { strokeColor?, strokeWidth?, fillColor? } }]`。各idの図形へ、`style`が自身のプロパティとして持つ3つのキーだけを代入する（値の検証はしない・存在しないidは無視）。見つかった図形の数を返し、1つ以上見つかったときだけ1回通知する（`style`が空でも見つかった図形は数える）。選択集合・ホバー・作成途中の図形・直前に使った値には触れない。呼び出し元は`ShapeStyleEditor`のみ。
    *   **知らないこと**：図形固有の頂点構造・内部プロパティ名、図形データ・作業データ形式・`DocumentSerializer`（作業データのフォルダの要素`type: 'group'`も含む。エディタの中のフォルダは`kind: 'group'`のアイテムで、`kind`は作業データに出ない）。`Line`への直接依存も持たない。ただし共通プロパティのスタイル3つ（`strokeColor`・`strokeWidth`・`fillColor`）は書く（図形固有のプロパティではない。`updateShapeStyles`・`startDraft`・`replaceDraft`・`updateNewShapeStyle`の作成途中の図形のみ）。
    *   **委譲**：再編集・追従は対象図形の`setVertex`/`translate`/`updateDraftEnd`へポリモーフィックに委譲する。生成は`ShapeFactory.create`へ委譲する（線を続けて引く途中の作成途中の線の組み立て直しは、`PathJoinRules`が作った図形を`replaceDraft`が受け取るだけ）。復元は`DocumentSerializer`→`ShapeFactory.fromJSON`が行い、`VectorModel`は復元済みの図形一式を受け取るのみ。
    *   **id**：図形idの採番（形式`shape-<連番>`）・フォルダidの採番（形式`group-<連番>`）は`#issueId(prefix)`の1箇所に一本化する（連番カウンタ`#nextId`は図形・フォルダで1つを共有し、合わせて一意。Phase 11-01）。連番カウンタは単調増加で減らさない。id形式の知識は`VectorModel`内に閉じる（他モジュールはid形式を解釈しない）。単一選択は`setSelection([id])`で表現する。
