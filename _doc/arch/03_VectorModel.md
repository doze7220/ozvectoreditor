*   **VectorModel.js**：描画データ（Shape配列）と、選択集合・頂点の選択・ホバー状態・作成中図形・選択矩形・吸い付きの表示の点・新しく描く図形のスタイル（直前に使った値）を保持する単一の真実（SSOT）。
    *   **公開メソッド**：`getShapes`・`replaceAllShapes`・`addShapesWithNewIds`・`replaceShape`・`reorderShapes`・`deleteShapes`・`updateVertex`・`updateVertices`（複数の頂点のまとめ更新。Phase 08-02b）・`moveShapes`・`moveShapesBy`（図形ごとに違う移動量のまとめ移動。Phase 08-05）・`updateShapeStyles`／`getNewShapeStyle`・`updateNewShapeStyle`／`setSelection`・`clearSelection`・`getSelectedIds`・`isSelected`／`setSelectedVertices`・`clearSelectedVertices`・`getSelectedVertices`・`isVertexSelected`（頂点の選択。Phase 08-02a）／`setHovered`・`clearHovered`・`getHoveredId`／`setSelectionRect`・`clearSelectionRect`・`getSelectionRect`／`setSnapPoint`・`clearSnapPoint`・`getSnapPoint`／`startDraft`・`updateDraft`・`commitDraft`・`cancelDraft`・`replaceDraft`・`getDraftShape`／`onChange`／`addShape`（使わない。理由はJSDoc）。
    *   **吸い付きの表示の点**：ワールド座標の1点（表示専用。保存・履歴の対象外）。`setSnapPoint`は同じ座標の再設定では通知せず、`clearSnapPoint`は表示中のときだけ通知する。`getSnapPoint`はコピーを返す。`replaceAllShapes`は選択集合・ホバー・作成中の図形・選択矩形とともにこの点も消す（通知は1回のまま）。設定・消去は`InputTracker`（3章12.）。
    *   **頂点の選択**（Phase 08-02a。2章・3章18.）：非公開の`#selectedVertices`（`{ shapeId, handle }`の配列。選んだ順）。表示専用の一時的な状態で、保存・履歴・書き出しの対象外（`DocumentSerializer`・`SnapshotAdapter`・`SpriteSerializer`は触れない）。公開は4つ：`setSelectedVertices(pairs)`（置き換え。`shapeId`が**現在の選択集合に含まれ**かつ`handle`が空でない文字列の組だけを、与えられた順で重複を除いて新しいオブジェクトとして写す。引数を保持も書き換えもしない。内容が変わったときだけ通知1回）・`clearSelectedVertices()`（1つ以上あったときだけ通知1回）・`getSelectedVertices()`（コピーを返す）・`isVertexSelected(shapeId, handle)`。**不変条件：選択集合に含まれる図形の組だけを持つ**。落とし方：非公開の`#pruneSelectedVertices()`を、選択集合・図形一式が変わる既存の操作（`setSelection`・`clearSelection`・`deleteShapes`・`replaceAllShapes`・`addShapesWithNewIds`・`replaceShape`）の`#notifyChange()`の**前**で呼ぶ。**通知の回数は増やさず、既存の通知に相乗りする**（専用の通知・購読を足さない）。これで取り消し・やり直し・キャンバスの切り替え・削除・結合・端点への吸い付きの確定・貼り付け・複製（`Ctrl`+`D`）・`?dev`の復元・`setMode`（`clearSelection`を通る）で取り残しが出ない。`reorderShapes`・`moveShapes`・`updateVertex`・`updateVertices`・`updateShapeStyles`は選択集合・図形の増減を変えないため呼ばない。**Phase 08-02bから2つ以上の組が入る**（入れる操作は`Ctrl`＋クリックでの追加・解除、範囲選択、選び直し。前半の「最大1つ」の前提は外れた）。`setSelectedVertices`の写し方（選択集合に含まれる図形の組だけ・重複を除く・与えられた順）・落とし方（`#pruneSelectedVertices`。複数のまま一部の図形が外れると、その図形の組だけが落ち、残る組の並びは保たれる）・通知の約束・保存しないことは変えていない。`VectorModel`は頂点のハンドル名の意味（どの図形のどの名前が頂点か）を知らず、文字列として持つだけ。設定・解除を呼ぶのは`InputTracker`のみ（`InputTracker`は`getSelectedVertices`も読む）。そのほかに`getSelectedVertices`を読むのは`main.js`（`renderCurrentState`）・`edit/NudgeEditor`・`edit/PositionInputEditor`（後の2つは`resolveNudgeTarget`の引数に渡す）。
    *   **頂点の更新**：`updateVertex(id, vertexIndex, x, y)`は`updateVertices([{ id, vertexIndex, x, y }])`へ委譲する（**`shape.setVertex`を呼ぶ箇所は`updateVertices`の1か所だけ**）。`updateVertices(updates)`（Phase 08-02b。`updates`は`{ id, vertexIndex, x, y }`の配列＝ワールド座標の絶対値）は、各組を配列の順に`shape.setVertex(vertexIndex, x, y)`へポリモーフィックに委譲する（図形種別を知らない）。**1件以上更新したときだけ変更を通知する（組の数によらず1回）**。存在しないidの組は無視し、全部が存在しない・空の配列では何もせず通知もしない。引数の配列・要素は書き換えない。呼び出し元は`InputTracker`の頂点のドラッグの追従（まとめ移動。3章18.）と、`edit/NudgeEditor`の頂点の移動（矢印キーの微調整`nudge`と、位置の数値入力から届く`nudgeWithoutGrouping`。今の位置＋移動量の絶対座標を渡す。通知1回。Phase 08-03・08-04。3章19.・20.）。テスト：`test/core/VectorModel.updateVertices.test.js`（`_doc/arch/16_test.md`）。
    *   **`moveShapes`の呼び出し元（Phase 08-03）**：`InputTracker`の図形のドラッグに加え、`edit/NudgeEditor`が図形の移動で呼ぶ（矢印キーの微調整`nudge`と、位置の数値入力から届く`nudgeWithoutGrouping`。選択中のidを渡す。通知1回。3章19.・20.）。`VectorModel`・図形クラスは変更しておらず、微調整であることも丸めも知らない。
    *   **`moveShapesBy(moves)`**（Phase 08-05）：`moves`＝`{ id, dx, dy }`の配列（図形ごとに違う移動量）。各組を配列の順に`shape.translate(dx, dy)`へポリモーフィックに委譲する（図形種別を知らない。`updateVertices`と同じ書き方）。存在しないidの組は飛ばし、**1件以上動かしたときだけ通知を1回**（組の数によらず。全部が存在しない・空の配列では通知0）。同じidの組が複数あれば順に当てる。引数の配列・要素は書き換えない。選択集合・頂点の選択・ホバー等には触れず、`#pruneSelectedVertices`も呼ばない（図形の増減・選択集合が変わらないため）。`moveShapes`（全図形に同じ移動量）の名前・引数・ふるまいは変えていない。呼び出し元は`edit/ShapeAlignEditor`のみ（3章21.）。履歴の記録は呼び出し側の責務。テスト：`test/core/VectorModel.moveShapesBy.test.js`。
    *   **`replaceShape`**：指定idの図形の位置へ新しい図形を入れ、指定の図形を除く（通知は1回）。`select`が真（既定）なら結果の図形だけを選択し、偽なら選択集合を作り直さず消えたidだけを外す。`keepId`が真なら指定idを引き継ぎ、偽なら`#issueId()`で新しいidを採番する。呼び出し元は`PathJoiner`（`select`は既定の真）と`EndpointSnapper`（描き足しは`select: false`、ハンドルのドラッグでの結合は`select: true`）。`select`が真のとき選択モードまたは頂点の選択モードであることは呼び出し側の保証（偽なら作成モードでも選択集合の不変条件を崩さない）。
    *   **`replaceDraft(shape)`**（直線のツールで線を続けて引く。3章22.）：作成途中の図形を、渡された図形（`PathJoinRules`が組み立てた線。`VectorModel`は図形固有の構造を知らず受け取るだけ）に置き換える。作成途中の図形が無いときは警告なしで何もせず`false`を返し、`#shapes`の図形そのものが渡されたときだけ`console.warn`して何もせず`false`を返す。渡された図形のidを`null`にし、直前に使った値（スタイル3つ。`#assignShapeStyle`）を当て、`#shapes`へは入れず、通知は1回。`startDraft`と並ぶ「作成途中の図形を作る・置き換える」2つ目の入口で、`commitDraft`が確定するときに採番する。呼び出し元は`edit/EndpointSnapper`のみ（点を打つ・最後の点を消す・吸い付きなしで終えるとき）。
    *   **`reorderShapes(orderedIds)`**：現在の全図形のidをちょうど1回ずつ並べた配列（先頭＝最も奥）で新しい並びを受け取る。配列でない・要素数が違う・現存しないid・重複idは`console.warn`して何もせず`false`。idから現在のインスタンスを引いて新配列を作り、全位置で同じインスタンスなら（警告・通知なしで）`false`。それ以外は`#shapes`を置き換えて通知を1回出し`true`。触れない状態：選択集合（`getSelectedIds`の返す順は新しい並びに従う）・ホバー・作成中の図形・選択矩形・吸い付きの表示の点・直前に使った値・idの採番・図形インスタンスの中身。履歴の記録は呼び出し側の責務。呼び出し元は`ShapeOrderEditor`のみ（図形の一覧のPhaseで一覧のドラッグからも使う見込み）。操作の種類（最前面へ等）を受け取らない理由：並べ替えの規則を`core/`へ持ち込まず、任意の並びを同じ操作で受けるため（規則は`edit/ShapeOrderRules`の1か所）。
    *   **新しく描く図形のスタイル（直前に使った値）**（2章）：非公開の`#newShapeStyle`（`NewShapeStyle`）。`getNewShapeStyle()`はコピーを返す。`updateNewShapeStyle(patch)`は5つのキー（自身のプロパティとして持つもの）だけを上書きし（値の検証は呼び出し側の責務）、値が変わったときだけ（作成途中の図形があればそのスタイルも新しい値にしたうえで）1回通知して`true`を返す。`startDraft`が`ShapeFactory.create`の直後に、`replaceDraft`が渡された図形へ当てる（有無が偽の項目は`null`）。`replaceAllShapes`は触れない（保存・履歴の対象外）。更新は`ShapeStyleEditor`のみ。起動時の既定`DEFAULT_NEW_SHAPE_STYLE`（線あり黒・塗りなし・塗りの色は白）は、`edit/StylePanelRules`の`RESET_COLORS_STYLE`（`D`の値＝線あり黒・塗りあり白）とは色の値が重なるだけの別の定義（`edit/`と`core/`の依存方向により`StylePanelRules`は`VectorModel`をimportせず、塗りの有無も違う。両方のコメントに互いの存在を書いてある。Phase 07-04）。
    *   **`updateShapeStyles(changes)`**：`changes`＝`[{ id, style: { strokeColor?, strokeWidth?, fillColor? } }]`。各idの図形へ、`style`が自身のプロパティとして持つ3つのキーだけを代入する（値の検証はしない・存在しないidは無視）。見つかった図形の数を返し、1つ以上見つかったときだけ1回通知する（`style`が空でも見つかった図形は数える）。選択集合・ホバー・作成途中の図形・直前に使った値には触れない。呼び出し元は`ShapeStyleEditor`のみ。
    *   **知らないこと**：図形固有の頂点構造・内部プロパティ名、図形データ・作業データ形式・`DocumentSerializer`。`Line`への直接依存も持たない。ただし共通プロパティのスタイル3つ（`strokeColor`・`strokeWidth`・`fillColor`）は書く（図形固有のプロパティではない。`updateShapeStyles`・`startDraft`・`replaceDraft`・`updateNewShapeStyle`の作成途中の図形のみ）。
    *   **委譲**：再編集・追従は対象図形の`setVertex`/`translate`/`updateDraftEnd`へポリモーフィックに委譲する。生成は`ShapeFactory.create`へ委譲する（線を続けて引く途中の作成途中の線の組み立て直しは、`PathJoinRules`が作った図形を`replaceDraft`が受け取るだけ）。復元は`DocumentSerializer`→`ShapeFactory.fromJSON`が行い、`VectorModel`は復元済みの図形一式を受け取るのみ。
    *   **id**：図形idの採番（形式`shape-<連番>`）は1箇所に一本化する。連番カウンタは単調増加で減らさない。id形式の知識は`VectorModel`内に閉じる（他モジュールはid形式を解釈しない）。単一選択は`setSelection([id])`で表現する。
