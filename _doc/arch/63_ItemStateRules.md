*   **ItemStateRules.js**：アイテムの表示・ロックの規則（自分の値・上のフォルダから受け継ぐ計算・変えられるかの判定・値を変えた入れ子の計算）を、状態を持たない関数として提供する（Phase 11-05で新設。形は`PROJECT_ARCHITECTURE.md`2章「アイテム」の「表示・ロック」、流れは3章2.・3.・6.・28.）。
    *   **用語**：**自分の値**＝アイテムの`visible`（`false`だけが「切」）・`locked`（`true`だけが「入」）。値が無いアイテム・素の図形は表示あり・ロックなし。**隠れている**＝自分の表示が切、または上のフォルダのどれかの表示が切。**ロックされている**＝自分のロックが入、または上のフォルダのどれかのロックが入。**変えられる**＝隠れてもロックされてもいない（図形・フォルダとも）。隠れているもの・ロックされているものの両方が、キャンバスの当たり・変更の対象から外れる（一覧からは選べる）。
    *   **公開**：`listItemStates(items)`・`listVisibleShapes(items)`・`listEditableShapes(items)`・`collectEditableIds(items)`・`collectItemStates(items)`・`resolveVisibleToggle(items, id)`・`resolveLockToggle(items, id)`・`applyItemStates(items, changes)`と、typedef`ItemState`・`ItemStateChange`。
    *   **`listItemStates(items)`** → `ItemState[]`：前順（フォルダ自身→中身）の1回の再帰。typedef`ItemState`＝`{ item, id, visible, locked, hiddenByAncestor, lockedByAncestor, hidden, editable }`（`item`は引数の入れ子の中のものそのもの。`visible`・`locked`は自分の値）。`visible = item.visible !== false`、`locked = item.locked === true`、`hidden = hiddenByAncestor || !visible`、`editable = !hidden && !lockedByAncestor && !locked`。フォルダの中へは`hiddenByAncestor = hidden`・`lockedByAncestor = lockedByAncestor || locked`を渡す（上のフォルダの値は中の自分の値を変えない）。**上のフォルダから受け継ぐ計算と「変えられるか」の判定はここだけ**で、ほかの関数はこれを使う（`ItemRowRules`の行の見た目・`VectorModel`の照会・`RemovalRules`・`SoloVisibilityRules`も、受け継ぐ計算を自分で書かない）。
    *   **`listVisibleShapes(items)`**・**`listEditableShapes(items)`** → 図形の配列（重なり順。`listItemStates`から図形のアイテムだけを取る。図形はインスタンスそのもの）：見えている図形（隠れていない。ロックされた図形を含む）・変えられる図形。**`collectEditableIds(items)`** → `Set<string>`（図形・フォルダの変えられるもののid）。**`collectItemStates(items)`** → `Map<string, ItemState>`（id→状態）。
    *   **`resolveVisibleToggle(items, id)`**・**`resolveLockToggle(items, id)`** → `{ id, visible }`／`{ id, locked }`：自分の値の反対（上のフォルダから隠れている図形でも自分の値の反対）。無いidなら`null`。1回の押下の変更を求めるだけで、入れ子を変えない。
    *   **`applyItemStates(items, changes)`** → 入れ子：`changes`は`Array<{ id, visible?: boolean, locked?: boolean }>`（同じidが複数あれば後のものが優先。真偽値でない値・無いidは無視）。**変わるものが無ければ引数と同じ参照**を返す（`VectorModel.setItemStates`が通知の要否の判定に使う）。変わるときは通り道と変わるアイテムだけ新しいオブジェクトにし、通り道でないフォルダ・変わらない図形は同じ参照、図形インスタンスは共有する。フォルダの値を変えても中のものの値は変えない。`collapsed`等のほかのキーは保つ。片方だけ変えるときはもう片方のキーを足さない。引数は書き換えない。
    *   **読むもの**：渡された入れ子の`kind`・`children`・`visible`・`locked`と、`itemIdOf`の結果（図形の`shape.id`）だけ。図形のほかのプロパティを読まない。**`visible`・`locked`の値を読むのはここだけ**（不備を補う`ItemAttributeRules`と、読み書きする`DocumentSerializer`を除く）。
    *   **知らないこと**：DOM・`VectorModel`・図形クラス・図形種別・選択・折りたたみ・描き込む先・操作モード・履歴。状態を持たない。importは`core/ItemTreeRules`（`ITEM_KIND`）・`core/GroupTreeRules`（`itemIdOf`）のみ。引数を書き換えない。
    *   **使う側**：`core/VectorModel`（`listVisibleShapes`・`listEditableShapes`・`collectEditableIds`・`applyItemStates`。`getVisibleShapes`・`getEditableShapes`・`setItemStates`・頂点の選択の条件）・`core/ItemRowRules`（`collectItemStates`）・`core/RemovalRules`（`collectEditableIds`）・`core/SoloVisibilityRules`（`listItemStates`）・`edit/ItemStateEditor`（`resolveVisibleToggle`・`resolveLockToggle`）・`io/SpriteSerializer`（`listVisibleShapes`）・`core/CompoundPathRules`（`listItemStates`。Phase 12-04。効いている複合パスの中身の「見えている図形」を、この規則の状態の`hidden`で決める。ロックされた図形も中の図形に入る。表示の判定は引き続きこのファイルだけが持ち、`CompoundPathRules`は結果を読むだけ。`CompoundPathRules`もこのファイルをimportするため、`ItemStateRules`は`CompoundPathRules`をimportしない一方向）。
    *   **置き場所の理由**：表示・ロックの受け継ぎと「変えられるか」を1か所に置き、描画・当たり・変更・吸い付き・書き出し・一覧の見た目が同じ判定を使うため（食い違いを作らない）。`ItemTreeRules`は図形のプロパティを読まない責務、`GroupTreeRules`は入れ子を動かす計算の責務で、値の意味を持つ計算を置けないため、状態を持たない別のファイルに分けた。循環は無い（`ItemTreeRules` ← `GroupTreeRules` ← `ItemStateRules` ← `RemovalRules`・`SoloVisibilityRules`・`ItemRowRules`。`GroupTreeRules`・`ItemPlaceRules`は`ItemStateRules`をimportしない）。
    *   **注意**：クリックが当たる図形は「変えられる図形」と同じ（隠れているものもロックされているものも素通りになるため、当たり用の別の照会を作らない）。**一覧のロック中**（`ItemListRules.isListLocked`＝読み込み中・キャンバスの切り替え中の操作を止める）とは別の言葉で、混同しない（`PROJECT_ARCHITECTURE.md`3章28.）。
