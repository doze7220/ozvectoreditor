*   **io/** :
    *   **DocumentSerializer.js** : 作業データ形式（2章）のシリアライズ・デシリアライズと旧版からのマイグレーションを担う、静的メソッドのみのクラス（インスタンス状態なし・DOM非依存）。図形単位の変換は`ShapeFactory`・図形クラスへ委譲し、図形種別の分岐・図形固有のプロパティ名を持たない。importは`ShapeFactory`のみ（依存方向は`io → core → shapes`の一方向。`edit/`からは利用されるが、`io/`は`edit/`をimportしない）。保存対象は図形データのみ。
        *   **公開API** : オブジェクト層の`serialize(shapes)`（図形の配列（描画順）→作業データ）／`deserialize(documentData)`と、文字列層の`serializeToString(shapes)`／`deserializeFromString(text)`（`JSON.parse`の失敗も結果へ変換）を提供する。デシリアライズ系は例外をthrowせず、結果オブジェクト`DeserializeResult`（`{ ok, shapes, skipped: [{ index, type, reason }], error }`。`ok: false`なら`shapes`・`skipped`は空配列）を返す。`serialize`系は入力を検証しない（`toJSON`を持たない要素が混ざると例外になる。`model.getShapes()`のみを渡す想定）。引数のオブジェクトは書き換えない。
        *   **全体の読み込み失敗** : 最上位がプレーンオブジェクトでない／`format`が不一致／`version`が整数でない・1未満・現行版より大きい／マイグレーション関数が未定義・例外を投げた・戻り値がプレーンオブジェクトでない／マイグレーション後の`shapes`が配列でない、のいずれかで`ok: false`とする。
        *   **スキップ** : `shapes`の各要素は`ShapeFactory.fromJSON`で復元し、図形単位の`try/catch`はここ1箇所のみ（`core/`・`shapes/`は捕捉しない）。失敗した要素は`{ index, type, reason }`として記録して残りを続行する。全要素がスキップされた場合・`shapes`が空配列の場合も`ok: true`（図形0個）。スキップ1件ごと・全体失敗時に`console.warn`を出す。この`try/catch`は図形クラスの実装不具合による例外も吸収するため、理由欄に検証メッセージ以外が出た場合はデータ不正ではなく実装不具合を疑うこと。
        *   **マイグレーションと版の追加手順** : マイグレーション表は「版nの作業データを受け取り版n+1の**新しい**オブジェクトを返す関数」の対応表で、関数は引数を書き換えてはならない（現行版と同じ版の入力はコピーせずそのまま読むため、書き換えると呼び出し元の作業データやUndo履歴のスナップショットが壊れる。履歴のスナップショットは凍結されているため、書き換えようとすると例外→全体の読み込み失敗となり、その取り消し・やり直しは無効になる）。変換不能時はthrowしてよい（全体失敗になる）。版を追加する手順は①マイグレーション表へ`[旧版]: (doc) => 新版のdoc`を追加 ②現行版番号（唯一の定義箇所）を+1 ③図形クラスの`toJSON`/`fromJSON`を新版の図形データへ更新、の順とする。
    *   **CanvasStorage.js** : ブラウザ内保存先（IndexedDB）へのキャンバス記録（2章）と「最後に開いていたキャンバスの識別子」の読み書き。IndexedDBのAPIを呼ぶ唯一のモジュールで、importを持たず、DOM・図形種別・図形固有のプロパティ名・作業データ形式の知識を持たない（`document`・`id`は不透明に扱い、記録の内容の検証は呼び出し側）。保存先の定数は`STORAGE_CONFIG`（凍結。exportしない。唯一の定義箇所）。
        *   **公開API** : `open()`、`getAllRecords()`、`getRecord(id)`（無ければ`null`）、`putRecord(record)`（新規・上書き兼用）、`renameRecord(id, name)`（1つのトランザクション内で名前のみを書き換え、`updatedAt`・`document`は変えない。記録が無ければ`false`）、`deleteRecord(id)`（記録が無くても成功）、`getLastOpenedId()`（文字列でなければ`null`）、`setLastOpenedId(id)`。いずれも`Promise`を返し、失敗時はrejectする（捕捉は呼び出し側の責務）。`open()`前の呼び出しはrejectする。`indexedDB`が無い・開けない（プライベートブラウズ等）場合は`open()`がrejectし、失敗後に再度呼ぶと開き直しを試みる。
        *   **書き込み順序の保証** : すべての読み書きは呼び出し時点で同期的にトランザクションを生成し（`await`を挟まない）、トランザクションの完了（`oncomplete`）で解決する。IndexedDBは範囲が重なるreadwriteトランザクションを生成順に実行するため、書き込みは呼び出し順に反映される（`CanvasLibrary`の順序保証はこれに依存する。この性質を崩す変更をしないこと）。
        *   **版の追加手順** : `STORAGE_CONFIG`の`databaseVersion`を+1し、ストア作成処理（`onupgradeneeded`）に旧版からの移行を追加する。現状は版1のみで、他のタブが古い版で開いている場合の`onversionchange`は扱っていない（版を上げる際は自タブの接続を閉じる処理の追加を検討すること）。
    *   **DocumentFileIO.js** : 作業データファイル（作業データ形式のJSON文字列を内容とするファイル。既定の拡張子`.json`）のブラウザ内での読み書き（`Blob`のダウンロード・`File`の読み取り・ファイル名とキャンバス名の変換）。作業データの中身は解釈せず（文字列として受け渡す）、importを持たず、図形種別・作業データ形式・版の知識を持たない。`CanvasStorage`と同じくインスタンスとして生成して`CanvasFileOperations`へ注入する（状態は持たない）。流れは3章9.。
        *   **公開API** : `downloadText(text, canvasName): void`（`Blob`→オブジェクトURL→非表示の`<a>`のclick→remove。URLの解放は`try/finally`で必ず予約し、ダウンロードの開始がclickより遅いブラウザがあるため一定時間後（定数`OBJECT_URL_REVOKE_DELAY_MS`＝10000ms）に行う。準備中の例外は呼び出し元へ投げる）／`readText(file): Promise<string>`（`file.text()`。UTF-8。失敗時はreject）／`getFileName(file): string`／`toFileName(canvasName): string`／`toCanvasName(fileName): string`。
        *   **ファイル名の変換規則** : `toFileName`はファイル名に使えない文字（`\ / : * ? " < > |`と制御文字）を`_`へ置換し、前後の空白と末尾のピリオド・空白を除き、空なら既定の名前`無題`とし、末尾に`.json`を付ける（連番は付けない。キャンバス名が`a.json`なら`a.json.json`で、開くと`a.json`へ戻るため往復で名前が変わらない）。`toCanvasName`は末尾の`.json`（大文字小文字を区別しない）を除くのみで、名前の長さ・空の扱いの規則（「無題 n」への置換）は`CanvasLibrary`の知識のため持ち込まない。
    *   **CodeExporter.js**（未実装） : ゲームで再利用可能なJavaScript(ESM)コードの出力を担当。出力フォーマットの詳細は、当該Phaseの実装REQ/RESで確定させる。
    *   **CodeImporter.js**（未実装） : 出力されたJSファイルを解析し、`VectorModel` に再ロードする。
