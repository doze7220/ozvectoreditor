*   **CanvasManager.js** : Canvasへの純粋な描画（レンダラーの責務）。状態は持たない。`render(shapes, { hoveredId, selectedIds, draftLine, selectionRect, view } = {})`の形で呼び出される（第2引数は省略可、省略時は通常描画のみ。`selectedIds`は選択集合のid配列、`selectionRect`はワールド座標の対角2点で正規化不要）。`view`（`{scale, offsetX, offsetY}`、省略時は倍率1.0・オフセット(0,0)）と`resize()`で算出したdpr（`#pixelRatio`）を合成した描画変換を毎フレーム`setTransform`で明示設定する。クリアは変換の影響を受けずにバッファ全体を消去する。図形より先に、ワールド座標上の背景グリッド（細線10/太線100、画面上の間隔が8px未満なら10倍ずつ繰り上げ、線幅は画面上1px一定、可視範囲のみ）と、ワールド座標の原点(0, 0)を示す原点表示（`x = 0`/`y = 0`の軸線は可視範囲内のみ、原点に十字＋円の原点マーク。線幅・マークの大きさは`÷ scale`で画面上一定。`save()`/`restore()`でスタイルを後続へ残さない）を描く。初期表示・`ViewTransform.reset()`時は原点がキャンバス左上に位置する。軸線はグリッド線と重なって描かれるため、グリッド・原点表示の色を変える場合は両者の見分けやすさを再確認すること。可視範囲の計算はprivate`#getVisibleWorldBounds()`に一本化され、背景グリッドと原点表示が共用する。これは現在の描画変換から求めるため、ワールド座標の描画変換を設定した後（変換を変えていない区間）に呼ぶこと。また対角2隅のみを写すため、回転・せん断を含まない描画変換（拡大縮小＋平行移動）を前提とする（ビューに回転を加える場合は四隅を写す実装へ変更が必要で、グリッド・原点表示の両方に影響する）。描画順は「背景グリッド → 軸線・原点マーク → 全図形の`draw(ctx)`（＋`hoveredId`と一致する図形の`drawHover(ctx, view.scale)`）→ 選択集合に含まれる図形の`drawHandles(ctx, view.scale)`（図形配列の順。複数選択時に前面の図形が背面図形のハンドルを覆わないよう、全図形の描画後にまとめて描く2パス）→ `draftLine`の`draw(ctx)` → 選択矩形」であり、補助描画はいずれもポリモーフィックに呼び出す（倍率は図形種別によらず一律に渡す）。選択集合の所属判定は`render()`内のローカルな`Set`で行い、インスタンスに状態は持たない。選択矩形は画面上1pxの破線＋薄い半透明塗りで常に最前面に描く（線幅・破線は`÷ scale`で画面上一定。描画側では正規化しない）。ビュー変換状態は保持しない（値は引数で受け取り、`ViewTransform`はimportしない）。dprの算出とバッファサイズの同期は公開メソッド`resize()`が担い（変換の適用は`render()`が行う）、コンストラクタからの初期化と`main.js`からのウィンドウリサイズ時の再同期の両方から呼び出される。`resize()`は`render()`の呼び出しを行わない（再描画トリガーは`main.js`側の責務）。
