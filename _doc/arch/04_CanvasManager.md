*   **CanvasManager.js**：Canvasへの純粋な描画（レンダラーの責務）。
    *   **公開メソッド**：`render(shapes, { hoveredId, draftShape, selectionRect, view, snapPoint, outline, darkBackground, showGrid, vertexHandles, scaleFrame } = {})`（Phase 10-01で足した`scaleFrame`＝外枠とハンドルの位置`{ bounds, handles: [{ name, x, y }], corners? }`（`corners`はPhase 10-02で足した省ける4点`[{ x, y }]`＝回した外枠の角。後述）。省略・`null`では何も描かず今までと同じ見た目。どのモードか・図形・選択状態を知らず、呼び出し側が`core/ScaleHandleRules.collectScaleFrame`の結果（Phase 10-02から`core/RotationRules.resolveDisplayedScaleFrame`を通した値。回している間は傾いた外枠）を渡す。`outline`＝アウトライン表示・`darkBackground`＝背景が黒・`showGrid`＝グリッドの表示。省略時は偽・偽・真で、従来と同じ見た目。Phase 08-02aで足した`vertexHandles`＝頂点のハンドルの一覧`[{ shapeId, handles: [{ x, y, selected }] }]`（省略時は空）。どのモードかは知らず、呼び出し側が渡す）・`resize()`。呼び出し元は`main.js`。Interrupt `261123_1213`で`selectedIds`・`showHandles`と、選択集合の図形の`drawHandles`を描く段を消した（`main.js`が常に`showHandles: false`を渡し、どのモードでも呼ばれなかったため）。
    *   **持たないもの**：図形データ・選択状態・ビュー変換状態・表示の状態（値は引数で受け取り、`ViewTransform`・`DisplayState`はimportしない）。保持するのはCanvas要素・2Dコンテキスト・dprのみ。
    *   **描画順**：背景の塗り（内部バッファ全体を配色の組の背景色で`fillRect`）→ 背景グリッド（`showGrid`が偽なら描かない。軸線・原点マークは常に描く）→ 軸線・原点マーク → 全図形の`draw(ctx)`（`outline`が真なら`drawOutline(ctx, view.scale, 配色の組のアウトラインの色)`。＋ホバー図形の`drawHover(ctx, view.scale)`）→ 頂点のハンドル（`vertexHandles`。同じ位置＝全図形の描画の後・作成中の図形の前。選ばれていない頂点は画面上8pxの白い四角・青い枠`#4a90e2`・線幅1.5px、選ばれている頂点は塗りを枠と同じ青`#4a90e2`にして見分ける。大きさ・線幅は`÷ view.scale`で画面上一定。倍率が正の有限値でなければ描かない。定数`VERTEX_HANDLE_*`は`CanvasManager`内）→ **外枠とそのハンドル（`scaleFrame`。Phase 10-01。頂点のハンドルの後・作成中の図形の前。非`null`のときだけ非公開の`#drawScaleFrame(frame, scale)`を呼ぶ。倍率が正の有限値でなければ描かない。外枠の線を線幅`SCALE_FRAME_LINE_WIDTH ÷ view.scale`（画面上1px）・色`SCALE_FRAME_STROKE_COLOR`（`#4a90e2`）で描く（**Phase 10-02**：`Array.isArray(frame.corners) && frame.corners.length === 4`なら`beginPath` → `moveTo(corners[0])` → `lineTo(corners[1..3])` → `closePath` → `stroke`で傾いた四角形を、そうでなければ今までどおり`bounds`を`strokeRect`。回している間だけ`corners`が来る。ハンドルの四角・線の色・太さは不変）。`handles`の並びの順に、選ばれていない頂点のハンドルと同じ見た目（`VERTEX_HANDLE_*`を流用。`÷ view.scale`）で描く＝並びの後ろ（角）が前面に重なる。`save`/`restore`。位置を受け取って描くだけで、状態・図形種別・選択・操作モード・回転の角度を判定しない（傾いた四角形は受け取った`corners`をつなぐだけ。ハンドルの四角は傾けず、受け取った位置に描く）。定数`SCALE_FRAME_*`は`CanvasManager`内）** → `draftShape`の`draw(ctx)`（`outline`が真なら`drawOutline`）→ 吸い付きの表示（`snapPoint`が非`null`のとき。中を青で塗った正方形で、大きさ・線幅を`÷ view.scale`して画面上で一定にする。定数は`CanvasManager`内）→ 選択矩形。補助描画はいずれもポリモーフィックに呼ぶ。`draw`に`t`は渡さない。
    *   **配色の組**：白・黒の2組（定数`COLOR_SCHEMES`は`CanvasManager`内。背景・グリッドの細線/太線・軸線・原点マーク・アウトラインの線の色）。`darkBackground`が真なら黒の組、偽なら白の組。白の組は07-03前の見た目と同じ値。**背景の色はCSSに置かず（`index.html`の`#editor-canvas`に背景色を付けない）、配色の組が唯一の定義箇所**。ホバーの強調・ハンドル・頂点のハンドル・外枠とそのハンドル・範囲選択の矩形・吸い付きの表示の色は組に含めない（黒の背景でも見える見込み）。
    *   **グリッドの間隔**：`core/GridSpacingRules.computeGridSpacing`で求める（定規・ステータスバーのグリッド1マスの表示と共有。間隔の規則を1か所にするため）。倍率の検査は`CanvasManager`に残る。
    *   **`resize()`**：コンストラクタとウィンドウリサイズ時（`main.js`）から呼ばれる。`render()`を呼ばない（再描画トリガーは`main.js`側の責務）。
    *   **制約**：可視範囲の計算は対角2隅のみを写すため、回転・せん断を含まない描画変換を前提とする（ビューに回転を加える場合は四隅を写す実装へ変更が必要で、グリッド・原点表示の両方に影響する）。軸線はグリッド線と重なって描かれるため、色を変える場合は見分けやすさを再確認する。初期表示（開く・新規作成・開く（ファイル）・起動時の復元）とビューのリセット時は、原点がキャンバス要素全体（定規の分だけ狭まったキャンバスの領域）の中央・倍率100%に位置する（`main.js`の`resetViewToCenter`。ウィンドウの大きさの変更には追従しない。インポートでは表示を変えない）。
