*   **shapes/** : 図形種別ごとのデータ保持・描画・当たり判定・図形データとの相互変換を担う。`Line`/`Curve`/`Rect`/`Ellipse`はいずれも同一シグネチャの12メソッド（`draw(ctx, t)`、`drawHandles(ctx, viewScale = 1)`、`drawHover(ctx, viewScale = 1)`、`hitTest(x, y, tolerance)`、`hitTestHandle(x, y, tolerance)`、`setVertex(vertexIndex, x, y)`、`translate(dx, dy)`、`updateDraftEnd(x, y)`、`getVertexIndexForHandle(handleName)`、`intersectsRect(minX, minY, maxX, maxY)`、`toJSON()`、`static fromJSON(data)`）を自律実装しており、この契約を満たす限り`core/`層（`VectorModel`/`CanvasManager`/`InputTracker`）・`io/`を変更せずに作成・選択・範囲選択・再編集・作業データの変換/復元フローへ組み込める（`ShapeFactory`の対応表への登録は必要。手順は`ShapeFactory.js`の項）。新規図形を追加する際はこの12メソッド契約を満たすこと。各図形クラスのクラスJSDocは12メソッド契約を列挙しているため、契約のメソッドを増減する場合は4クラスのクラスJSDocも更新すること。`intersectsRect`は範囲選択用の交差判定で、引数はワールド座標の正規化済み（min ≤ max）軸平行矩形（境界を含む）。描画されている輪郭線の中心線（`strokeWidth`は含めない）が一部でも掛かれば`true`を返し、塗り内部は判定しない（Line・Rectは線分の厳密判定、Curve・Ellipseは輪郭を100分割した折れ線による近似判定。Ellipseの弧は描画されている弧部分のみが対象）。`drawHandles`/`drawHover`の`viewScale`は表示倍率であり、ハンドルの大きさ・枠線幅・ホバー強調の上乗せ幅等の補助表示を画面上一定に保つため`÷ viewScale`で換算する。図形本体の`draw`は倍率を受け取らない（線幅は倍率に比例して表示される）。図形クラスが扱う座標はすべてワールド座標であり、オフセットは渡されない。各メソッドの内部実装（描画方法・当たり判定アルゴリズム等）は各ファイルのJSDocを参照。
    *   **図形データとの相互変換（`toJSON`/`fromJSON`）** : `toJSON()`は2章の図形データの形の新しいプレーンオブジェクトを返し、`static fromJSON(data)`は図形データから新しいインスタンスを生成する。どちらの方向でも内部配列・頂点オブジェクトを共有しない（`data`内の配列・オブジェクトも流用せず、座標値から新規に作る）。`fromJSON`は次の場合に`Error`をthrowする：`data`がプレーンオブジェクトでない／`data.type`が自クラスの図形種別でない／`points`が配列でない、または要素数が自クラスの頂点数と一致しない／頂点がオブジェクトでない、または`x`/`y`が有限の数値でない／`strokeColor`が文字列でない／`strokeWidth`が有限の数値でない、または0以下（Canvasは0以下の線幅の代入を無視して直前の値を残すため）。`id`は検証せずそのまま保持し（正規化は`VectorModel.replaceAllShapes`の責務）、余分なプロパティは無視する。各図形クラス・`ShapeFactory`は`try/catch`を持たない（捕捉は`DocumentSerializer`）。往復（`toJSON`→`fromJSON`）で図形データの内容と描画・当たり判定の結果は一致する。
    *   **変換の実装上の注意** : 検証ロジックは各図形クラスのprivate staticヘルパーとして個別に持つ（共通モジュールはない）ため、図形データの共通項目の規則を変える場合は4クラスすべてを追従させること。`fromJSON`はコンストラクタで仮生成した後に頂点を`data`の値で設定し直す手順であるため、将来コンストラクタに派生値の初期化等を加える場合は、頂点の差し替え後に整合が崩れないか確認すること。図形データの形を変える場合は`DocumentSerializer`の版の追加手順に従うこと。
    *   **Line.js** : 直線（`points`配列は持たず、`x1, y1`=始点／`x2, y2`=終点のプロパティで保持する。図形データでは`points`2点[始点, 終点]へ変換する）。`hitTestHandle`の戻り値は`'start'|'end'|'move'|null`（`move`は中点）。
    *   **Curve.js** : 2次ベジェ曲線（3頂点：`points[0]`=始点／`points[1]`=制御点／`points[2]`=終点）。`move`ハンドルは持たない（`hitTestHandle`の戻り値は`'start'|'end'|'control'|null`）。
    *   **Rect.js** : 矩形（4頂点：`points[0]`=topLeft／`points[1]`=topRight／`points[2]`=bottomRight／`points[3]`=bottomLeft）。コンストラクタは対角2点から4点を算出するのみで、矩形維持のための正規化は行わない（4隅の自由変形が可能）。`fromJSON`も4頂点を独立に採用し、軸平行矩形への再計算は行わない。
    *   **Ellipse.js** : 円・楕円・弧（5頂点：`points[0]`=中心／`points[1]`=右端制御点／`points[2]`=上端制御点／`points[3]`=開始角制御点／`points[4]`=終了角制御点）。図形種別`type`（`'circle'`|`'arc'`）で振る舞いも分岐する。開始角・終了角は`type`から決まる固定値のため図形データに保存しない（弧の角度編集を実装する際は保存対象へ加え、作業データ形式の版を上げること）。`fromJSON`は`points[3]`/`[4]`も再計算せず保存値を採用する（描画・当たり判定は`points[0..2]`と角度のみに依存し、以後のハンドル操作で正準位置へ再計算される）。`type`の検証用に自クラスの受理種別一覧を持つため、扱う種別を増やす場合はこの一覧・コンストラクタの種別による分岐・`ShapeFactory`の対応表の3箇所を揃えて更新すること。
