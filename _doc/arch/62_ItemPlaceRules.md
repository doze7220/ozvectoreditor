*   **ItemPlaceRules.js**：アイテムの入る場所（行の上・行の下・フォルダの中・一番下）の値と、その場所へ入れる・動かす計算、アイテムの位置の照会を、状態を持たない関数として提供する（Phase 11-04bで新設。流れは`PROJECT_ARCHITECTURE.md`2章「描き込む先」・3章14.・28.）。
    *   **公開**：`PLACE_KIND`・`findItemLocation(items, id)`・`insertItemsAt(items, place, addedItems)`・`canMoveItems(items, ids, place)`・`moveItems(items, ids, place)`と、typedef`ItemPlace`・`ItemLocation`。
    *   **`PLACE_KIND`**：`{ ABOVE: 'above', BELOW: 'below', INSIDE: 'inside', BOTTOM: 'bottom' }`（凍結）。`'above'`＝`id`の行のすぐ上（同じ並びのすぐ後ろ。並びは配列の後ろが前面なので、一覧ですぐ上）、`'below'`＝`id`の行のすぐ下（同じ並びのすぐ前。**ドロップ位置だけが使う**）、`'inside'`＝`id`のフォルダの中の一番上、`'bottom'`＝`id`のフォルダ（`id`が`null`ならいちばん外側）の中の一番下。typedef`ItemPlace`＝`{ kind, id: string|null }`（`id`が`null`になるのは`'bottom'`のいちばん外側だけ）。描き込む先は場所のうち`'above'`・`'inside'`・`'bottom'`、または`null`（無し＝いちばん外側の末尾＝一番上。`54_InsertTargetRules.md`）。
    *   **`findItemLocation(items, id)`** → `{ parentId: string|null, siblings: Item[], index: number, ancestorIds: string[] }|null`：前順で最初に見つかったアイテム（図形もフォルダも）の、入っている並び（引数の配列そのもの）・その中の添字・入っているフォルダのid（外側から。`parentId`はその最後で、いちばん外側なら`null`）。無ければ`null`。typedef`ItemLocation`。
    *   **`insertItemsAt(items, place, addedItems)`** → 新しい入れ子：`place`の場所へ`addedItems`を順のまま入れる。`'above'`はその行のすぐ後ろ、`'below'`はすぐ前（どちらも基準がフォルダでも「そのフォルダ行の」すぐ上・すぐ下）、`'inside'`は中の末尾（一番上）、`'bottom'`は中の先頭（一番下）。`place`が`null`・`id`のアイテムが無い・`'inside'`／`'bottom'`の`id`がフォルダでない（図形）ときは、いちばん外側の末尾（一番上）。`{ kind: 'bottom', id: null }`だけはいちばん外側の先頭（一番下）。通り道のフォルダだけ新しいオブジェクトにし（非公開`updateListAt`）、引数を書き換えない。使う側：`VectorModel`の`#placeAdded`（描いた図形・追加）・`GroupEditor.addEmptyGroup`・`moveItems`。旧`ItemTreeRules.insertItemsAbove`（図形が基準のときだけの「すぐ上」）の後継で、`'above'`の値は同じ（`insertItemsAbove`は消した）。
    *   **`canMoveItems(items, ids, place)`** → boolean（`ids`は`Set`）：`place`が`null`なら偽。`{ bottom, null }`は真。`place.id`のアイテムが無ければ偽。そのアイテムの`ancestorIds`に`ids`のものがあれば偽（動かすフォルダの中）。`'inside'`・`'bottom'`で`place.id`が`ids`にある（自分の中）か、基準がフォルダでなければ偽。ほかは真（自分自身の行の上下は真）。**「自分の中・自分の中のフォルダの中へは入れられない」の唯一の判定箇所**で、`ItemListWiring`の`canDrop`と`moveItems`が使う。
    *   **`moveItems(items, ids, place)`** → 新しい入れ子または`null`：`canMoveItems`が偽、または`ids`のアイテムが1つも無ければ`null`。手順は(1)`pickItems(items, ids)`で動かすまとまり（前順）、(2)`insertItemsAt(items, place, [目印])`（目印＝`{ kind: 'group', id: Symbol('place'), children: [] }`。一時的な値で結果には残らない）、(3)`removeItems(…, ids)`、(4)`mapSiblingLists`で目印をまとまりへ置き換える。目印を先に置いてから抜くため、動かすまとまり自身の行の上下を指しても位置がずれない。抜いたフォルダが空になっても残る（`removeItems`の規則）。動かさないアイテム・折りたたみ等の属性は保たれる。
    *   **読むもの**：渡された入れ子の`kind`・フォルダの`id`・`children`と、`itemIdOf`の結果（図形の`shape.id`）だけ。図形のほかのプロパティを読まない。
    *   **知らないこと**：DOM・`VectorModel`・図形クラス・図形種別・選択・折りたたみ・描き込む先の決まり方・操作モード・履歴。importは`core/ItemTreeRules`（`ITEM_KIND`）・`core/GroupTreeRules`（`itemIdOf`・`pickItems`・`removeItems`・`mapSiblingLists`）のみ。引数を書き換えない。
    *   **使う側**：`core/InsertTargetRules`（`PLACE_KIND`・`findItemLocation`）・`core/ItemRowRules`・`core/ListDragRules`（`PLACE_KIND`）・`core/SoloVisibilityRules`（`findItemLocation`の`siblings`・`ancestorIds`から、その行と上のフォルダ・それぞれの兄弟を求める。Phase 11-05。`65_SoloVisibilityRules.md`）・`core/VectorModel`（`PLACE_KIND`・`insertItemsAt`）・`edit/GroupEditor`（`insertItemsAt`）・`edit/ShapeOrderEditor`（`moveItems`）・`wiring/ItemListWiring`（`canMoveItems`）。`edit/ → core/`の例外に`GroupEditor`・`ShapeOrderEditor`が加わる（`14_edit.md`）。
    *   **置き場所の理由**：入る場所の値と、入れる・動かす計算を1か所に置くため（描き込む先・行のドラッグ・作るボタン・貼り付けと複製が同じ「場所」で話すため）。`ItemTreeRules`は図形のプロパティを読まない責務で`id`を読む計算を置けず、`GroupTreeRules`は入れ子を動かす基本の計算を持つため、場所という新しい概念の計算を状態を持たない別のファイルに分けた。循環は無い（`ItemTreeRules` ← `GroupTreeRules` ← `ItemPlaceRules` ← `InsertTargetRules`・`ItemRowRules`・`ListDragRules`・`SoloVisibilityRules`。`ItemPlaceRules`は`ItemStateRules`をimportしない。Phase 11-05）。
