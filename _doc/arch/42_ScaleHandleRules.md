*   **ScaleHandleRules.js**：選択（`V`）の外枠と外枠のハンドルの出し方・位置・当たり・カーソルの向きと、引いたときの倍率・動かない点・スナップの当て方・変換の組み立てを、状態を持たない関数として提供する（Phase 10-01で新設。流れは3章25.）。
    *   **公開**：定数`SCALE_HANDLE_NAMES`（ハンドル名の唯一の定義。`nw`・`n`・`ne`・`e`・`se`・`s`・`sw`・`w`）・`SCALE_HANDLE_HIT_SCREEN_PX`（6。当たりの正方形の一辺の半分。画面上px）・`SCALE_EDGE_HANDLE_MIN_SCREEN_PX`（24。辺のハンドルを出す外枠の辺の長さの下限。画面上px＝ハンドル3つ分）、関数`collectScaleFrame(mode, bounds, viewScale)` → `ScaleFrame|null`・`hitTestScaleHandle(frame, point, viewScale)` → ハンドル名|`null`・`resolveScaleHandleCursor(name)` → CSSの`cursor`値|`null`・`computeBoundsScale(input)` → `BoundsScale`・`toScaleTransform(scale)` → `AffineTransform`、`collectFrameCorners(bounds)` → 外枠の4つの角`[{ name, x, y }]`（`nw`・`ne`・`se`・`sw`の順。幅0・高さ0でも4つ。Phase 10-02）・`computeFrameCenter(bounds)` → 外枠の中心`{ x, y }`（`(min + max) / 2`。Phase 10-02）、typedef`ScaleHandle`・`ScaleFrame`・`BoundsScale`・`BoundsScaleInput`。非公開（exportしない。JSDocあり）：`isPositiveFinite`・`isFiniteBounds`・`readAxis`（Phase 10-02で第6引数`center`を足した。`computeBoundsScale`が`computeFrameCenter(bounds)`を1回求めて渡す）・`snapAxisScale`、typedef`AxisState`。いずれも新しいオブジェクトを返し、引数を書き換えない。規則の詳細（各関数の手順）の正本はJSDoc。
    *   **`collectScaleFrame`**（描画と当たりが共有する唯一の組み立て）：`mode`が選択（`OperationMode.SELECT`）以外・`bounds`が`null`・`viewScale`が正の有限でない・`bounds`の値が有限でない・幅も高さも0のときは`null`（外枠もハンドルも出さない）。幅だけ0なら`n`・`s`、高さだけ0なら`w`・`e`のハンドルだけ。それ以外は角の4つを常に出し、辺のハンドルは「その辺の長さ×表示倍率が24px以上」のときだけ出す。角のハンドルの位置は`collectFrameCorners`、辺のハンドルの位置は`computeFrameCenter`（`cx`・`cy`）から作る（**外枠の角の位置・中心の式を1か所にする**＝Phase 10-02。`RotationRules`が回転の範囲・回転の中心・回した外枠の角に同じ関数を使い、式を写さない）。`handles`の並びは辺→角で、**後ろほど優先**（描画は前から、当たりは後ろから探す＝角が優先。図形の描画順・当たりの約束と同じ）。`bounds`は線を含まない外枠（`ShapeExtentReader.getSelectedGeometryBounds()`の結果）で、規則は外枠を求めない（外枠は`core/`が`io/`・`edit/`をimportできないため引数で受ける）。
    *   **`computeBoundsScale`**（倍率と動かない点の計算とスナップの当て方の唯一の箇所。手順1〜8はJSDocが正本）：引くハンドルの軸（`'w'`を含めば横の動く辺は`minX`、`'e'`なら`maxX`、`'n'`・`'s'`は縦）ごとに、動かない点（`Alt`＝`fromCenter`なら外枠の中心（`computeFrameCenter`）、そうでなければ反対側の辺。引かない軸は中心）と丸めない倍率`raw = (カーソル − 動かない点) / (動く辺の元の位置 − 動かない点)`を求め、角で`Shift`（`keepAspect`）なら**外枠に対するカーソルの動きの割合が大きいほう（`|raw − 1|`の大きいほう。同じなら横）**に縦横の倍率の大きさをそろえる。長さ0の軸は引かない軸と同じ（倍率1）。**スナップの当て方**：`step`が非`null`なら、引いているハンドルの位置（カーソル位置）を`UnitSnapRules.roundPointToUnit`で刻みの目へ丸めた絶対位置を目標にして倍率を割り算で求める（動かした量を刻みの倍数にするのではなく、引いている辺・角そのものを目に乗せる。外枠の辺が半端な位置でも引くとすぐ目に乗る）。丸める軸は、角で`Shift`なしは引く軸すべて、角で`Shift`は倍率を決めた向きだけ（倍率を決めた向きの符号は丸めた後の値から、もう一方の向きの符号はその向きの`raw`の符号から取る）、辺はその軸だけ。**丸めた結果の倍率がちょうど0なら`previous`（直前の倍率）のまま**（倍率0＝図形がつぶれる形にしない。符号は`previous`の符号）。辺で`Shift`のとき、もう一方の軸は`|引く軸の倍率|`（裏返らない。動かない点は中心）で、直前の倍率が使われる場合は`previous.scaleY = |previous.scaleX|`が保たれる。裏返りは倍率が負になる形で表す（引く辺が動かない点を越えたとき）。未知のハンドル名は`Error`。精度：倍率は割り算で求めるため、ちょうど表せない値では引いた辺の位置が刻みの目から`1e-12`程度ずれることがある（許容）。
    *   **`toScaleTransform`**：`{ a: scaleX, b: 0, c: 0, d: scaleY, e: originX − scaleX·originX, f: originY − scaleY·originY }`（動かない点を固定した縦横の拡大縮小・裏返し。`b`・`c`は0なので円・弧の`createTransformed`にも渡せる）。
