*   **index.html**：スタイルはCSSファイル分割せず`<style>`タグに内包する。配置・見た目はマークアップとCSSコメントを正とする。
    *   **画面の領域**：上端にツールバー（`#toolbar`）、下端にステータスバー（`#status-bar`）、その間にキャンバスの領域、フロートウィンドウのツールパレット等。寸法は`<style>`先頭の`:root`のカスタムプロパティ（`--toolbar-height`・`--statusbar-height`・`--canvas-area-*`・`--float-window-*`）が唯一の定義箇所。キャンバス（`#editor-canvas`）と読み込み中の覆い要素は、まとめた1つのCSSルールで同じキャンバスの領域に置く（`<canvas>`は置換要素で`left`・`right`の両指定では伸びないため、`width`/`height`をCSSの変数で明示する）。07-03で定規を足すときに直すのは`--canvas-area-top`と`--canvas-area-left`の2行で、幅・高さ・フロートウィンドウの既定の位置の基準はそれに追従する。**キャンバスに枠線・内側の余白を付けない**（`InputTracker.getScreenCoordinate`の`clientWidth / rect.width`の比が1でなくなり、座標がずれるため。領域を狭めるときは`:root`で行う）。重なりの順（`z-index`）：キャンバス1 → 覆い要素5 → ツールバー・ステータスバー8 → フロートウィンドウ10以上（`WindowManager`の最前面化で増える一方）。ブラウザのウィンドウの大きさの変化は既存の`resize` → `renderCurrentState`の経路で足りる。
    *   **ツールバー・ステータスバー**：固定の要素で、フロートウィンドウではない（`WindowManager`の管理対象外。イベント遮断も不要。キャンバスの子ではない兄弟要素のため、その上の押下・クリックはキャンバスの操作にならない）。高さ固定・1行（`flex-wrap: nowrap; overflow: hidden`）で、収まらない右側の項目は画面の外へ切れる（折り返し・横スクロール・省略メニューは無い。ステータスバーのキャンバス名だけは先に`…`で省略される）。`user-select: none`。項目はまとまりごとに置く：ツールバーは`<div class="toolbar-group">`、ステータスバーは左右の`.status-bar-side`の中に`<div class="status-bar-group">`。まとまりの区切りは隣接セレクタ（`.toolbar-group + .toolbar-group`・`.status-bar-group + .status-bar-group`）の`border-left`で付け、区切りの要素は置かない。項目を足すときはまとまりを足すだけで既存のまとまりを変えない。保っているid（`main.js`が`getElementById`で解決する）：`#launcher-canvas`・`#history-undo`・`#history-redo`・`#selection-delete`・`#selection-join`（ツールバー）、`#option-style-group`・`#option-stroke-toggle`・`#option-stroke-color`・`#option-stroke-color-frame`・`#option-fill-toggle`・`#option-fill-color`・`#option-fill-color-frame`・`#option-stroke-width`・`#option-order-group`・`#option-bring-to-front`・`#option-bring-forward`・`#option-send-backward`・`#option-send-to-back`（ツールバーのオプションバー。`main.js`はまとまりのルート要素`#option-style-group`・`#option-order-group`だけを解決し、中の要素はUI部品がルート要素内で解決する）、`#canvas-name-display`・`#view-zoom-display`・`#view-reset`（ステータスバー）。
    *   **ボタンの見た目**：ツールバー・ステータスバー・ツールパレットのボタンはアイコンのみ（`class="tool-btn icon-btn"`。文字のラベルは付けない）。アイコンは`index.html`のそのボタンの中身の1か所だけに書く（JSはボタンの中身を書き換えず、CSSの`content`で重ねない）。説明とショートカットは`title`に書く。`.icon-btn`は`.tool-btn`のルールの後に置き、大きさと中央寄せだけを上書きする（押し込み・押せない・ホバーの見た目は`.tool-btn`のルールをそのまま使う）。オプションバーの線・塗りのON/OFFのボタンは`aria-pressed`（`"true"`／`"false"`／`"mixed"`）が状態の唯一の持ち方で、`.active`は併用しない。ON＝押し込みは`.tool-btn.active`のルールのセレクタに`.tool-btn[aria-pressed="true"]`を足して共有し、そろっていない（`mixed`）は破線の枠のルール1つ。
    *   **非活性の表現**：ボタン単体の押せない状態はHTMLの`disabled`属性と`.tool-btn:disabled`のみで表す。フロートウィンドウ全体を非活性にする`.disabled`クラスは以前あったがPhase 07-01で削除した（CSSのルールごとなくなった。ツールパレットは常に押せる）。
    *   **ショートカットの表記**：各ボタンの`title`属性にショートカットキーを併記している（ツールパレットの図形のボタンは`SHAPE_TYPES`の並びに対応する数字）。`KeyboardShortcuts.js`の`SHORTCUT_BINDINGS`と手動で同期する必要がある。結合ボタン`#selection-join`の`title`は`(J)`を併記している。オプションバーの重なり順の4ボタンの`title`は`最前面へ (Home)`・`前へ (PageUp)`・`後ろへ (PageDown)`・`最背面へ (End)`。結合ボタンは`disabled`で始まり、`main.js`の`syncJoinButtonState`が同期する。
    *   **読み込み中の覆い要素**：`#canvas-loading-cover`は`hidden`を付けずに表示状態で始める（`main.js`の実行前からキャンバスへのマウス入力を遮るため）。キャンバスの領域だけを覆い、ツールバー・ステータスバー（`z-index`が上）は読み込み中も押せる。`.canvas-loading-cover[hidden] { display: none; }`の指定は必須。`main.js`の初期化が途中で失敗すると覆いが消えない（その場合はコンソールのエラーを確認する）。
    *   **ツールパレット**：`#window-tool-palette`は静的に置き（`hidden`なし＝常に表示。`WindowManager`は起動時にDOMにある`.float-window`だけを検知するため）、`×`は無い。見出し（`.window-header`）に文字は置かない（幅44pxに収まらないため。ドラッグ用）。ボタンのidは`tool-${toolId}`（`toolId`は`ToolRules`の`TOOL_IDS`の値＝`select`・`pan`と`SHAPE_TYPES`の値）。`ToolPalette`が起動時にこの規則で照合・配線する。パレット内では、ツールのボタン以外の要素に`tool-`で始まるidを使わない（照合時に警告される）。区切りは`.tool-palette-group`の隣接セレクタ。起動時は`#tool-select`だけに`index.html`で`active`を付ける（`InputTracker`の初期モードは選択で、JSの読み込み前も押し込みを見せるため。起動時の`applyMode(OperationMode.SELECT)`が同じ結果を同期する）。旧id`#mode-select`・`#mode-create`・`#mode-pan`・`#palette-${type}`は無い。
    *   **キャンバスパレットのボタンの並び**：「＋ 新規作成」・「出力（作業ファイル）」（`#canvas-export`）・「出力（エンジン用）」（`#canvas-export-sprite`）は1行に1つずつ縦に並べ、「開く」「インポート」だけを`.canvas-file-row`で横並びにする（出力の2ボタンは文字だけで約247pxとなり、パレットの内側の幅216pxに1行で収まらないため）。`title`にダウンロードされるファイルの拡張子を書く。
    *   **キャンバスパレットのファイル選択**：非表示の`<input type="file">`を「開く」用（`#canvas-open-file-input`）と「インポート」用（`#canvas-import-file-input`）の2つ置く。どちらのボタンから開いたかの状態を持たずに済むため。1つにまとめない。`accept=".json,.js,application/json,text/javascript"`は拡張子の末尾で照合するため`.ozve.json`も選べ、スプライトのJSも選べる（`.json`は作業データファイルのため外さない。変更しない。2章「エディタで開くときの規則」）。ボタンの`title`に作業ファイル（.ozve.json）とスプライト（.js）を書く。
    *   **オプションバー**：`#toolbar`の既存3つのまとまりの右に続く2つの`<div class="toolbar-group">`（スタイル`#option-style-group`、重なり順`#option-order-group`）。静的に置き（ウィンドウではない。`WindowManager`の管理対象外）、要素idの接頭辞は`option-`。スタイルのまとまりは、線のON/OFFのボタン・線の色・塗りのON/OFFのボタン・塗りの色・太さの欄と`px`の単位の順。重なり順のまとまりは4ボタン。`value`・`checked`等の初期値は書かない（起動時に`main.js`が1回描画する。既定値を二重に書かないため）。例外：ON/OFFのボタンの`aria-pressed="false"`（`InputTracker`の`isToggleButtonElement`が`aria-pressed`属性の有無で判定するため、起動時から持たせる）と、重なり順の4ボタンの`disabled`（結合ボタンと同じ扱い。`main.js`の`syncOptionBarOrderGroup`が同期する）。塗れない形だけの選択での塗りの欄の無効表示は`disabled`属性（上の「非活性の表現」と同じ）。色の欄（`<input type="color">`）は`.option-color-frame`の`<span>`で包み、色がそろっていない・表示できない色のときは包む要素の`data-color-note`（`mixed`・`unsupported`）の`::after`で色の部分にグレーの地と赤の斜線を重ねる（`pointer-events: none`・幅を変えない。追加の要素・画像なし）。オプションバーの中では太さの欄のみ`user-select: text`（ほかに`?dev`の確認用ウィンドウの欄にも付く。ツールバーの`user-select: none`は変えない）。幅は1280pxの画面で、ツールバー全体の内容（オプションバーだけではない）が約610pxを使う見積もり（CSSコメントが正）。収まらないときは右のまとまりから切れる（重なり順→スタイルの順）。まとまりを足すときは新しい`.toolbar-group`を足すだけで既存のまとまりは変えない（`PROJECT_ARCHITECTURE.md`3章13.）。
    *   **確認用ウィンドウ**：`#window-dev-panel`は`hidden`で初期非表示。`?dev`時のみ`main.js`が表示する。
    *   **ウィンドウの既定の位置**：ツールパレットは左上、キャンバスパレットは右上、`?dev`の確認用ウィンドウはツールパレットの右隣。いずれも上端はツールバーの下（`--float-window-top`）。互いに重ならない根拠の数値（幅・画面幅の条件）は各ルールのCSSコメントを正とする（ここに重ねて書かない）。位置・表示状態は保存しない。
    *   **フロートウィンドウの`×`ボタン**：ツールパレットには`×`が無い。`PaletteLauncher`の対応表に含まれる開閉式パレット（現状はキャンバスパレットのみ）の`×`は閉じ、呼び出し口（ツールバーの`#launcher-canvas`）で開き直せる。`?dev`の確認用ウィンドウの`×`は`DevPanel`が配線して閉じる（開き直す手段は無く、再読み込みで再表示）。
