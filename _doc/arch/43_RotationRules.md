*   **RotationRules.js**：選択（`V`）の外枠の角の外側の回転の範囲の当たり・回転のカーソルの絵と向きと、回した角度・回転の変換・回している間の外枠の位置の規則を、状態を持たない関数として提供する（Phase 10-02で新設。流れは3章26.）。
    *   **公開**：定数`ROTATION_ZONE_SCREEN_PX`（20。回転の範囲の広さ。角からの画面上px）・`ROTATION_SNAP_STEP`（`Math.PI / 12`＝15°。`Shift`の刻み）・`ROTATION_CURSOR_HOTSPOT`（`{ x: 12, y: 12 }`。凍結。カーソル画像の中の位置）、関数`hitTestRotationZone(frame, point, viewScale)` → 角の名前|`null`・`resolveRotationCursor(corner)` → CSSの`cursor`値|`null`・`computeRotationCenter(frame, referencePoint)` → 基準点の位置（Phase 10-03で第2引数を足した）・`computeRotationAngle(input)` → `RotationAngle`・`toRotationTransform(center, angle)` → `AffineTransform`・`rotateScaleFrame(frame, transform)` → `RotatedScaleFrame`・`resolveDisplayedScaleFrame(frame, rotationView)` → 表示する外枠|`null`、typedef`RotationAngleInput`・`RotationAngle`・`RotationDragView`・`RotatedScaleFrame`。非公開（exportしない。JSDocあり）：定数`RIGHT_ANGLE_EPSILON`（`1e-9`）・`ROTATION_CURSOR_SVG`・`ROTATION_CURSOR_DEGREES`・`ROTATION_CURSORS`、関数`isPositiveFinite`・`normalizeZero`。オブジェクトを返す関数は新しいオブジェクトを返し（`resolveDisplayedScaleFrame`は`rotationView`が`null`なら`frame`をそのまま返す）、いずれも引数を書き換えない。規則の詳細（各関数の手順）の正本はJSDoc。
    *   **`hitTestRotationZone`**：`frame`が`null`・`viewScale`が正の有限でない → `null`。外枠のハンドルの当たり（`ScaleHandleRules.hitTestScaleHandle`）の上 → `null`（拡大縮小が優先）。外枠の矩形の内側・境界上（幅か高さが0なら線分の上）→ `null`。それ以外は、`ScaleHandleRules.collectFrameCorners`の角から`ROTATION_ZONE_SCREEN_PX / viewScale`以内（境界を含む）のうち最も近い角の名前（`'nw'`・`'ne'`・`'se'`・`'sw'`。同じ距離なら並びの先）。選択モード以外では`collectScaleFrame`が`null`を返すため当たらない（この関数は操作モードを知らない）。
    *   **`resolveRotationCursor`**（回転のカーソルの絵と向きの表の唯一の箇所）：角の名前ごとに、基準の絵（24×24のSVG。右上`ne`の向き。白い縁取りの上に黒の線）を`ne`＝0°・`se`＝90°・`sw`＝180°・`nw`＝270°傾けた`url("data:image/svg+xml,…") 12 12, auto`の形の値を返す（モジュールの読み込み時に1回組み立てる）。`nw`・`ne`・`se`・`sw`以外・文字列以外・`Object.prototype`のキー名は`null`。
    *   **`computeRotationCenter`**：引き始めの外枠の上の基準点（`ReferencePointRules.resolveReferencePointPosition(frame.bounds, referencePoint)`を返すだけ。Phase 10-03）。`referencePoint`を省く・`null`・基準点の名前でない値は外枠の中心（今までの値。式は`ScaleHandleRules.computeFrameCenter`の1か所で、`ReferencePointRules`が呼ぶ）。`InputTracker`の`#beginRotateSelection`が第7引数の`getReferencePoint()`の戻り値を、検証せずに第2引数へ渡す。基準点が中心ならドラッグの回転は今までと同じ。
    *   **`computeRotationAngle`**（回した角度を求める唯一の箇所）：画面は`y`が下向きのため`atan2`が増える向き＝カーソルを時計回りに動かす向きで、角度が正なら時計回り。(1)カーソルが中心に重なる（`dx === 0 && dy === 0`）なら`raw = previousRaw`（直前のまま）。(2)それ以外は`target = atan2(カーソル − 中心) − atan2(押した位置 − 中心)`、`delta = target − previousRaw`を`[−π, π]`へ寄せて（`delta − 2π·round(delta / 2π)`）`raw = previousRaw + delta`（±180°の境目で跳ねず、何周でも追従する）。(3)`snapToStep`なら`angle`は`raw`を最も近い15°の倍数にした値（ちょうど中間は0から遠い側。`-0`は0）、そうでなければ`angle = raw`。**座標のスナップは使わない**。戻り値の`raw`は次の呼び出しの`previousRaw`に渡す。
    *   **`toRotationTransform`**：中心の周りに`angle`だけ回す`{ a: cos, b: sin, c: −sin, d: cos, e, f }`（`e = center.x − (cos·center.x − sin·center.y)`・`f = center.y − (sin·center.x + cos·center.y)`。Canvasの`setTransform`と同じ並び。見た目で時計回りが正）。`angle`が90°の倍数から`1e-9`ラジアン以内ならちょうどの`cos`・`sin`（0・±1）を使う（`Shift`の90°・180°で矩形等の座標に`1e-16`程度の誤差を入れないため）。`angle`が0なら恒等の変換。`-0`は0にする。
    *   **`rotateScaleFrame`・`resolveDisplayedScaleFrame`**：`rotateScaleFrame`は外枠を変換で回した形`{ bounds（回す前の外枠の写し）, corners（`collectFrameCorners`の4つの角を写した点。`nw`・`ne`・`se`・`sw`の順）, handles（各ハンドルの位置だけを写す。名前・並びは同じ）}`を返す。点の写しは`shapes/ShapeGeometry.applyAffineTransformToPoint`。`resolveDisplayedScaleFrame(frame, rotationView)`は表示する外枠を選ぶ唯一の箇所で、`rotationView`が`null`なら`frame`をそのまま返し、あれば引き始めの外枠（`rotationView.frame`）を今の角度で回した形を返す（回している間は図形から求め直さない）。`main.js`の`renderCurrentState`がこれを通して`CanvasManager.render`の`scaleFrame`を作る。
    *   **読むもの**：importは`./ScaleHandleRules.js`の`SCALE_HANDLE_NAMES`・`hitTestScaleHandle`・`collectFrameCorners`と、`./ReferencePointRules.js`の`resolveReferencePointPosition`（Phase 10-03。`computeFrameCenter`はimportしなくなった）と、`../shapes/ShapeGeometry.js`の`applyAffineTransformToPoint`（**`import`文**。`core/`から`shapes/`を`import`文でimportするのは`core/ShapeFactory`に続く2ファイル目。1章の依存方向の例外）のみ。`AffineTransform`はJSDocの`import()`型参照でも参照する。`ScaleHandleRules`・`ReferencePointRules`・`ShapeGeometry`は`RotationRules`をimportしないため循環しない（`RotationRules → ReferencePointRules → ScaleHandleRules`）。
    *   **知らないこと**：DOM・図形・図形種別・`VectorModel`・操作モード・修飾キーの読み取り（`Shift`は`snapToStep`の真偽値として受けるだけ。`Alt`・`Ctrl`は使わない）・座標のスナップ（`UnitSnapRules`・`UnitSnapSettings`）・外枠の求め方・履歴。
    *   **使う側**：`core/InputTracker`（`hitTestRotationZone`・`computeRotationCenter`・`computeRotationAngle`・`toRotationTransform`。`#findRotationZone`・`#beginRotateSelection`・`#applyRotateUpdate`）、`core/CursorShapeRules`（`resolveRotationCursor`。カーソルの絵と向きの表を1か所にするため）、`main.js`（`resolveDisplayedScaleFrame`。`renderCurrentState`）、**`edit/TransformInputRules`**（`toRotationTransform`。角度の数値入力の変換。符号を変えて渡す。Phase 10-03。3章27.）。`PressActionRules`は角の名前の意味を知らず、第4引数の文字列かだけを見る。
    *   **置き場所の理由**：判定・計算を`node --test`で確かめるため（`InputTracker.js`は`DragTracker`・DOMに依存し、`CanvasManager`は位置を引数で受け取るだけ、`main.js`は判定・計算を持たない）。`ScaleHandleRules`へ足さず新しいファイルにした理由：`ScaleHandleRules`の責務定義は拡大縮小の規則で、回転の角度・カーソルの絵・回した外枠は別の責務のため。外枠の角の位置・中心の式は`ScaleHandleRules`に1か所だけ持ち（`collectFrameCorners`・`computeFrameCenter`）、ここへ写さない。`InputTracker`の再分離（状態の所有者設計）ではない。
    *   **注意**：回転のカーソルの絵・ホットスポット・向きを変えるときは、この表だけを変える（`CursorShapeRules`は表を持たない）。回転にスナップを当てない（発注者の決定）。`Shift`の刻みを変えるときは`ROTATION_SNAP_STEP`だけを変える。水平・垂直な直線の外枠では同じ位置の角が2つずつ重なり、`collectFrameCorners`の並びの先の角名が当たる（上端・左端は`nw`、下端・右端は`se`。高さ0の外枠では左端`nw`・右端`ne`）。
