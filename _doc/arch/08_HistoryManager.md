*   **HistoryManager.js** : 編集操作の履歴（スナップショットの前後の組の列・取り消し/やり直しの位置・上限）の保持と、記録・取り消し・やり直し・リセット・可否の照会を担う。importは持たず、DOM・図形種別・図形固有のプロパティ名・作業データの中身を知らない。スナップショットの取得・適用の実体は、コンストラクタで注入される関数`{ capture: () => Snapshot, restore: (snapshot) => boolean }`（関数でなければ`Error`。実体は`edit/SnapshotAdapter`の`capture`/`restore`）へ委譲する（`core/`から`io/`をimportしないため）。
    *   **データ構造** : typedef`Snapshot`＝`{ document: 作業データ形式のオブジェクト, selectedIds: string[] }`（`document`は比較のための文字列化以外で解釈しない）。エントリ`HistoryEntry`＝`{ before, after }`の配列`#entries`と、適用済みエントリ数`#cursor`で保持する（前後両方を持つため、エントリ間で状態が一致しない場合も取り消し・やり直しがそれぞれ正しい状態へ戻る）。上限は定数`HISTORY_LIMIT`（100。唯一の定義箇所としてexport）。履歴はメモリ上のみで保存しない。`capture()`の戻り値は汎用の再帰`Object.freeze`（private static`#deepFreeze`。プロパティ名を参照せず、凍結済みの値は辿らない）で凍結して保持する。
    *   **公開API** : `beginEdit()`（前の状態を取得して`#pendingBefore`に保持。保持中なら`console.warn`して上書き）、`commitEdit(): boolean`（後の状態を取得し、前後の`document`部分の`JSON.stringify`が一致すれば記録せず`false`（やり直しの履歴も破棄しない）、異なれば`#cursor`以降を切り詰めて1件追加し、上限超過分を最古から捨てて`true`。`#pendingBefore`がなければ`console.warn`して`false`）、`undo()`/`redo(): boolean`（冒頭で`#pendingBefore`が残っていれば`console.warn`して破棄。可否が偽なら`false`。`restore`が`false`なら位置を動かさず通知せず`false`）、`canUndo()`/`canRedo()`、`clear()`（履歴を空にする。図形一式・選択集合には触れない。`CanvasLibrary`の切り替え処理（3章8.の手順5）から呼ばれる）、`onChange(listener)`。
    *   **変更通知** : 記録時・適用成功時・`clear()`で実際に何かを破棄したときのみ通知する（`beginEdit()`・不記録の`commitEdit()`では通知しない）。`model.onChange`ごとの記録は行わず、`beginEdit`/`commitEdit`の明示呼び出しでのみ記録する（呼び出し元は`InputTracker`（作成・削除・切り取り・ドラッグ）、`main.js`（`?dev`の復元）、`ShapeInserter`（貼り付け・複製）。`InputTracker`・`ShapeInserter`へは`EditRecorder`として注入され、両者は`HistoryManager.js`をimportしない）。進行中の入力操作の中断は呼び出し側の責務。
    *   **注意** : 記録ごとに`serialize`と`JSON.stringify`による比較が走り、最大100件×2のスナップショットを保持する（図形数が極端に多い場合は遅延・メモリを確認すること）。
