*   **edit/** : `io/`・`core/`の機能を組み合わせて図形一式を扱う手順。図形一式を編集する手順（貼り付け・複製。流れは3章7.）、履歴のスナップショットの取得・適用（`SnapshotAdapter`）、キャンバス一覧の管理（`CanvasLibrary`。流れは3章8.）、ファイル操作（書き出し・開く（ファイル）・インポート）の組み立て（`CanvasFileOperations`。流れは3章9.）を含む。いずれもDOMに触れず、図形種別の分岐・図形固有のプロパティ名・図形のid形式の知識を持たない。`InputTracker`に依存せず操作モードを知らないため、前提（選択モードであること・ドラッグ中でないこと・作成途中の図形がないこと）は呼び出し側（`main.js`。インポートでは`CanvasFileOperations`が`insertDocument`の前に`prepareInsert()`を呼んで満たす）の責務であり（選択モード以外で呼ぶと「選択集合は選択モード以外では空」の不変条件が崩れる）、操作モードに依存する判定・処理が必要な場合は`shouldRestoreSelection`・`prepareSwitch`・`prepareInsert`のような操作モードに中立な名前の注入関数で受け取る（実体は`main.js`が与える）。importは`DocumentSerializer`のみで、他の依存（`VectorModel`・`HistoryManager`・`CanvasStorage`等）は注入で受け取る。
    *   **ShapeInserter.js** : 作業データ形式のオブジェクトの図形を、平行移動したうえで新しいidで現在のキャンバスの最前面へ追加し、追加した図形だけを選択する1件の編集操作（貼り付け・複製とインポートの共通処理。インポートは`CanvasFileOperations`が`serialize`した作業データを渡して呼ぶ）。`constructor({ model, editRecorder })`（`editRecorder`は`EditRecorder`。実体は`historyManager`）。公開API`insertDocument(documentData, dx = 0, dy = 0): InsertResult`（`{ ok, insertedIds, skipped, error }`。`ok`・`skipped`・`error`は`DeserializeResult`の値、`insertedIds`は追加した図形の新しいid（描画順））。処理順は3章7.のとおりで、毎回`deserialize`で新しい図形インスタンスを生成し、`documentData`を書き換えない。履歴へは1件以上追加した場合のみ1件記録する。importは`DocumentSerializer`のみ（`VectorModel`・`HistoryManager`は注入）。`EditRecorder` typedefは`InputTracker.js`と同じ内容を本ファイルにも定義しているため、形を変える場合は両方を揃えること。
    *   **ClipboardController.js** : アプリ内部のクリップボード（作業データ形式のオブジェクト`#documentData`と貼り付けの段数`#nextPasteStep`）の保持と、コピー・切り取り・貼り付け・複製の手順。`constructor({ model, inserter, deleteSelection })`（`deleteSelection`が関数でなければ`Error`。`model`・`inserter`は検証しない）。公開API`copy()`/`cut()`/`paste()`/`duplicate()`（いずれも何かを行った場合に`true`）と`isEmpty()`。モデルへの依存は読み取り（`getShapes()`・`isSelected(id)`）のみで、図形の追加は`ShapeInserter`、削除は注入された`deleteSelection`（実体`inputTracker.deleteSelection()`）へ委譲する。`cut()`は削除の前に`serialize`する（削除後は選択集合が空になるため。順序を入れ替えないこと）。定数`PASTE_OFFSET_STEP`（20。exportしない）が貼り付け・複製のずらし量の唯一の定義箇所。importは`DocumentSerializer`のみ。
    *   **SnapshotAdapter.js** : 履歴のスナップショット（作業データ＋選択集合）の取得と、キャンバスへの適用（`HistoryManager`へ注入する`capture`/`restore`の実体）。`constructor({ model, shouldRestoreSelection })`（`shouldRestoreSelection`が関数でなければ`Error`）。`capture()`は`{ document: serialize(model.getShapes()), selectedIds }`を返し、`restore(snapshot)`は3章6.の適用（`deserialize`が全体失敗・スキップ1件以上なら`console.warn`してキャンバスを変更せず`false`。成功時は`replaceAllShapes`し、`shouldRestoreSelection()`が真のときのみ選択集合を復元して`true`）。`shouldRestoreSelection()`は「選択集合を復元してよいか」を返すだけの関数で、本クラスはその判定の根拠（操作モード）を知らず、`OperationMode`・`InputTracker`をimport・参照しない。進行中の入力操作の中断は呼び出し側の責務。typedef`Snapshot`は`HistoryManager.js`と本ファイルの二重定義のため、形を変える場合は両方を揃えること。
    *   **CanvasLibrary.js** : キャンバス一覧の管理（起動時の復元・開く・新規作成・開く（ファイル）の受け口・名前の変更・削除・切り替え処理・開いているキャンバスの自動保存・保存失敗の状態）。`main.js`が1つだけ生成する。流れと規則は3章8.のとおりで、詳細の正本はクラスJSDocにある（仕様を変える場合はクラスJSDocと該当メソッドのJSDocを併せて更新すること）。
        *   **生成と依存** : `constructor({ storage, model, historyManager, prepareSwitch, resetView })`（`prepareSwitch`・`resetView`が関数でなければ`Error`）。`historyManager.onChange`へ自動保存の予約を登録する。`model`は`getShapes()`・`replaceAllShapes()`、`historyManager`は`onChange()`・`clear()`のみ使う。`prepareSwitch()`は進行中の入力操作の中断と選択モードへの切り替え（実体`applyMode(OperationMode.SELECT)`）、`resetView()`はビュー変換の初期化（実体`viewTransform.reset()`）。importは`DocumentSerializer`のみで、`CanvasStorage`も注入で受け取りimportしない。`setTimeout`/`clearTimeout`/`Date.now`/`Math.random`以外のブラウザAPI（`document`・`window`のイベント等）を使わない。
        *   **公開API** : `start()`（起動時の復元。2回目以降は何もしない）、`openCanvas(id)`、`createCanvas()`、`createCanvasFromShapes(rawName, shapes)`（開く（ファイル）用。任意の名前と読み取り済みの図形で新しいキャンバスを作って開く。切り替え処理の手順1〜6を通り、名前は名前の変更と同じ規則で正規化して空なら「無題 n」、`issue`は`'partialLoad'`にしない。`createCanvas()`は`createCanvasFromShapes(null, [])`への委譲）、`renameCanvas(id, rawName)`、`deleteCanvas(id)`（いずれも`Promise<boolean>`で、受理して処理したか。rejectしない）、`flushPendingSave(): Promise<boolean>`（3章8.のページ非表示時の確定）、`getState(): CanvasLibraryState`、`onChange(listener)`。
        *   **状態（`CanvasLibraryState`）** : `getState()`は毎回新しいオブジェクト`{ loading, busy, canManage（'unavailable'でない）, openCanvasId, openCanvasName, canvases: [{ id, name, updatedAt, isOpen }]（最終更新日時の新しい順。同値はid順）, issue, hasSaveProblem }`を返す。`loading`は`start()`の呼び出し前から完了まで真。キャンバス一覧はメモリ上に要約（`id`・`name`・`updatedAt`）のみを保持し、作業データは保持しない（起動時に一覧作成のため全記録を一度読み出す。キャンバス数・図形数が極端に多い場合は起動時間を確認すること）。
        *   **注意** : 自動保存の確定と切り替え処理の順序保証が同じprivate状態を同期区間内で読み書きする密結合のため、1クラスにまとめている（分割すると順序保証が崩れやすい）。自動保存の予約を止める仕組みは`#isSwitching`の1つのみで、真・偽にする箇所を増やさないこと（偽へ戻し損ねると自動保存が予約されなくなる）。書き込み中の保存は宛先のキャンバスを区別しないため、切り替え直後に再び切り替える場合、直前のキャンバスへの書き込みの失敗でも切り替えが中止される。
    *   **CanvasFileOperations.js** : ファイル操作（書き出し・開く（ファイル）・インポート）の組み立て（ファイル読み取り→判定→`CanvasLibrary`／`ShapeInserter`の呼び出し→通知の状態の更新）と、キャンバスパレットの表示同期用の状態・変更通知の提供。流れ・判定の表・通知・受理条件は3章9.のとおりで、詳細の正本はクラスJSDocにある。DOM・ブラウザAPIに触れず（`Blob`・`File`は注入された`DocumentFileIO`に任せる）、操作モードを知らず、図形種別の分岐・図形固有のプロパティ名・図形のid形式の知識を持たず、作業データは不透明に扱う。importは`DocumentSerializer`のみ。`main.js`が1つだけ生成する。
        *   **生成と依存** : `constructor({ fileIO, canvasLibrary, inserter, model, prepareInsert })`（`prepareInsert`が関数でなければ`Error`）。`fileIO`は`DocumentFileIO`、`inserter`は`ShapeInserter`、`model`は`getShapes()`のみ使う。`prepareInsert()`は進行中の入力操作の中断と選択モードへの切り替え（実体`applyMode(OperationMode.SELECT)`）。`canvasLibrary.onChange`へ登録し、開いているキャンバスの変化でファイル操作の通知を消して自身のリスナーへ転送する。
        *   **公開API** : `exportCanvas(): boolean`（同期）、`openFile(file): Promise<boolean>`、`importFile(file): Promise<boolean>`（rejectしない。表示同期のリスナーの例外を除く）、`getState()`（毎回新しいオブジェクト`{ ...canvasLibrary.getState(), busy: ライブラリのbusy || 処理中, fileNotice }`）、`onChange(listener)`。`openFile`・`importFile`の共通の流れはprivate`#runReadOperation`にまとめる。
        *   **注意** : 合成した`busy`は`getState()`のみで行い、`canvasLibrary.getState()`の値は変えない（`main.js`の`syncCanvasNameDisplay`・`syncLoadingCover`・`?dev`の判定に影響させないため）。インポートの同一性の確認は処理中の自身を除くため`canvasLibrary.getState()`の値で行い、`getState()`の合成後の`busy`で判定してはならない（常に真となり、すべて失敗になる）。判定の表（`#classifyRead`）は「ファイルの図形が1個以上か」を`shapes.length + skipped.length`で数え、作業データ自体の`shapes`を参照しない。
